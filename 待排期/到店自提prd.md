## 1. App 端：到店自提（FR-129）

#### 已确认项（2026-09-30 拍板）

- 新增**到店自提**作为快递之外的配送方式
- 骑手配送、多店多地址拆单不在本次范围
- **自提点为合作门店**（2026-10-02 拍板）：上线时为 1 家；门店的货由门店自行购入，**自提订单由门店用自有库存备货**，不从平台仓库调货
- **自提点须支持配置多个**，不得按单一门店写死
- **核销由门店店员操作**：店员持有运营后台账号，在后台核销提货
- **超时未提**：订单进入「待提货」满 **7 天**未核销即为超时；超时后**提醒用户、运营与该门店**，由门店联系用户；不自动取消、不自动退款
- **可自提的商品由门店维护**：门店在后台维护本店有货的商品，结算时只有门店有货的商品才可选自提
- **不拆单**：一单只能整单自提或整单快递；购物车中任一商品该门店无货，本单即不可选该门店自提
- **钱款与价格**：用户付款给 TailTopia，平台再与门店结算；自提订单售价与线上一致
- 运营后台须提供**门店维度的订单统计**，支撑平台与门店结算（后台规格另见后台 PRD）

#### 自提规则（2026-10-06 拍板）

- **自提点由运营后台配置**（名称、地址、营业时间、联系电话、启停）；全部自提点停用时，结算页不出现配送方式选择；启用的自提点多于 1 个时，用户在结算页选择门店
- 选择自提：**无运费**；不受配送范围限制；**免运券不可用**（没有运费可免）
- 下单时需填提货联系人姓名与手机号（默认取账号信息，可改）
- **提货凭证**：订单号 + 6 位提货码，显示在订单详情页；到店出示，店员在后台输入提货码核销
- **订单状态**：待支付 → 待备货 → 待提货 → 已完成；「待提货」时推送通知用户可到店
- 结算页选择自提而本单有商品该门店无货时，配送方式中该门店置为不可选并注明「门店暂无：{商品名}」

## 2. 后台：自提门店管理、门店商品与自提订单处理（AB-26）

**背景：** App 端 FR-129 新增到店自提。自提点为合作门店，门店用自有库存备货；平台收款后与门店结算。

**与 App 端的依赖：** AB-26 与 FR-129 强耦合，须同批发版。

#### 已确认项（2026-10-02 拍板）

- 自提点为合作门店，**须支持配置多个**
- **门店维护本店有货的商品**，App 端只有门店有货的商品才可选自提
- **核销由门店店员在后台操作**
- **权限**：运营后台已支持自定义角色，**不新建固定的「门店店员」角色**；本条目只需把门店相关操作拆成可单独勾选的权限项，由管理员自行组合角色
- **门店维度的订单统计**：支撑平台与门店结算
- 待提货满 7 天未核销：**通知运营与该门店**，由门店联系用户

#### 功能与流程（2026-10-06 拍板）

- **门店管理**：位置在 🛍 商城 →「服务范围与运费」页，新增「自提门店」分组卡。字段：门店名称、地址、营业时间、联系电话、启停。全部停用时 App 端结算页不出现配送方式选择
- **门店商品**：位置在「自提门店」分组卡每家门店的行内操作「门店商品」→ 右侧抽屉，按 SKU 勾选本店有货 / 无货，支持搜索与批量勾选
- **自提订单处理**：位置在 🛍 商城 →「订单履约」页。筛选项新增配送方式（快递 / 自提）与门店；自提订单的行内操作：
  - 「备货完成」：订单进入待提货并推送用户
  - 「核销提货」：输入 6 位提货码，校验通过后订单完成；校验失败给出明确提示，不透露正确码
- **新增权限项**（可单独勾选）：门店管理、门店商品维护、自提订单处理（备货完成 / 核销）、门店订单统计查看
- **⚠️ 账号须关联门店**：只靠权限项无法限定「店员只能看到本门店的订单」——权限管的是能做什么，管不了能看哪家门店的数据。账号增加「所属门店」字段，关联了门店的账号在门店商品、自提订单、门店统计中**只能看到本门店的数据**；不关联门店的账号（运营）看全部。2026-11-03 核：现有后台支持自定义角色与权限矩阵勾选，**不支持按数据范围限定**，账号上没有所属门店之类的字段，须新做。另注意：1.4.1 商家平台的「门店」（`merchant_stores`，邀请码绑定、进货单）由独立仓库 `tailtopia-merchant` 管理，TailTopia 后台无门店管理页；自提门店是否复用这套门店数据，重新排期时须定
- **门店订单统计**：位置在 🛍 商城 →「对账」页新增按门店筛选与门店汇总（订单数、销售额），可按时间段导出明细
- **超时通知**：订单履约页对超时自提订单加「超时未提」标记；该门店账号登录后台时在待办中心看到角标

## 3. 自提对电商其他条款的影响（拆出时从电商 PRD 移来）

并入时，把以下条款加回对应的电商需求：

| 电商条款 | 自提相关内容 |
|---|---|
| FR-127 配送范围前置 | 选择到店自提的订单不受配送范围限制；所选地区不在开通范围时，除明示「该地区暂不支持快递配送」外，在开通了自提点时提示「可选择到店自提」 |
| FR-127 免运进度提示 | 结算页选择到店自提时不出现（自提无运费） |
| FR-128 结算页结构 | 结算页顶部加「配送方式」：快递 / 到店自提；未开通任何自提点时不显示此选择，直接为快递。「收货信息」随之区分：快递显示收货地址，自提显示自提点与提货联系人 |
| FR-130 优惠券 | 选择自提时免运券不可用（已写在 §1 自提规则） |
| FR-133 订单页 | 订单列表状态分组增加「待提货」 |
| §1 版本目标 | 「新增到店自提——作为快递之外的第二种履约方式」 |
| §4 埋点 | `toko_order_submitted` 增加 `delivery_type`（快递 / 自提）、`store_id`（自提时），用于自提占比 |

## 4. 重新排期前须先定的事项

- **与 1.4.1 商家平台「门店」的关系**：1.4.1 已上线商家平台（独立仓库 `tailtopia-merchant`，与 TailTopia 共用数据库），门店在那边注册、审核，有邀请码，用户可绑定门店，Toko 订单记归属门店并按差价返佣。自提门店是复用这套门店数据，还是在 TailTopia 后台另建一套；自提订单是否同时产生返佣，都须定
- **后台按门店限定数据范围**：2026-11-03 核线上 1.4.1，后台支持自定义角色与权限矩阵，**不支持按数据范围限定**，账号上没有所属门店字段，须新做（见 §2「账号须关联门店」）
- **订单履约页现状**：线上订单履约页的行内没有操作按钮，发货、缺货、送达都在抽屉里。§2 写的「行内操作」须按届时的页面形态调整
- **与电商重构的先后**：本文规则建立在 V1.4.2 新结算页（配送方式区、页内地址）之上；若 V1.4.2 电商重构也延后，须一起重排
