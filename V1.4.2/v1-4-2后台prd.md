## 1. AB-24：优惠券管理

**背景：** App 端 FR-130 引入优惠券（满减、免运），券的一切参数由运营在后台配置，App 端不写死任何一张券。现有后台无任何优惠券能力。

### 已确认项（2026-09-30 拍板）

**可配置的维度：**

| 维度 | 取值 |
|---|---|
| 券类型 | 满减 / 免运（本次只有这两种） |
| 面额与门槛 | 满减：减免金额 + 门槛金额；免运：可设门槛金额 |
| 有效期 | 固定起止日期，或领取后 N 天内有效 |
| 数量 | 发放总量、每人限领张数 |
| 适用范围 | 全场 / 指定品类 / 指定商品 |
| 发放方式 | 新人自动发放 / 用户领取 / 兑换码 |

- 没有系统默认券——三种发放方式都要运营建券后才存在
- 规则口径以 App 端 FR-130 为准：每单最多 1 张满减券 + 1 张免运券；满额免运与免运券并存，已满额免运的订单免运券不可用；满减券门槛按券前商品金额判断，满额免运与免运券门槛按商品实付金额（商品金额 − 满减券）判断

### 页面位置与流程（2026-10-06 拍板）

- **位置**：🛍 商城组新增侧栏项「优惠券」，独立列表页
- **列表**：券名称、类型、面额 / 门槛、发放方式、有效期、已发 / 总量、已使用数、状态（未开始 / 进行中 / 已结束 / 已停用）；可按状态、类型、发放方式筛选
- **新建 / 编辑**：列表页右上「新建优惠券」→ 右侧抽屉表单 → 提交后回到列表并定位到新行。**已开始发放的券只能改总量（只增不减）与停用**，面额、门槛、适用范围不可改，避免用户手里同一张券前后规则不一致
- **兑换码**：发放方式选兑换码时，由运营填写一个通用码或批量生成一次性码（批量码可导出）
- **停用**：行内操作，二次确认；停用后不能再领取或兑换，**用户已领取未使用的券是否继续可用**须在确认弹层中让运营二选一
- **数据**：券详情抽屉显示领取数、使用数、带来的订单金额

### 防误配提醒（2026-10-06 拍板）

面额 ≥ 门槛的满减券（等于白送商品）、总量不限且每人不限领的券，保存时给出醒目提示并要求二次确认。

### UI 说明

**需要出稿。** 新页面、新表单，现有后台无同类先例。后台文案按中 / EN / ID 三语准备。

## 2. AB-25：Toko banner 管理扩展

**现状：** 🛍 商城 → 「顶部 Banner」页已可上传、编辑、上下架、删除 banner，但**同一时间只生效一张**（生效中排序权重最高的那张），且**没有跳转链接字段**。

### 已确认项（2026-09-30 拍板）

- banner 由运营在后台配置，支撑 App 端 FR-132

### 扩展内容与流程（2026-10-06 拍板）

- **与现有能力的关系：完全取代「只生效一张」的规则**——所有上架中且在排期内的 banner 都展示，上限 6 张；上传、编辑、上下架、删除等现有操作保留
- **新增字段**：
  - 跳转类型：商品 / 品类 / 优惠券（领券）/ 外部链接 / 无跳转
  - 跳转目标：按类型选择商品、品类、优惠券，或填写外链 URL
  - 排期：上线时间、下线时间（可不填下线时间）
  - 排序：列表内拖动排序
- **跳转目标失效自动下线**：目标商品下架、目标券停用 / 已领完 / 已过期时，该 banner 在 App 端自动不再展示，后台列表标记「目标失效」
- **位置**：仍在「顶部 Banner」页，不新增菜单项

### UI 说明

**需要出稿。** 在现有页面上新增字段与排序交互。

## 3. AB-26：自提门店管理、门店商品与自提订单处理

**背景：** App 端 FR-129 新增到店自提。自提点为合作门店，门店用自有库存备货；平台收款后与门店结算。

### 已确认项（2026-10-02 拍板）

- 自提点为合作门店，**须支持配置多个**
- **门店维护本店有货的商品**，App 端只有门店有货的商品才可选自提
- **核销由门店店员在后台操作**
- **权限**：运营后台已支持自定义角色，**不新建固定的「门店店员」角色**；本条目只需把门店相关操作拆成可单独勾选的权限项，由管理员自行组合角色
- **门店维度的订单统计**：支撑平台与门店结算
- 待提货满 7 天未核销：**通知运营与该门店**，由门店联系用户

### 功能与流程（2026-10-06 拍板）

- **门店管理**：位置在 🛍 商城 →「服务范围与运费」页，新增「自提门店」分组卡。字段：门店名称、地址、营业时间、联系电话、启停。全部停用时 App 端结算页不出现配送方式选择
- **门店商品**：位置在「自提门店」分组卡每家门店的行内操作「门店商品」→ 右侧抽屉，按 SKU 勾选本店有货 / 无货，支持搜索与批量勾选
- **自提订单处理**：位置在 🛍 商城 →「订单履约」页。筛选项新增配送方式（快递 / 自提）与门店；自提订单的行内操作：
  - 「备货完成」：订单进入待提货并推送用户
  - 「核销提货」：输入 6 位提货码，校验通过后订单完成；校验失败给出明确提示，不透露正确码
- **新增权限项**（可单独勾选）：门店管理、门店商品维护、自提订单处理（备货完成 / 核销）、门店订单统计查看
- **⚠️ 账号须关联门店**：只靠权限项无法限定「店员只能看到本门店的订单」——权限管的是能做什么，管不了能看哪家门店的数据。账号增加「所属门店」字段，关联了门店的账号在门店商品、自提订单、门店统计中**只能看到本门店的数据**；不关联门店的账号（运营）看全部。现有后台是否已有按数据范围限定的能力，需研发核实
- **门店订单统计**：位置在 🛍 商城 →「对账」页新增按门店筛选与门店汇总（订单数、销售额），可按时间段导出明细
- **超时通知**：订单履约页对超时自提订单加「超时未提」标记；该门店账号登录后台时在待办中心看到角标

## 5. AB-28：异常订单取消退款

**背景：** App 端 FR-134 ③ 拍板：异常订单取消必须退还现金部分。现状「异常订单」页的整单取消只退 PawCoin 部分、现金部分只写审计不退款；部分取消完全不退款。

**位置：** 🛍 商城 → 「异常订单」页，现有「整单取消」「部分取消」两个处置动作。

### 已确认项（2026-09-30 拍板）

- 整单取消：PawCoin 与现金部分全额退回
- 部分取消：退回被取消行对应的金额
- 现金部分的去向沿用现有退货流程：退为 PawCoin 或财务线下打款（2026-10-02 拍板）
- **与现状的关系：完全取代现行「整单取消不退现金、部分取消不退款」的处置结果**，两个处置入口本身保留

### 流程（2026-10-06 拍板）

- 处置确认弹层列出本次退款金额明细：PawCoin 部分、现金部分
- 提交后 **PawCoin 部分立即退回**用户账户；**现金部分**待用户在 App 订单详情页选定退款去向后处理——选 PawCoin 即时到账，选线下打款则转财务打款（App 端 FR-134）
