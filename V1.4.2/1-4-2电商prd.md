## 1. 版本目标

1. **减少下单阻力**——现有下单流程在多个环节阻挡用户的下单意愿（见 §2），本次围绕「从想买到付完款」重做主链路
2. **给运营基础促销能力**——优惠券（拉新首单 + 日常促销）与可配置的首页 banner
3. **资金闭环**——堵住三处「用户付了钱却可能收不回」的漏洞，这是在引入优惠券之前必须先修好的底线
4. **新增到店自提**——作为快递之外的第二种履约方式

**核心指标：** 下单转化漏斗为主指标，其余三项辅助。

- 下单转化漏斗：商品详情 → 进入结算 → 提交订单 → 支付成功，各步转化率
- 首单转化率：新注册用户 30 天内完成首单的比例
- 优惠券核销率：领取（或发放）→ 使用
- 支付成功率：出码 → 到账

## 2. 问题现状（2026-09-30 按 petgo-platform main 分支代码核实）

### 2.1 下单链路的阻力点

以新用户从商品详情页到付完款为路径：

| # | 环节 | 现状 |
|---|---|---|
| A | 配送范围 | 用户**到结算页才知道**地址能不能送；不在开通区域则无法下单，之前的浏览、详情、购物车环节均无任何提示 |
| B | 地址 | 无地址时须跳出结算页填完整表单；超出范围时「换一个地址」跳到的是地址**管理**页，选完不回填到本单 |
| C | 提交后 | 提交订单后先跳「待支付订单详情」，须**再点一次支付**才出二维码 |
| D | 同机扫码 | 用同一台手机付 QRIS 需截图、再到电子钱包里从相册识别，二维码面板不支持存图 |
| E | 运费与免运 | 商品页、购物车看不到运费，也不知道差多少能免运 |
| F | 首单动机 | 无任何首单激励或促销手段 |
| G | 信任信息 | 详情页只显示评价均分与条数，不显示评价内容（数据已拉取但未展示） |
| H | 立即购买 | 实现为「先加入购物车再跳结算」，会改动购物车状态 |
| I | PawCoin | 有余额即自动抵扣到上限，用户不能选择本单不用 |

### 2.2 资金闭环的三处漏洞

| # | 漏洞 | 后果 |
|---|---|---|
| ① | 支付回调丢失后没有兜底——主动查单能力已写好（`PaymentReconciliationService`），但没有任何调用方 | 用户已付款，订单仍显示待支付，超时后被取消 |
| ② | 订单超时取消后才到账的款项，系统只记一条日志 | 钱停在网关，用户既没收到货也没拿回钱 |
| ③ | 异常订单（缺货）处置：整单取消只退 PawCoin 部分、不退现金部分；部分取消某一行完全不退款 | 用户损失现金部分 |

## 3. 功能与需求

### 3.1 配送范围与运费信息前置（FR-127）

**目标：** 让用户在浏览阶段就知道「能不能送到、运费多少」，不再到结算页才撞墙（§2.1 A、E）。

#### 已确认项（2026-09-30 / 10-02 拍板）

- 配送范围信息**前置到结算页之前**，用户在浏览与决策阶段即可得知能否送达
- 选择到店自提（FR-129）的订单不受配送范围限制
- **只在商品详情页**显示当前送达地区，Toko 首页不放：
  - 已登录且有默认地址 → 显示「送至 {Kecamatan}」+ 该地区运费
  - 未登录或无地址 → 显示「选择送达地区」，点击弹出地区选择（省 / 市 / 区三级，数据取开通区域树），选择结果仅本地记住、不生成收货地址
  - 所选地区不在开通范围 → 明示「该地区暂不支持快递配送」，并在开通了自提点时提示「可选择到店自提」
- 运费展示取服务端试算，与结算页口径一致

#### 免运进度提示（2026-10-02 拍板）

- 运营设置了满额免运门槛时（门槛 > 0），在**商品详情页、购物车、结算页**显示「再买 RpX 免运费」/「已免运费」
- 门槛为 0（不做免运）时整条提示不出现
- 结算页选择到店自提时不出现（自提无运费）
- 计算基数同 §3.4 的满额免运口径：**商品实付金额**（商品金额减去满减券后的金额）

### 3.2 结算页一页完成（FR-128）

**目标：** 从进入结算到看到付款二维码，全程不离开结算页（§2.1 B、C、D、H）。

#### 已确认项（2026-09-30 拍板）

- **地址在结算页内新增与选择**，不跳出结算页；新增的地址保存进地址簿
- **提交订单后直接拉起支付**，不再中转到「待支付订单详情」页再点一次支付
- **QRIS 二维码支持保存到相册**
- **二维码有效期与订单付款时限一致**：生成二维码时须把订单剩余付款时间传给支付网关，订单到期时二维码同时失效，用户在订单取消后无法再用存下的二维码付款。这是二维码存图功能的前置条件——现状向网关申请二维码时不传截止时间，二维码在网关侧能付多久由网关默认设置决定，可能长于订单时限。**研发须先确认 GemPay 支持设置二维码有效期**
- 支付方式维持 **QRIS + PawCoin**，不新增 e-wallet 直连、COD、虚拟账户

#### 结算页结构（2026-10-02 拍板）

自上而下：

1. **配送方式**：快递 / 到店自提（FR-129）；未开通任何自提点时不显示此选择，直接为快递
2. **收货信息**：快递显示收货地址（点击展开本页内的地址选择 / 新增）；自提显示自提点与提货联系人
3. **商品清单**
4. **优惠券**：满减券一行、免运券一行（FR-130）
5. **金额明细**：商品金额 → 满减券 → 运费 → 满额免运或免运券 → **应付金额**。此段只含优惠，**不出现 PawCoin**
6. **支付方式**（FR-131）：PawCoin 余额与 QRIS 在此并列呈现——PawCoin 是现金等价物，与现金同一心理预期，**不得放在优惠券旁或以扣减行的形式出现在金额明细中**
7. **吸底栏**：应付金额 + 提交订单；同时使用两种支付方式时，金额下方加一行小字「PawCoin Rp a + QRIS Rp b」

#### 立即购买直达结算（2026-10-02 拍板）

商品详情页「立即购买」直接以所选 SKU 与数量进入结算，**不写入购物车、不改动购物车的勾选状态**。需后端新增单 SKU 直接结算的入口（现状无此端点，见 §2.1 H）。

#### 支付面板（2026-10-02 拍板）

- 二维码下方提供「保存二维码」，保存后提示用户打开**电子钱包或手机银行**，从相册扫码
- 面板显示付款倒计时与**本次需扫码支付的金额**（使用了 PawCoin 时只显示 QRIS 部分，不显示应付总额）
- 提供「我已付款」按钮，点击后主动查询一次支付结果（与 FR-134 ① 的主动查单能力共用）

### 3.3 到店自提（FR-129）

#### 已确认项（2026-09-30 拍板）

- 新增**到店自提**作为快递之外的配送方式
- 骑手配送、多店多地址拆单不在本次范围
- **自提点为合作门店**（2026-10-02 拍板）：上线时为 1 家；门店的货由门店自行购入，**自提订单由门店用自有库存备货**，不从平台仓库调货
- **自提点须支持配置多个**，不得按单一门店写死
- **核销由门店店员操作**：店员持有运营后台账号，在后台核销提货
- **超时未提**：订单进入「待提货」满 **7 天**未核销即为超时；超时后**提醒用户、运营与该门店**，由门店联系用户；不自动取消、不自动退款
- **可自提的商品由门店维护**：门店在后台维护本店有货的商品，结算时只有门店有货的商品才可选自提
- **不拆单**：一单只能整单自提或整单快递；购物车中任一商品该门店无货，本单即不可选该门店自提
- **钱款与价格**：用户付款给 TailTopia，平台再与门店结算；自提订单售价与线上一致
- 运营后台须提供**门店维度的订单统计**，支撑平台与门店结算（后台规格另见后台 PRD）

#### 自提规则（2026-10-06 拍板）

- **自提点由运营后台配置**（名称、地址、营业时间、联系电话、启停）；全部自提点停用时，结算页不出现配送方式选择；启用的自提点多于 1 个时，用户在结算页选择门店
- 选择自提：**无运费**；不受配送范围限制；**免运券不可用**（没有运费可免）
- 下单时需填提货联系人姓名与手机号（默认取账号信息，可改）
- **提货凭证**：订单号 + 6 位提货码，显示在订单详情页；到店出示，店员在后台输入提货码核销
- **订单状态**：待支付 → 待备货 → 待提货 → 已完成；「待提货」时推送通知用户可到店
- 结算页选择自提而本单有商品该门店无货时，配送方式中该门店置为不可选并注明「门店暂无：{商品名}」

### 3.4 优惠券（FR-130）

**目标：** 拉新首单 + 给运营日常促销的手段。券的具体面额、门槛、发放均由运营在后台配置，App 端不写死任何一张券。

#### 已确认项（2026-09-30 拍板）

**券类型：** 本次只有两种

| 类型 | 作用 |
|---|---|
| 满减券 | 商品金额满门槛后减固定金额 |
| 免运券 | 减免本单运费 |

**获取方式：** 三种，均需运营在后台配置后才存在——**没有系统默认自动发放的券**

- 新人券：运营配置后，符合条件的新用户自动获得
- 领取：用户在 App 内主动领取
- 兑换码：用户输入运营发出的兑换码获得

**叠加：** 每单最多使用 **1 张满减券 + 1 张免运券**。

**满额免运与免运券并存（2026-09-30 拍板）：**

- 现有的全站满额免运（运营设置门槛，商品金额达到门槛即整单免运）**继续保留**，与免运券并存
- 本单已满足满额免运时，**免运券不可用**，也不扣券
- 未满足满额免运的订单才可使用免运券

**计算顺序（2026-09-30 拍板）：**

```
商品金额
− 满减券
+ 运费
− 满额免运 或 免运券（二者只会生效其一）
= 应付金额
  → 应付金额由 PawCoin 与 QRIS 分担（PawCoin 是支付手段，不是折扣，见 FR-131）
```

- **运费相关的优惠一律按商品实付金额判断是否减免**（2026-10-06 拍板，取代 09-30「按券前商品金额」的口径）：满额免运门槛、免运券门槛都以**商品实付金额 = 商品金额 − 满减券**为准；用了满减券后实付金额低于门槛，则不满足免运。PawCoin 是支付手段，不影响实付金额
- 满减券的门槛按券前商品金额判断

#### 券的使用规则细节（2026-10-06 拍板）

- 券的适用范围为「指定品类 / 指定商品」时，门槛只计算适用范围内的商品金额
- 券抵扣额不超过其作用对象：满减券不超过适用商品金额，免运券不超过本单运费
- **结算页默认自动选中最优组合**（抵扣额最大的满减券 + 可用的免运券），用户可手动更换或不使用
- 不可用的券单独成组，标明原因：未达门槛 / 不在适用范围 / 已过期 / 本单已免运
- **退券**：订单在支付前取消或超时取消、平台原因取消（如缺货整单取消）时，券退回账户（仍在有效期内才可再用）；部分取消时券不退回，退款金额按 FR-134 ③ 的分摊口径计算

#### 券的入口（2026-10-06 拍板）

- **我的券**：入口放在「订单 → 电商订单」页面；按可用 / 已使用 / 已过期列出；页内有兑换码输入框
- **领券**：商品详情页显示该商品可领的券，点击领取；Toko 首页 banner 可跳转到领券（FR-132）
- **新人券到账**：新用户获得新人券时，在首次进入 Toko 时提示一次

### 3.5 PawCoin 支付自选与单笔上限提醒（FR-131）

**定性（2026-09-30 拍板）：** **PawCoin 是真钱**（储值余额），在订单中是**支付手段**，不是折扣或优惠币。这决定了它在计算顺序中位于所有优惠之后（见 FR-130）。

#### 已确认项（2026-09-30 拍板）

- **用户自己决定本单用不用 PawCoin**——完全取代现行「有余额即自动抵扣到上限、用户不可选」的机制（FR-100 的自动抵扣逻辑随本条废止）
- **单笔上限 100 万 PawCoin 保留**
- 余额超过单笔上限时：本单最多使用 100 万，**超出部分由 QRIS 支付**；并提醒用户「单笔使用超过 100 万 PawCoin 会触发套现判定」
- PawCoin 足额覆盖应付金额时，本单无需 QRIS、提交即完成支付（沿用现有纯 PawCoin 支付能力）
- **PawCoin 在界面上作为支付方式呈现，不作为折扣呈现（2026-10-02 拍板）**：
  - 结算页「支付方式」区：「PawCoin 余额（当前余额 Rp xx）」可勾选；勾选后显示「PawCoin 支付 Rp a，剩余 Rp b 用 QRIS 支付」，不勾选则全额 QRIS
  - 余额足以覆盖应付金额且不超过单笔上限时，整单 PawCoin 支付，不出二维码
  - 单笔上限的套现判定提醒显示在此区
  - 订单详情页同理：金额明细止于应付金额，其下单列「支付方式」区，分列 PawCoin 支付额与 QRIS 支付额

#### 默认勾选状态（2026-10-06 拍板）

### 3.8 资金闭环（FR-134）

#### 已确认项（2026-09-30 拍板）

以下三项为本次必做（问题见 §2.2）：

- **① 支付回调丢失的兜底**：对「已出码、未收到回调」的订单，系统须主动向网关查询支付结果，查到已付款即按正常到账处理
- **② 超时取消后才到账的款项**：二维码有效期与订单时限对齐后（FR-128），只剩「临近到期付款、到账通知晚于订单取消」这一种极少数情况，**由用户联系客服处理**，不做自动恢复订单或自动退款
- **③ 异常订单取消必须退还现金部分**：整单取消时 PawCoin 与现金部分全额退回；部分取消某一行时，退回该行对应的金额
- **现金部分的退款去向（2026-10-02 拍板）**：沿用现有退货流程的两种去向——**退为 PawCoin**（即时到账）或**财务线下打款**到用户银行账户；PawCoin 部分只退回 PawCoin

#### 实现口径（2026-10-06 拍板）

- **① 查单时机**：用户在支付面板点「我已付款」时立即查一次；此外对待支付订单在付款窗口内定时轮询，付款窗口到期前做最后一次查询，查询失败不关单
- **③ 部分取消的退款分摊**：该行用过满减券时，按该行商品金额占适用商品金额的比例分摊券抵扣，退「该行实付」部分
- **② 让客服看得到这笔款**：现状仅记一条服务端日志，客服无从查起。「订单已取消但款项到账」时在后台订单详情标记「取消后到账」并显示到账金额，客服据此按 ③ 的退款去向处理
- **去向由用户选择**：订单详情页出现「选择退款方式」入口（复用现有退款方式页），选择线下打款时填写收款银行账户；用户选定前款项不退出

**整个复购功能下线**，**完全废止 FR-108 复购触发与 FR-109 粮量预估**，不保留任何触发路径。下线范围：
