## 1. 版本目标

1. **减少下单阻力**——现有下单流程在多个环节阻挡用户的下单意愿（见 §2），本次围绕「从想买到付完款」重做主链路
2. **给运营基础促销能力**——优惠券（拉新首单 + 日常促销）与可配置的首页 banner
3. **资金闭环**——堵住三处「用户付了钱却可能收不回」的漏洞，这是在引入优惠券之前必须先修好的底线

**核心指标：** 下单转化漏斗为主指标，其余三项辅助。

- 下单转化漏斗：商品详情 → 进入结算 → 提交订单 → 支付成功，各步转化率
- 首单转化率：新注册用户 30 天内完成首单的比例
- 优惠券核销率：领取（或发放）→ 使用
- 支付成功率：出码 → 到账

### 2.2 资金闭环的三处漏洞

| # | 漏洞 | 后果 |
|---|---|---|
| ① | 支付回调丢失后没有兜底——主动查单能力已写好（`PaymentReconciliationService`），但没有任何调用方（无定时任务、无接口调用；App 支付面板的轮询只读本地状态，不向网关查） | 用户已付款，订单仍显示待支付，超时后被取消 |
| ② | 订单超时取消后才到账的款项：取消时支付记录已置为失败，之后到达的付款回调被**直接丢弃**，多数情况连日志都没有（2026-11-03 复核，比 09-30 所记「只记一条日志」更严重）；后台看到的仍是支付失败 | 钱停在网关，用户既没收到货也没拿回钱，客服和财务都查不到 |
| ③ | 异常订单（缺货）处置：整单取消只退 PawCoin 部分、不退现金部分（现金部分只写进审计记录）；部分取消某一行完全不退款 | 用户损失现金部分 |

> 2026-11-03 补充：
>
> - 订单付款时限为 **60 分钟**，写死在代码中，不可配置；向 GemPay 申请二维码时仍不传有效期（FR-128）。
> - 1.4.0 的「退款扣回 Tailrent 成长值」只接在 PawCoin 退款上；③ 的现金部分、问诊挂起的 QRIS 退款都没有扣回。Roadmap 已把这两条路径的扣回列为 1.4.2 修复项。③ 的现金部分已拍板：退为 PawCoin 时自动扣回，线下打款时由客服在后台**人工扣回**（FR-134、AB-28，2026-11-04）；问诊挂起见 `1-4-2退款扣回成长值修复prd.md`。
> - 送礼线（1.4.0）已有「关单后到账自动退为 PawCoin」的处理，电商线没有。② 已拍板由客服处理（FR-134），不照搬送礼线的自动退款。

### 2.3 1.4.1 商家平台带来的新约束（2026-11-03 补）

- Toko 订单在下单时记录用户绑定的**归属门店**，门店返佣按每行「下单单价 − SKU 批发价」的差价计算，计算在商家平台仓库（`tailtopia-merchant`）完成，本仓库只提供数据
- **用券后返佣基数不变（2026-11-04 拍板）**：门店返佣仍按每行「下单单价 − SKU 批发价」计算，券的抵扣不分摊进单价、不降低返佣，券的成本由平台全额承担（FR-130）。部分取消、退货时返佣按被取消行的原口径扣回，与 FR-134 ③ 的券分摊（只影响退给用户的金额）互不影响

## 3. 功能与需求

### 3.0 用户旅程与页面跳转（2026-11-04 新增）

本节把 FR-127 ~ FR-172 串成用户实际走的路径，作为研发与设计的总览；各步骤的规则以对应 FR 为准。各步骤均为已拍板规则或线上现状（2026-11-04 核 1.4.1 代码）。

#### 页面清单

| 页面 | 从哪进 | 能去哪 |
|---|---|---|
| Toko 首页 | 底部导航 | 商品详情、品类列表、搜索页、banner 目标、购物车 |
| 搜索页 | 首页吸顶行放大镜 | 商品详情 |
| 商品详情 | 首页 / 品类 / 搜索 / banner / 订单详情商品行 | 规格弹层、购物车、结算页（立即购买）、送达地区选择 |
| 购物车 | 首页与详情页的购物车图标 | 商品详情、结算页 |
| 结算页 | 购物车「去结算」/ 详情「立即购买」 | 地址选择与新增（页内）、支付面板 |
| 支付面板 | 结算页提交 / 订单「去支付」 | 支付成功 → 订单详情 |
| 订单列表 | 「订单 → 电商订单」 | 订单详情、我的券 |
| 订单详情 | 订单列表 / 支付成功 | 支付面板（待付款）、商品详情、选择退款方式 |
| 我的券 | 订单列表页顶部入口 | — |
| 地址簿 | 「我的」→ 地址管理 | 新增 / 编辑地址 |

#### 旅程 A：加入购物车后下单

1. 从首页 / 品类 / 搜索 / banner 进入**商品详情**，看到价格、可领的券、送达地区、「运费 Rp X 起」、免运进度（FR-127、FR-133）
2. 点「加入购物车」→ 弹出规格弹层，选 SKU 与数量 → 确认后提示「已加入购物车」，**留在详情页**，购物车图标角标更新
   - 未登录：先登录，登录后回到详情页
   - SKU 缺包裹重量或体积：不可加入，按钮显示「暂不可售」（FR-172）
3. 进入**购物车**：勾选商品、改数量；底部显示免运进度与预估应付（规则见 FR-133 购物车）
4. 点「去结算」→ 带着已勾选的商品进入**结算页**（旅程 C）
5. 提交订单后，已下单的商品从购物车移除；没勾选的留在购物车

#### 旅程 B：立即购买

1. 商品详情点「立即购买」→ 规格弹层选 SKU 与数量 → 确认后**直接进入结算页**
2. 不写入购物车，也不改动购物车的勾选（FR-128）
3. 从结算页返回，回到商品详情，什么都不保存

#### 旅程 C：结算与付款

1. **进入结算页时的默认值：**
   - 收货地址：**每次都默认选中地址簿里的默认地址**；在结算页换了别的地址只对这一单有效，下次进来仍回到默认地址（2026-11-04 拍板，同线上）。没有任何地址时，地址区显示「新增收货地址」，快递区不询价，提交按钮不可用
   - 快递：按所选地址向 Biteship 询价，列表按运费从低到高，默认选中最便宜的一家（FR-172）
   - 优惠券：默认选中最优组合（FR-130）
   - PawCoin：有可用余额时默认勾选（FR-131）
2. **在结算页内可以改的：**
   - 换地址或新增地址（页内完成，新增的地址存入地址簿）→ 重新询价 → 快递、免运、免运券重算。换地址后若原快递仍可选则保留，否则改为最便宜的一家
   - 换快递、勾选或取消保价 → 金额明细重算
   - 换券或不用券；勾选或取消 PawCoin
3. **不能提交的情况：** 地址不在开通区域或没有快递可达（提示「该地区暂不支持快递配送」）；询价失败（提示暂时无法获取运费并提供重试）（FR-127、FR-172）
4. **提交订单：** 锁定快递、运费与保价（FR-172），然后：
   - PawCoin 足额支付 → 直接支付成功，不出二维码
   - 否则拉起**支付面板**：二维码、付款倒计时（60 分钟）、本次需扫码支付的金额、保存二维码、「我已付款」（FR-128）
5. **关掉支付面板没付：** 订单进入「待付款」，倒计时继续；用户可在订单列表或订单详情点「去支付」重新拉起同一个支付面板
6. **超时未付：** 订单自动取消，券退回（FR-130）。已扣的 PawCoin 一并退回，研发核对线上现有处理
7. **支付成功：** 显示支付成功页（应付金额、「查看订单」「继续逛」），点「查看订单」进入订单详情，订单状态为「待发货」

#### 旅程 D：发货、收货与完成

1. 运营在后台向 Biteship 下运单（AB-38），订单进入「待收货」
2. 订单详情显示快递名称、运单号与物流状态：待揽收 → 已揽收 → 运输中 → 派送中 → 已签收（FR-172）
3. Biteship 回传签收 → 订单自动标为已送达；回传缺失时运营可在后台手工标记（FR-172）
4. 用户在「待收货」时可以随时点「确认收货」，不必等签收（线上现状）
5. 送达后 7 天自动完成（线上现状）；退货规则不在本次范围
6. 线上「发货起 7 天自动标记送达」的兜底改为 14 天：接入 Biteship 后送达以回传为准，印尼偏远地区 7 天可能还没送到

#### 旅程 E：领券到用券

1. 获取：新人券在首次进入 Toko 时提示一次；商品详情点「领取」；Toko 首页 banner 跳转领券；在「我的券」页输入兑换码（FR-130）
2. banner 的「领券」跳转：运营给 banner 绑定一张券，用户点击即领取并提示「已领取，可在我的券查看」；已领过则提示「已领取过」，不另做领券中心页
3. 查看：「订单 → 电商订单」页顶部的「我的券」入口，按可用 / 已使用 / 已过期列出（2026-11-04 确认维持只放订单页）
4. 使用：购物车按最优券预估；结算页默认选中最优组合，可更换（FR-130、FR-133）
5. 退回：待付款时取消、超时取消、平台原因整单取消时券退回；部分取消不退（FR-130）

#### 旅程 F：取消与退款

1. **待付款**：用户可自行取消订单，券退回（线上现状仅待付款可自助取消）
2. **待发货及之后**：用户不能自助取消，需联系客服
3. **缺货等平台原因取消**：运营在后台「异常订单」页处理（AB-28），PawCoin 部分立即退回；现金部分在订单详情出现「选择退款方式」，用户选退为 PawCoin 或线下打款（FR-134 ③）
4. **运单失败取消**：运营联系用户后按平台原因整单取消处理，同上（FR-172）

### 3.1 配送范围与运费信息前置（FR-127）

**目标：** 让用户在浏览阶段就知道「能不能送到、运费多少」，不再到结算页才撞墙（§2.1 A、E）。

#### 已确认项（2026-09-30 / 10-02 拍板）

### 3.2 结算页一页完成（FR-128）

**目标：** 从进入结算到看到付款二维码，全程不离开结算页（§2.1 B、C、D、H）。

#### 已确认项（2026-09-30 拍板）

### 3.4 优惠券（FR-130）

**目标：** 拉新首单 + 给运营日常促销的手段。券的具体面额、门槛、发放均由运营在后台配置，App 端不写死任何一张券。

#### 已确认项（2026-09-30 拍板）

**券类型：** 本次只有两种

| 类型 | 作用 |
|---|---|
| 满减券 | 商品金额满门槛后减固定金额 |
| 免运券 | 减免本单运费（减免额封顶，见 FR-172） |

**获取方式：** 三种，均需运营在后台配置后才存在——**没有系统默认自动发放的券**

- 新人券：运营配置后，符合条件的新用户自动获得
- 领取：用户在 App 内主动领取
- 兑换码：用户输入运营发出的兑换码获得

**叠加：** 每单最多使用 **1 张满减券 + 1 张免运券**。

**满额免运与免运券并存（2026-09-30 拍板）：**

- 现有的全站满额免运（运营设置门槛，商品金额达到门槛即整单免运）**继续保留**，与免运券并存
- 本单已满足满额免运时，**免运券不可用**，也不扣券
- 未满足满额免运的订单才可使用免运券

**计算顺序（2026-09-30 拍板）：**

```
商品金额
− 满减券
+ 运费
− 满额免运 或 免运券（二者只会生效其一；减免额封顶，见 FR-172）
+ 保价费（用户勾选保价时，见 FR-172）
= 应付金额
  → 应付金额由 PawCoin 与 QRIS 分担（PawCoin 是支付手段，不是折扣，见 FR-131）
```

- **运费相关的优惠一律按商品实付金额判断是否减免**（2026-10-06 拍板，取代 09-30「按券前商品金额」的口径）：满额免运门槛、免运券门槛都以**商品实付金额 = 商品金额 − 满减券**为准；用了满减券后实付金额低于门槛，则不满足免运。PawCoin 是支付手段，不影响实付金额
- 满减券的门槛按券前商品金额判断

#### 券的使用规则细节（2026-10-06 拍板）

- 券的适用范围为「指定品类 / 指定商品」时，门槛只计算适用范围内的商品金额
- 券抵扣额不超过其作用对象：满减券不超过适用商品金额，免运券不超过本单运费且受 FR-172 的减免封顶
- **结算页默认自动选中最优组合**（抵扣额最大的满减券 + 可用的免运券），用户可手动更换或不使用
- 不可用的券单独成组，标明原因：未达门槛 / 不在适用范围 / 已过期 / 本单已免运
- **退券**：订单在支付前取消或超时取消、平台原因取消（如缺货整单取消）时，券退回账户（仍在有效期内才可再用）；部分取消时券不退回，退款金额按 FR-134 ③ 的分摊口径计算

#### 券的入口（2026-10-06 拍板）

- **我的券**：入口放在「订单 → 电商订单」页面；按可用 / 已使用 / 已过期列出；页内有兑换码输入框
- **领券**：商品详情页显示该商品可领的券，点击领取；Toko 首页 banner 可跳转到领券（FR-132）
- **新人券到账**：新用户获得新人券时，在首次进入 Toko 时提示一次

#### 新人与新人券（2026-11-04 拍板）

- **新人的定义**：注册 **1 个月内**，且**从未在电商下过订单**的已注册用户。未注册的游客不算新人
- **发放时机**：新人**首次进入 Toko 时**发放，同时提示一次（见上「新人券到账」）
- **吸引游客注册**：运营配置了新人券活动时，游客进入 Toko 弹窗展示新人券，引导注册；注册后首次进入 Toko 即发放

#### 新人券细节（2026-11-04 拍板）

- 「下过订单」只算**已支付**的订单；下单后未付款、超时取消的不算，仍是新人
- 「1 个月」按注册时间起算 30 天，以首次进入 Toko 的时刻判断；进入时已超过 30 天则不发
- 新人在新人券活动开始前已进过 Toko 的：活动开始后、仍满足新人条件时，下一次进入 Toko 补发
- 游客弹窗：同一设备每个活动只弹一次；弹窗显示券面额与门槛，按钮「注册领取」进入注册，关闭后不再弹

#### 券的状态（2026-11-04 拍板）

```
已领（可用）→ 下单后被待付款订单占用 → 付款后：已使用
                                    → 订单取消：退回为可用（已过有效期则为已过期）
已领（可用）→ 过了有效期：已过期
```

- 被占用的券在「我的券」与其他订单的结算页中都不可选
- 退回规则见上「退券」：支付前取消、超时取消、平台原因整单取消时退回；部分取消不退

#### 券快过期提醒（2026-11-04 拍板）

- 用户手里有可用的券快过期时，提醒用户

#### 兑换码与过期提醒细节（2026-11-04 拍板）

- 兑换码失败提示：
  - 码不存在：「兑换码无效」
  - 一次性码已被使用：「该兑换码已被使用」
  - 券未开始、已结束或已停用：「该兑换码不在有效期内」
  - 已达每人限领张数：「你已领取过这张券」
  - 发放总量已领完：「券已被领完」
  - 未登录：先登录再兑换
- 防暴力试码：同一账号 1 小时内输错 10 次，锁定兑换 1 小时，提示「尝试次数过多，请稍后再试」
- 过期提醒：券到期前 48 小时发一条推送（同一用户同一天多张券到期合并为一条，点击进「我的券」）；「我的券」列表中 48 小时内到期的券显示「即将过期」标签

### 3.5 PawCoin 支付自选与单笔上限提醒（FR-131）

**定性（2026-09-30 拍板）：** **PawCoin 是真钱**（储值余额），在订单中是**支付手段**，不是折扣或优惠币。这决定了它在计算顺序中位于所有优惠之后（见 FR-130）。

#### 已确认项（2026-09-30 拍板）

- **用户自己决定本单用不用 PawCoin**——完全取代现行「有余额即自动抵扣到上限、用户不可选」的机制（FR-100 的自动抵扣逻辑随本条废止）
- **单笔上限 100 万 PawCoin 保留**
- 余额超过单笔上限时：本单最多使用 100 万，**超出部分由 QRIS 支付**；并提醒用户「单笔使用超过 100 万 PawCoin 会触发套现判定」
- PawCoin 足额覆盖应付金额时，本单无需 QRIS、提交即完成支付（沿用现有纯 PawCoin 支付能力）
- **PawCoin 在界面上作为支付方式呈现，不作为折扣呈现（2026-10-02 拍板）**：
  - 结算页「支付方式」区：「PawCoin 余额（当前余额 Rp xx）」可勾选；勾选后显示「PawCoin 支付 Rp a，剩余 Rp b 用 QRIS 支付」，不勾选则全额 QRIS
  - 余额足以覆盖应付金额且不超过单笔上限时，整单 PawCoin 支付，不出二维码
  - 单笔上限的套现判定提醒显示在此区
  - 订单详情页同理：金额明细止于应付金额，其下单列「支付方式」区，分列 PawCoin 支付额与 QRIS 支付额

#### 默认勾选状态（2026-10-06 拍板）

有可用余额时 **PawCoin 默认勾选**（与现行体验一致，避免老用户突然发现要多付现金）；用户取消勾选后，本次结算内保持不勾选，不跨订单记忆。

#### 已确认项（2026-09-30 拍板）

以下三项为本次必做（问题见 §2.2）：

- **① 支付回调丢失的兜底**：对「已出码、未收到回调」的订单，系统须主动向网关查询支付结果，查到已付款即按正常到账处理
- **② 超时取消后才到账的款项**：二维码有效期与订单时限对齐后（FR-128），只剩「临近到期付款、到账通知晚于订单取消」这一种极少数情况，**由用户联系客服处理**，不做自动恢复订单或自动退款
- **③ 异常订单取消必须退还现金部分**：整单取消时 PawCoin 与现金部分全额退回；部分取消某一行时，退回该行对应的金额
- **现金部分的退款去向（2026-10-02 拍板）**：沿用现有退货流程的两种去向——**退为 PawCoin**（即时到账）或**财务线下打款**到用户银行账户；PawCoin 部分只退回 PawCoin

#### 实现口径（2026-10-06 拍板）

- **① 查单时机**：用户在支付面板点「我已付款」时立即查一次；此外对待支付订单在付款窗口内定时轮询，付款窗口到期前做最后一次查询，查询失败不关单
- **③ 部分取消的退款分摊**：该行用过满减券时，按该行商品金额占适用商品金额的比例分摊券抵扣，退「该行实付」部分
- **② 让客服看得到这笔款**：现状这笔回调被直接丢弃，多数情况连日志都没有（见 §2.2 ②），客服无从查起。「订单已取消但款项到账」时在后台订单详情标记「取消后到账」并显示到账金额，客服据此按 ③ 的退款去向处理
- **去向由用户选择**：订单详情页出现「选择退款方式」入口（复用现有退款方式页），选择线下打款时填写收款银行账户；用户选定前款项不退出
  - ⚠️ 现状（2026-11-04 核 1.4.1）：App 端**没有任何退款 / 退货入口**。1.3.0 起订单详情的退货按钮已删除，退货申请页与退款方式页的路由都换成了「退货暂不可用」说明页，页面代码仍在。本条须恢复退款方式页的路由，并只从「选择退款方式」入口进入；退货申请入口仍保持关闭（售后不在本次范围）
- **③ 退款时的成长值扣回（2026-11-04 拍板）**：PawCoin 部分，以及用户把现金部分选为「退为 PawCoin」时，系统**自动扣回**；现金部分选「线下打款」时，由客服在后台订单详情**人工扣回**（AB-28）。扣回额按 1.4.0 FR-143 的规则：按退款金额占比扣回、累计不超过这笔消费当初入账的成长值。等级随之下降时**不通知用户**

### 3.10 物流接入 Biteship（FR-172）

**目标：** 运费按真实包裹报价、由用户自选快递，运单与物流轨迹自动化，取代现在按 Kecamatan 配置的固定运费、运营手工录运单号与人工时间线（§2.1 E、FR-133 物流现状）。

**Biteship 是什么：** 印尼的物流聚合商。传入发货地、收货地与包裹重量、体积，返回多家快递的报价；也可通过它下运单，并回传物流轨迹。

#### 已确认项（2026-11-03 拍板）

- **物流服务商为 Biteship**，用于三件事：结算时报价、付款后下运单、之后回传物流轨迹
- **能不能送须同时满足两个条件**：① 收货地址在运营开通的区域内（运营借此控制想卖哪些区域）；② Biteship 对该地址至少返回一家快递报价。任一不满足即不可下单。开通区域从此只决定卖不卖，**不再决定运费**，原按区域配置的固定运费停用
- **多家报价由用户自选**：结算页列出 Biteship 返回的快递，用户选择其一
- **运费由用户支付**：所选快递的运费计入应付金额，按 FR-130 的计算顺序
- **商品详情页显示最低价**：「运费 Rp X 起」，取当前送达地区所有快递报价中最低的一家（FR-127）
- **满额免运与免运券都保留，减免额封顶**：减免额不超过以下二者中较小的一个——① 本单所有可选快递中最低的运费；② 运营配置的上限（满额免运在后台配一个全局上限，免运券每张券配自己的上限，见后台 AB-38 / AB-24）。用户选了更贵的快递，超出部分自己付
  - 例：本单最低报价 Rp15.000，运营上限 Rp20.000，用户选了 Rp28.000 的快递 → 减免 Rp15.000，用户付运费 Rp13.000
- **包裹重量与体积必填**：每个 SKU 须填包裹重量与长宽高，作为报价依据；**没填的 SKU 不能卖**（App 端不可加入购物车、不可立即购买）。存量在售 SKU 须在上线前由运营补齐（后台见 AB-38）
- **运单通过 Biteship 下单**：用户付款后，运营在后台按用户所选快递向 Biteship 创建运单，自动拿到运单号（后台见 AB-38）
- **物流轨迹由 Biteship 回传**：订单详情显示轨迹时间线，取代现在的人工时间线（FR-133）

#### 报价、运单与订单状态规则（2026-11-03 拍板）

- 结算页快递列表**按运费从低到高排列**
- **提交订单时锁定所选快递与运费**，之后不再变动
- Biteship 询价失败（接口异常、超时）时，结算页提示暂时无法获取运费并提供重试，**不可提交**；不退回旧的固定运费
- Biteship 对该包裹无可用快递（如超重、超尺寸）时，按「该地区暂不支持快递配送」处理
- 报价与下运单的起点为后台配置的**发货地址**（只有一个，见 AB-38）
- Biteship 回传签收后，订单**自动标记为已送达**；后台手工「标记送达」保留作为兜底。之后的确认收货、退货窗口规则不变
- **Biteship 下运单失败**时，订单标记为运单失败并返回给运营，由运营决定：用同一家快递重新下单（适用于超时、接口报错、无可约取件时段、账户余额不足等临时问题），联系用户后取消订单，或手工填写运单（见 AB-38）。**研发须对重新下单做报警**：短时间内重新下单次数快速上升时通知技术排查（2026-11-04）。取消按平台原因整单取消处理：PawCoin 与现金部分全额退回（FR-134 ③，现金去向由用户选择），已用的券退回（FR-130）

#### 购物车运费、询价与保价（2026-11-04 拍板）

- **购物车显示运费**：购物车预估应付 = 所选商品金额 + 本单所有可选快递中最低的运费 − 默认最优券组合 − 满额免运减免，并显示「已省 Rp X」（FR-133）
- **控制询价次数**：Biteship 每次询价都要付费，研发实现时须避免重复询价，具体做法由研发决定
- **询价传参由研发决定**：传给 Biteship 哪些数据（商品明细、重量、体积等）由研发对照 Biteship 接口确定
- 进入结算页时**默认选中运费最低的一家**，用户可改选
- 提交前**换收货地址或改商品时重新询价**
- **保价（Asuransi）可选**：结算页快递区提供保价选项，由用户决定是否加入；保价费为商品价值的 0.5%（例：订单商品 Rp300.000 → 保价费 Rp1.500），由用户支付，计入应付金额（FR-130）；提交订单时与快递、运费一起锁定，下运单时一并传给 Biteship

#### 其余细节（2026-11-04 拍板）

- 商品详情页「运费 Rp X 起」按当前所选 SKU 与数量询价
- 购物车询价的收货地用默认地址；未登录或无地址时用详情页选过的送达地区，都没有则显示「选择地址后计算运费」、预估应付暂不含运费
- 结算页快递列表每项显示快递名称、服务类型、预计时效、运费
- 保价：默认不勾选；商品价值按商品实付金额（商品金额 − 满减券）计算；保价费不受满额免运、免运券减免；Biteship 显示某家快递不支持保价时，选中该快递则不显示保价选项

#### 物流状态与减免额展示（2026-11-04 拍板）

- **第一版只显示物流状态**，不做逐条轨迹时间线：订单详情显示快递名称、运单号（可复制）与当前状态，保留「去承运商官网查询」
- 用户看到的状态：**待揽收 → 已揽收 → 运输中 → 派送中 → 已签收**；Biteship 回传的状态与这五个文案如何对应，由研发对照 Biteship 接口确定
- **结算页显示实际减免额**：金额明细中满额免运 / 免运券一行显示本单实际减掉的金额（例：运费 Rp28.000，满额免运 −Rp15.000）；订单详情同样显示

#### 物流异常（2026-11-04 拍板）

用户付款、运单创建之后，可能出现以下四类异常。后台的标记与处理入口见 AB-38。

| 类型 | 典型原因 | 怎么发现 |
|---|---|---|
| ① 揽收失败 | 快递没来取件、找不到快递员 | Biteship 回传 |
| ② 派送失败被退回 | 地址错、联系不上收件人、用户拒收；或快递自身原因派送不到 | Biteship 回传退回 |
| ③ 卡件 | 中转积压等 | 物流状态 **3 天**没有更新 |
| ④ 丢件、破损 | 快递责任 | 长时间卡件后经 Biteship 确认，或用户向客服反馈 |

**② 被退回，按原因区分谁出运费：**

- **快递原因**（例如快递自身派送不到）：**平台承担**，免费重新发货；同时运营须向快递 / Biteship 处理责任认定与索赔，后台对该订单留「待索赔」提醒（AB-38）
- **用户原因**（地址错、联系不上、拒收）：**原订单取消**，已花掉的运费不退；商品须退回仓库，运营确认入库后退还商品款。用户仍想要的，**重新下单**购买，平台按新订单发货

**③ 卡件：** 物流状态 3 天没有更新时，后台自动标「物流停滞」，提醒运营去 Biteship 追件。

**④ 丢件、破损：**

- 用户**买了保价**：按商品价值赔付
- 用户**没买保价**：由客服与用户协商处理（退款或其他方式）
- 平台向快递 / Biteship 索赔，与 ② 快递原因一样留「待索赔」提醒

**用户侧显示：** 订单出现 ②③④ 类异常时，订单详情只显示一个简单状态「**配送异常，请联系平台客服**」，并放「联系客服」按钮；不向用户展示退回中、理赔中等内部状态。需要用户做选择（补运费重发、取消、协商赔付）时由客服联系用户。

**线上已有的「拒收」流程不复用（2026-11-04 核 1.4.1）：** 后端已有完整的拒收退款流程——用户在「已发货」时提交拒收申请，订单进入「退款中」，客服批准后跳过寄回与质检直接退款，并且**按平台责任处理**（全额退款，转 PawCoin 还加补偿溢价）。但 App 端退货入口自 1.3.0 起已换成「退货暂不可用」说明页，后台也只能审核用户提交的申请、不能代为发起，**这条流程实际上没人能触发**。它把拒收算作平台责任，与本节「用户原因不退运费」相反，因此不复用，拒收按 ② 用户原因处理。

**其余细节（2026-11-04 拍板）**

- ① 揽收失败按「Biteship 下运单失败」同样处理：运营重新下单、手工填运单或联系用户取消；用户侧继续显示「待发货」，不提示异常
- ③ 卡件期间，用户侧继续显示最后一个物流状态；只有运营确认为 ② 或 ④ 时才改为「配送异常」
- 用户原因取消时，退款 = 应付金额 − 运费 − 保价费，按 FR-134 ③ 的去向退回；券不退回
- 快递原因重新发货时，在原订单上新建一张运单，原运单保留在记录中；订单详情显示最新的运单号与物流状态
- 用户反馈破损时，客服请用户提供照片作为索赔凭证
