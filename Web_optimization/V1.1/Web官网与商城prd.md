# PRD：TailTopia 官网改版与网页商城

## 0. 文档说明

这次把官网 tailtopia.id 从一页英文宣传页，改成**印尼语为主、手机和电脑都能用、可以登录下单的网页商城**。同时完成贸易部 SIUPMSE 审核退回的整改项（见 [Revisi Perbaikan SIUPMSE Tailtopia - Sheet1.csv](Revisi%20Perbaikan%20SIUPMSE%20Tailtopia%20-%20Sheet1.csv)）。整改和商城两期合在一起做（2026-11-23 定）。

网页商城**复用 App 的后端接口**：账号、商品、购物车、订单、优惠券、Paw Coin 余额和 App 完全打通，同一个 Google / Apple 账号在两边是同一个用户。

## 2. 现状（2026-11-23 核 `origin/dev_1.5.2` 与线上 tailtopia.id）

### 2.1 现在的官网

- 一页英文宣传页，锚点导航：AI 症状自查、在线兽医、成长档案、社区、下载。下载按钮写的是「即将上线」（Coming soon），App 其实早已上线
- 已有手机适配（有 viewport 设置和汉堡菜单）
- 页脚联系方式：电话 +62 812-9369-2491、邮箱 lumosdigitalindonesia@gmail.com，**和 INATRADE 登记的 cs@tailtopia.id 不一致**
- 法务页面在 legal.tailtopia.id（由后端提供：`/terms`、`/privacy`、`/support`、`/account-deletion`），都是印尼语
- 部署：Cloudflare Pages（`docs/runbooks/website-deploy-cloudflare-pages.md`）；接口在 `https://api.tailtopia.id`（Cloudflare Tunnel）
- KTP 分享链接（1.5.4，Albar）用的是 `s.tailtopia.id` 子域名，和官网路由不冲突

### 2.2 后端能不能给网页用

电商接口基本都能直接用：商品、搜索、购物车、地址、运费估算、优惠券、结算试算、下单、订单、取消、确认收货、取消后的退款去向、客服工单、注销账号。商品图片是公开 CDN 链接。

挡住浏览器、必须改的地方（FR-316）：
- **没有跨域配置**：在搜索代码里找不到任何跨域设置，浏览器从 tailtopia.id 调 api.tailtopia.id 会被拦下
- **靠请求头 `X-App-Version` 区分新旧客户端**（`ClientAppVersion.java`）：不带这个头会被当成旧版 App，订单详情返回旧格式；如果网页冒充 1.5.2，又会把用户真实的 App 版本记录（`users.last_app_version`，推送版本门槛读这个字段）覆盖掉
- **Apple 登录只认 iOS 的应用标识**（`NimbusAppleTokenVerifier.java`）：网页的 Apple 登录用的是另一个标识（Services ID），会被拒。Google 登录现在就能用：App 用的就是网页类型的客户端 ID
- **订单没有记录是从哪个端下的**：`entrySource` 是加购来源，不是下单渠道
- **阿里云 OSS 没配跨域**：工单附件要从浏览器直传 OSS

### 2.3 账号

- 生产库（11-23，未注销）：只用 Google 的 28,907 人；只用 Apple 的 **415 人（1.4%）**，其中 1 人下过单
- 登录返回 access token（15 分钟）+ refresh token（30 天）。refresh 每次刷新都会作废旧的，**多个标签页同时刷新会互相踢下线**
- 带过期的 token 调公开接口也会返回 401（`SecurityConfig.java`），游客浏览时要先清掉过期 token

### 2.4 App 商城里已有、网页照搬的规则

以下以代码为准（11-23 定：已写进代码的规则按代码），网页不另定：
- 付款时限 60 分钟；建单 10 分钟后不再出码
- 只有待付款的订单能取消，取消后币和券退回
- 送达 7 天后自动确认收货；退货期限为签收后 7 天
- 保价费率是商品金额的 0.5%，默认不开
- Paw Coin 1 币 = Rp 1，每单最多抵扣 Rp 1,000,000，可抵扣运费，默认开启
- 用 Paw Coin 付的部分只退回 Paw Coin；现金部分由用户选择退成 Paw Coin（即时到账）或退到 BCA（免费）/ OVO / GoPay（手续费 Rp 2,500），最多 3 个工作日到账
- 商品详情正文（`detailHtml`）按纯文本显示，不渲染富文本
- 游客没有购物车；游客点加购或立即购买时弹登录，登录后自动完成刚才的操作

### 2.5 客服

- 客服配置（生产库 `support_contact_config`）：WhatsApp 081290906953、邮箱 cs@tailtopia.id。**网页只用邮箱**，不显示 WhatsApp
- App 里的客服抽屉：WhatsApp、邮箱、「提交问题」（Lapor Masalah）工单
- 工单接口：`POST/GET /api/v1/support-tickets`，可以关联订单（`relatedOrderToken`），最多 5 个附件

## 3. 功能与需求

### 3.1 全站语言（FR-298）

- 默认**印尼语**，可以切换英文。切换入口在顶栏（手机端放在菜单里），显示「ID / EN」
- 记住用户的选择（存在本地浏览器）；第一次访问一律印尼语，不按浏览器语言自动切换（审核要求印尼语，避免审核方看到英文）
- 调接口时带上 `Accept-Language`（`id` / `en`），和 App 一样
- 商品名称、商品详情、Banner 只有一种语言，切换英文后不翻译
- 法务页（legal.tailtopia.id）只有印尼语，从英文界面点进去也是印尼语
- 页面 `<html lang>` 跟着当前语言改

#### 验收标准
- 新用户第一次打开任意页面都是印尼语，`<html lang="id">`
- 切换到英文后刷新、跳转页面仍是英文；清掉浏览器数据后回到印尼语
- 所有界面文字都有印尼语和英文两版，没有中文、没有漏翻

### 3.2 消费者投诉服务区块（FR-299）

**位置：**
- **全站页脚**（包括首页、商城、商品详情、结算、付款、订单、账户、关于、购物指南等所有页面），登录前后都显示
- **我的账户页**（FR-313）里再放一份完整的区块，满足「登录后清楚可见」
- 结算页、付款页的页脚也不能隐藏或折叠

**内容和顺序固定如下**，**不放电话**。App 服务条款页末尾同步改成完全一样的文字（11-24 定，见 FR-316 第 8 条）。区块标题和机构名称两种语言都保留印尼语原文（这是审核要求的固定格式）：

```
Layanan Pengaduan Konsumen
Tailtopia (PT Lumos Digital Indonesia)
Email: cs@tailtopia.id

Kementerian Perdagangan Direktorat Jenderal Perlindungan Konsumen dan Tertib Niaga
Kementerian Perdagangan RI
WhatsApp: +62 853 1111 1010
```

中文意思：消费者投诉服务 / Tailtopia（PT Lumos Digital Indonesia）邮箱 / 贸易部消费者保护与贸易秩序总局 / 印尼贸易部 WhatsApp。

- 邮箱可点击（`mailto:`）；贸易部 WhatsApp 号码可点击，打开 `https://wa.me/6285311111010`
- 邮箱**写死在页面里**，不从客服配置接口读（避免后台改了号码导致和 INATRADE 登记不一致）
- 不能用 Cloudflare 的邮箱混淆（现在官网用了，审核截图会显示成「[email protected]」）

#### 验收标准

- 手机和电脑两种宽度下区块都完整显示，不折叠、不截断

#### UI 稿需要

#### UI 稿需要

### 3.11 QRIS 付款（FR-308）

- 下单后自动打开付款页（不是弹层，有独立网址，刷新后还在）
- 显示金额、二维码、倒计时「请在…内支付」（按后端返回的付款截止时间）、订单号（可复制）
- **电脑**：二维码放大居中，提示「用手机上的电子钱包或银行 App 扫码」
- **手机**：二维码下方「保存二维码」（Simpan Kode QR）按钮，把二维码存成图片；下面写清步骤：保存二维码 → 打开电子钱包或银行 App → 扫码 → 从相册选这张图片 → 付款（11-23 定：手机网页截图扫码可以接受）
- 折叠的「支付方法和支持的应用」，内容照 App
- 每 3 秒查一次付款状态；「我已付款」按钮主动查一次（后端限 10 秒一次），还没到账时提示「还没收到付款」
- 结果：到账 → 付款成功页（「查看订单」「继续购物」）；被拒 → 提示后可以重新付款；超时 → 「付款时间已过，订单已取消」；二维码生成失败 → 提示重试
- 用户关掉页面不影响订单，可以从订单列表或详情再次付款：同一笔订单的二维码出过一次就复用（出码后 65 分钟内有效），**不会重新生成**；只有下单 10 分钟内一次都没出成码、或付款被拒后超过 10 分钟再付，才出不了码（`ShopOrderPaymentService.payGate`），付款页显示说明、等订单自动取消

#### 验收标准
- 手机上保存的二维码图片能被 GoPay / OVO / DANA / 银行 App 从相册识别并完成付款
- 付款后不刷新页面，后端收到支付服务商的到账通知后 3 秒内自动跳到成功页

### 3.18 自适应布局与非功能要求（FR-315）

- **宽度**：手机（< 768px）、平板（768–1199px）、电脑（≥ 1200px）。最小支持 360px 宽，任何宽度都不能出现横向滚动条
- **浏览器**：Chrome、Safari（iOS 15+）、Edge 最近两个大版本；三星浏览器
- **速度**：手机 4G 下，商城首页和商品详情首屏 3 秒内出来
- **搜索引擎收录**：首页、关于页、购物指南、商城首页、商品详情要能被搜索引擎直接读到内容（服务端渲染或预渲染），每页有自己的标题、描述和分享图；生成站点地图
- **安全**：
  - 登录 token 的存放方式由研发评估（见 OQ-1），不能把 refresh token 明文放在能被页面脚本随意读取的地方而不做防护
  - 多个标签页同时刷新 token 时只能有一个请求真正去刷新，其他等结果
  - 商品详情正文、Banner 外链都不能执行脚本
- **无障碍**：按钮有文字标签；颜色对比度达标；键盘能操作结算和付款流程
- **找不到的页面**：不存在的网址显示 404 页（带回首页、去商城的按钮，页脚照常有投诉区块）。**404 要能让我们知道**（11-24 操作者定）：①每次出现 404，网页自动向自家埋点服务器上报一条 `web_404`（出错的网址、来源页面、浏览器语言），运营后台能按网址汇总；②页面上加「报告问题」按钮，用户点一下即上报（同一事件加 `user_reported=true`），不用登录、不用填表，点完提示「谢谢，我们收到了」；已下架商品的网址显示「该商品已停售」，同时告诉搜索引擎这一页已经没了（返回 404 或 410），不再收录

#### 验收标准
- 360px、768px、1440px 三种宽度下所有页面没有横向滚动条，内容不重叠
- 用 Google 的网址检查工具能读到商品详情页的标题、价格和图片

### 3.19 后端改造（FR-316）

1. **跨域**：允许 `https://tailtopia.id` 和 `https://www.tailtopia.id`（加上测试环境的网址）调接口，允许 `Authorization`、`Idempotency-Key`、`Content-Type`、`Accept-Language`、`X-Client` 等请求头。也可以改走同源转发，研发定（见 OQ-1）
2. **网页端标识**：网页所有请求带 `X-Client: web`。后端看到这个头时：
   - 按新版客户端处理（不返回旧版兼容格式，不放宽出码时限，邮编不符照常报 POSTAL_MISMATCH）
   - **不写** `users.last_app_version`
3. **Apple 登录**：校验时同时接受 iOS 应用标识和网页的 Services ID。需要在苹果开发者后台建 Services ID、验证 tailtopia.id 域名、配置回跳网址
4. **Google 登录**：在 Google 后台给现有的网页客户端加上 tailtopia.id 作为允许的来源（只改配置，不改代码）
5. **订单渠道**：商城订单新增字段记录下单渠道（`APP` / `WEB`），按请求头 `X-Client` 写入，用于数据统计。本版运营后台不加筛选（不占 AB 编号）。加购来源 `entrySource` 网页统一传 `WEB_*` 开头的值（比如 `WEB_HOME`、`WEB_SEARCH`、`WEB_DETAIL`）
6. **OSS 跨域**：给存工单附件的 OSS 存储桶配置跨域，允许网页直传
7. 新增接口如果放在 `/api/v1/me/**` 下，记得同步加进 `SecurityConfig` 的用户权限规则（兽医 token 和用户 id 会撞号）
8. **服务条款页的投诉区块**：把 `petgo-backend/src/main/resources/legal/terms.html` 末尾现在的「Tailtopia / Email: cs@tailtopia.id / 贸易部…」改成和 FR-299 完全一样的文字：加上标题「Layanan Pengaduan Konsumen」（消费者投诉服务），公司一行改为「Tailtopia (PT Lumos Digital Indonesia)」。只改这一页的文字，App 不用发版。法务改购物章节时如果整份条款重写，要保留这一块

#### 验收标准
- 浏览器从 tailtopia.id 调所有商城接口都不报跨域错误
- 用户在网页操作后，`users.last_app_version` 不变
- 网页下的订单渠道字段是 `WEB`，App 下的是 `APP`

### 3.21 全站视觉改版（FR-318）

现在的官网不好看（2026-11-24 操作者提出）。核对线上 `styles.css` 和页面，具体问题是：

| 问题 | 现状（11-24 核线上） |
|---|---|
| 字号乱 | 一共用了 **29 种字号**，px 和 rem 混用；最小的 8px、8.5px、9px，手机上基本看不清 |
| 品牌色不统一 | App 品牌紫是 #845EC9，官网还混用了另一种紫 #7D45F6（logo 原色，App 里叫 `AppColors.brandViolet`），以及多个没有出处的深浅紫（11-24 定：主色统一用 logo 原色 #7D45F6，见下方要求） |
| 没有真实图片 | 页面上只有 logo 两张图；5 个「手机截图」是用 CSS 画的假手机（状态栏写死 9:41），里面的字只有 8–11px，看不出 App 真实的样子 |
| 像模板 | 一页从上到下都是「标题 + 一段话 + 假手机」的重复结构，没有宠物、没有用户、没有商品，看不出是宠物社区和宠物商城 |
| 和 App 不像一家 | 字体、圆角、按钮、卡片和 App 都不一样，用户从官网下载 App 后会觉得换了一个产品 |

**要求：**
- **品牌和 App 统一**：字体用 App 的 Poppins；颜色只用 App 主题里的颜色（`petgo_app/lib/core/theme/colors.dart`，品牌紫 #845EC9 及其色阶）；圆角、按钮、卡片、商品卡的样子向 App 靠齐，让用户觉得是同一个产品
- **一套网页用的尺寸规范**：字号、间距、圆角只能从一张固定的表里取（参照 App 的 `typography.dart` / `spacing.dart`，网页另定一张，写进 UI 稿的规范页）。正文最小 14px，辅助文字最小 12px，**不再出现 12px 以下的字**（商品角标这类徽标除外）
- **用真实内容代替假手机**：首页和关于页用 App 真实截图（放进设备框）和宠物照片；商城部分直接展示真实商品。图片要做压缩，不能拖慢首屏（FR-315 的 3 秒要求）
- **首页结构重排**：明确告诉访客 TailTopia 是什么、能做什么，再把人分流到两个地方：「去商城买东西」和「下载 App」。具体版式在 UI 稿第三步出**两个方向**并排对比，由操作者选
- **商城页面风格**：和官网首页是同一套视觉，但以商品为主，少装饰，保证浏览和下单效率
- **已定视觉方向（11-25 操作者选定方向 D「干净 + playful」，全站官网 + 商城统一）**：白底为主、大留白；每屏只有一块**饱和实色主形状**（圆 / 胶囊 / 软方块）当焦点，站与站换色换形；好玩的感觉靠**真实宠物照片**和动作来做，不靠堆颜色或装饰。另外三个方向（A 年度报告 / B 贴纸潮牌 / C 韩式轻奢）的原型留作备用，不进本版。规则：
  - **品牌主色用 logo 原色 #7D45F6**（App `AppColors.brandViolet`）：用在主按钮、logo、进度和少量点睛；首屏物种台、小测框可以用实色紫。#845EC9 色阶只用在链接等小面积
  - **主形状颜色**只取 App 主题里的实色：品牌紫、金 #F6A609、珊瑚 #F0425A、物种线色（兔 #C23E73、鸟 #1F72B8、猫 #B84D15、龟 #23805A、鱼 #0B7F8C 等），每屏约占 25–40%（11-26 第四步操作者定，原写 25–30%）；实色上的文字用白色，对比度 ≥ 4.5:1，对比度不够的颜色上不放文字；物种浅底只做辅色（标签、提示框）。不做整屏铺色，不做描边 + 硬投影，不用颗粒纹理或半透明叠色
  - **真实宠物照片**：首屏物种选择用 15 种宠物的真实抠图（去背景、白色描边），按真实体型错落站在紫色台上；首页有一只跨站「你的宠物」角色，选猫 / 狗后每站换对应姿势照片，每站进场方式和道具不同（KTP 卡、相机、饭碗、铃铛、体温计、蛋糕）。照片上线用自有拍摄或采购素材（原型里是 Wikimedia Commons 公有领域占位图），全站风格统一；商品图仍来自商城后台
  - **logo 一律用真实品牌资产**（`petgo_app/assets/brand/logo.svg` 紫色字标、`wordmark_brand.svg` 白色字标、`app_icon.png`），不许用图标 + 文字拼一个
  - **商城不挂单一物种色**：商品以猫狗用品为主，商城用品牌色，商品图底色按适用物种（猫 / 狗 / 通用）
  - **字体**：展示标题用 Bricolage Grotesque（OFL 开源，网页按需加载拉丁子集），正文、按钮、表单仍用 App 的 Poppins
  - **商城首页例外（11-26 操作者定）**：商城首页用方向 A 的版式和配色（整块高饱和色块紫 / 金 / 珊瑚 / 墨轮换、斜放大字「TOKO」），更有活力；字体和组件（顶栏、页脚、商品卡、按钮、券、弹窗）仍用 D，点进商品详情、购物车不跳风格
  - **动效**：只动 transform / opacity / clip-path；页面默认就是最终可见状态，动画只负责出场，浏览器暂停动画时内容也必须完整显示；跟随系统「减少动态效果」设置时全部静止
- **网页字号表（11-24 定）**：正文 16（App 15，网页阅读距离更远）；展示标题手机 40 / 30、电脑 64 / 48；H1 24、H2 18、小字 13、说明 12，徽标 9–11
- **手机和电脑都要好看**：不是把手机版拉宽，电脑上要用好横向空间（多列商品、左右分栏的详情和结算）

- 每种宽度下（手机 / 电脑分别统计）实际用到的字号种类不超过 10 种（徽标除外），全部来自规范表；没有 12px 以下的正文或说明文字（11-24 随字号表改为按宽度统计：展示标题和站牌数字手机、电脑各用一套，合并统计会超过 10 种）

- 首页没有用 CSS 画的假手机，App 截图都是真实截图
- 整站（官网 + 商城）按操作者最终选定的方向统一；全站 logo 都是真实品牌资产

#### UI 稿需要
- 视觉规范页（颜色、字号、间距、圆角、按钮、商品卡，手机 / 电脑两套尺寸）
- 第三步：首页、关于页、商城首页、商品详情各出两个视觉方向对比

**30 秒宠物性格小测的规则：**
- 位置：时间线开头「第 1 天：先认识它」（11-24 改，原为滚动故事之后）。不用登录
- 流程：选「猫 / 狗 / 其他」→ 填宠物名（可以跳过，跳过时题目里用「你家宠物」anabulmu；名字只在浏览器内存里用，不上传、不保存；11-24 定）→ 4 道题（一屏一题，点选项自动跳下一题，交互照 1.5.4 性格测试 FR-292）→ 生成中（约 1.5 秒）→ 结果卡
- 题目：从 1.5.4 定下的 10 题里，四个字母维度各取 1 题（每个维度的锚题），按所选物种用对应题库；题目、选项、权重和 App 完全一样（题目里的宠物名换成用户填的名字），计分规则照 App（不算第 5 维度的能量后缀）

- **不能展示 App 里要付费解锁的内容**（详细解读、配型结果等），以免和 App 的付费内容冲突
- 依赖：1.5.4 性格测试 PRD（FR-292 ~ FR-297）定稿的 10 题题目和文案；如果网页先上线，就用当时 App 线上的题库

**硬性约束**（所有交互形式都要满足）：
- **文字和按钮都是真实网页内容**，不能画在动画里：搜索引擎要能读到，要能切换语言，屏幕阅读器要能读
- **首屏不能变慢**：首屏的标题、两个主按钮（「去商城」「下载 App」）先显示出来，动画资源在这之后再加载。首页满足 FR-315 的 3 秒要求；动画额外增加的下载量建议不超过 600KB（压缩后），研发评估后定
- **不能用脚本接管页面滚动**：整屏切换只用浏览器原生吸附（CSS scroll-snap），不用脚本拦截滚轮 / 触摸；触屏、键盘、触控板、搜索引擎都照常；一站内容超过一屏时（如商品那一站）允许在这一站内正常滚动（11-24 改：操作者要「页面切换、没有下滑感」）
- **手机也要有交互**：鼠标悬停的效果在手机上要有对应的触摸或滚动版本，不能只有电脑能玩
- **中低端安卓也要流畅**：在印尼常见的中低端安卓机上不卡顿（测试机型由研发和测试定），卡顿时自动降级成静态
- **减弱动效**：系统设置了「减少动态效果」的用户，只显示静态画面，信息和按钮一样不少
- **加载失败有兜底**：动画资源加载失败或浏览器不支持时显示静态图片，页面不留空白
- **看不见时暂停**：动画滚出屏幕或切到别的标签页时暂停，回来再继续
- **不能挡住正事**：顶栏、主按钮、页脚投诉区块（FR-299）任何时候都不能被动画盖住
- 动效只放在**首页**（关于页可以少量复用）；商城、详情、结算、付款页保持朴素，不加装饰动效
- **常驻转化按钮**（11-24 定）：首页、关于页的首屏滚出视口后，底部（电脑为右下）常驻一条浮动按钮栏「下载 App」「去商城」，不用等用户看到页底；页底的收尾区块保留

**方向选定后**，按 rive-kb 的动效交接清单补全以下内容，写回这一节再交研发（如果选的方向不用 Rive，就写对应的实现方式和同样的约束）：
- `.riv` 文件版本、artboard 名、状态机名
- 网页这边要传给动画的每个属性：类型、可选值、默认值、作用（比如「看向的位置 x / y」「当前是第几屏」）
- 触发器（比如「点击」）能不能连续触发、连续点会怎样
- 动画用到的外部图片由谁加载
- 网页运行库、版本、渲染方式、在不同屏幕宽度下怎么缩放和对齐
- 减弱动效时的样子、降级方案、已知限制
- 一段最小的接入示例

#### 验收标准（QA 场景）
- 第一次打开：标题和两个主按钮先出来，动画随后出现，不闪、不跳位
- 网速慢 / 动画加载失败：显示静态图，页面完整
- 快速连续点击或来回滑动：动画不卡死、不叠加错乱
- 动画进行中改变方向（比如滚到一半往回滚）：能平滑反转
- 猫和狗同时被触发（比如快速在两只之间来回点）：两只各自反应，互不打断、不错位
- 360px 手机和 1440px 电脑上都完整显示，不被裁切
- 鼠标和触摸都能操作
- 滚出屏幕、切到别的标签页：动画暂停；回来后继续
- 系统打开「减少动态效果」：只显示静态画面
- 性格小测：猫、狗、其他各答一遍，结果卡和用同样答案在 App 里算出的四字母一致；保存的图片带 TailTopia 标识和网址
