# PRD：TailTopia 宠物 App V1.5.2——宠物推荐排序优化

## 0. 文档说明

「逛别人家的毛孩子」宠物推荐的排序规则重做。三个目标（2026-11-19 操作者提出、2026-11-20 定方案）：

1. **不审美疲劳**：养猫的人也想看别的宠物，不要翻很久都是同一类。
2. **新宠物能上推荐**：新建档的宠物要有露脸机会。
3. **热门多曝光，但不只看热门**：热门宠物让更多人看见，但页面不能被热门霸占。

| 编号 | 功能 | 来源 |
|---|---|---|
| **FR-252** | 每页按配方混排：同类 3 / 其他类 3 / 新宠 2 / 热门 2（每页 10 张时），取代现在的「同品种 → 同类 → 其他类」三段先后排；首日推荐页单独一套 2 / 2 / 0 / 2 | 2026-11-20 定比例 |
| **FR-253** | 防扎堆：同一细分物种连续出现不超过 2 张（排不开时允许超出） | 2026-11-20 定 |
| **FR-254** | 「同类」改按细分物种（1.5.0 的 27 种）判断；同品种在同类名额内排前面 | 读代码发现仍按猫 / 狗 / 其他三大类；2026-11-20 定保留同品种优先 |
| **FR-255** | 新宠物名额：建档 14 天内、有头像、至少 1 条带图的公开成长记录 | 2026-11-20 定门槛 |
| **FR-256** | 热门名额：近 14 天真人点赞，越近权重越高；每人每天从热门前 30 只里轮换 | 2026-11-20 定 |
| **FR-257** | 普通位排序：最近更新优先，热度次之，加按「人 + 日期」固定的随机；一次连续翻页内不重复不漏，隔天顺序变化 | 2026-11-20 定 |
| **FR-258** | 埋点「命中段」扩充为六种来源 | FR-252 配套 |
| **AB-59** | 后台「算法参数」页新增「宠物推荐」配置卡：配方比例（含首日推荐页）、连续上限、新宠门槛、热门窗口与池大小、随机幅度 | 操作者要求「参数产品可调」 |

**版本：** **V1.5.2**。

**编号：** 接 FR-251、AB-58（V1.5.2《头像框与推送直达》PRD），本文用 **FR-252 ~ FR-258**、**AB-59**。若其他 V1.5.2 PRD 同期占了这些号，以先入库者为准，本文顺延。

**代码基线：** `petgo-platform` `main`（`172f77b9e`，2026-11-19；已含 1.5.0 的细分物种字段 `pet_profiles.pet_species`）。

**本文不含：**
- **「看过的少推」（曝光记录 / 降权）**：不做。操作者 11-20 原话：「昨天看过了，那今天他又更新了呢，我还是想看更新的最新内容」。宠物一更新就该往前排，靠 FR-257 的新鲜度保证，不靠记录谁看过。
- **首页内容流（帖子）推荐算法**：那是另一套（FR-95），不动。
- **推荐卡片样式**：本版本不加「新」「热门」角标，卡片 UI 不改（2026-11-20 定；上线后看各来源点击率再议）。
- **按位置分配方**：除首日推荐页外，本版本所有位置用同一套配方（2026-11-20 定；上线后按位置看数据再议）。
- **入池基本条件之外的排除规则**：自己的、已追更的、互相拉黑的、主人注销 / 封号的、没头像的，照旧排除，不改。

**UI 稿：** 不出稿。App 端无界面变化；后台只在「算法参数」页加一张配置卡，沿用现有配置卡样式。

**算法文档：** 排序规则、参数和数据依据同步在 `TailTopia/2.数据算法/宠物推荐算法.md`（V1 节）；改本 PRD 的规则时一并改那份。

## 1. 版本目标

现在的推荐是「先把和你同品种的看完，再看同类，最后才轮到其他类」。养猫的用户要翻过约 130 只猫（13 页）才见得到第一只狗；新宠物因为要攒满 3 条公开记录才进得了池子，近两周新建档的 550 只发过帖的宠物全被挡在外面；排序又是「今天谁更新了谁在前」，同品种的人看到的顺序一模一样。

目标：**每一页都有同类、有别的类、有新面孔、有热门；每天打开都不一样；宠物一更新就能往前排。**

**观察指标（上线后看，不做 A/B）：**
- 推荐卡点击率，按来源（同类 / 其他类 / 新宠 / 热门）拆
- 推荐带来的追更（关注宠物）数，上线前后对比
- 每天被推荐曝光过的**不同宠物数**（是否从「总是那一批」变成更分散）
- 新宠物被推荐后 7 天内再发帖的比例（露脸是否激励继续记录）

数据口径：按自建埋点（analytics-pipeline）算，不依赖 PostHog（11-08 起断数）。

## 2. 现状（2026-11-19 读 `main`，数据取 11-19 生产库）

### 2.1 推荐用在哪

同一个推荐接口（登录 `GET /api/v1/me/pet-recommendations`、游客 `GET /api/v1/public/pet-recommendations`）供下面这些位置：

| 位置 | 一次取几张 | 翻页 |
|---|---|---|
| 全屏推荐列表页（`/pet-recommendations`，新手任务也落这里） | 10 | 可翻页 |
| 首页（Discover）横滑行 | 10 | 不翻 |
| 关注列表页（看自己的）推荐区 | 10 | 不翻 |
| Diary 页（空态 / 看别人的）推荐网格 | 10 | 不翻 |
| 首日推荐页（新用户注册后） | 6 | 不翻 |
| 游客横条 | 6 | 不翻（服务端 10 分钟快照） |

**本次改的是这一个接口的排序，以上位置全部生效。** 只有**首日推荐页**用单独的配方（见 §3.1），其他位置同一套规则。

### 2.2 现在的规则

- **入池条件**：近 14 天发过公开成长记录（Diary）帖；公开成长记录累计 ≥ 3 条；有头像；主人未注销 / 未封号
- **对看的人排除**：自己的宠物、已追更的、与自己互相拉黑（任一方）的
- **分三段先后排**（按看的人的默认宠物 = 最早建档、在用的那只）：同品种 → 同类其他品种 → 其他类；没填品种跳过第一段；没宠物 / 游客只有全站一段
- **段内排序**：最后发帖日期（雅加达时间）越新越前 → 同一天比近 14 天真人点赞数（不含自动赞）→ 同赞数比发帖时刻
- **「同类」按 `pet_type`（猫 / 狗 / 其他三大类）判断**，没用 1.5.0 的细分物种：养兔子的人「同类」里会看到仓鼠、鸟、鸡
- **没有随机**：同品种的人看到的顺序完全一样
- **后台没有任何可调参数**（代码注释「零后台依赖」）

### 2.3 数据（11-19 生产库）

| | 猫 | 其他 | 狗 | 合计 |
|---|---|---|---|---|
| 现在能进推荐池 | 130 | 36 | 16 | **182** |
| 近 14 天发过帖、但不满 3 条被挡 | 448 | 116 | 40 | **604** |
| 其中近 14 天新建档的 | 409 | 108 | 33 | **550** |

- 被挡的 604 只里，**另有 54 只**建档已超过 14 天、近 14 天发过帖但公开记录不满 3 条：本次既进不了新宠池也进不了普通池，**先接受**，后续优化再处理（2026-11-20 定）
- 推荐池 182 只近 14 天共收到真人点赞 1,514 个；**前 10% 的宠物拿走 52%**；中位数 3 个；32 只一个赞都没有；最高 84 个
- 近 7 天活跃用户里养猫的约 65%、其他宠物 16%、狗 5%、没有在用宠物档案的 14%

## 3. 功能与需求

### 3.1 混排配方（FR-252）

每页按配方从四个来源取卡，**混在一起**出，不再按段先后。

| 来源 | 每页 10 张时 | 取哪些宠物 |
|---|---|---|
| **同类** | 3 | 与看的人默认宠物**细分物种相同**（FR-254）；同品种排前 |
| **其他类** | 3 | 细分物种不同的 |
| **新宠** | 2 | 符合 FR-255 的新宠物，不分物种 |
| **热门** | 2 | 符合 FR-256 的热门宠物，不分物种 |

**页面张数不是 10 时按比例折算**（四舍五入，保证总数对得上）：

| 一页张数 | 同类 / 其他类 / 新宠 / 热门 |
|---|---|
| 10 | 3 / 3 / 2 / 2 |
| 6 | 2 / 2 / 1 / 1 |

没有宠物的用户、游客（无同类名额）：

| 一页张数 | 其他类（全站） / 新宠 / 热门 |
|---|---|
| 10 | 6 / 2 / 2 |
| 6 | 4 / 1 / 1 |

**首日推荐页（新用户注册后第一屏推荐，6 张）单独一套配方**，不放新宠，名额让给热门，保证新用户第一眼看到的是内容丰富的宠物：

| 首日推荐页 | 同类 / 其他类 / 新宠 / 热门 |
|---|---|
| 有宠物 | 2 / 2 / 0 / 2 |
| 没宠物 | — / 4 / 0 / 2 |

- 区分方式：现在首日推荐页和其他位置调的是同一个接口、只传 `limit=6`，服务端分不出来。接口**新增一个位置参数**（如 `scene=onboarding`，命名由架构定），首日推荐页传，其他位置不传；不传的走通用配方
- 旧版 App 的首日推荐页不传该参数，仍走通用配方 2 / 2 / 1 / 1，可以接受
- 首日推荐页补位时**跳过新宠**：按「其他类 → 热门 → 同类」补，热门同样最多比配方多 1 张（即最多 3 张）
- 新宠物如果本身进了热门池，仍可能以热门名额出现在首日推荐页，属正常

**特殊情况：**
- **没有宠物的用户、游客**：没有「同类」名额，同类的张数并入「其他类」（此时其他类 = 全站，不分物种），见上表
- **某来源没货了**（比如养鸟的，同类只有 1 只）：空出的名额按「**其他类 → 新宠 → 热门 → 同类**」顺序补（跳过没货的那个来源自己）；**热门每页最多比配方多 1 张**（10 张时最多 3 张热门），到上限后继续往后补；四个来源都没货了才少出、并结束翻页
- **同一只宠物同时符合多个来源**（比如新宠又是热门）：只出一次。四个来源按「**热门 → 新宠 → 同类 → 其他类**」先后取，后取的来源跳过已经出过的宠物（所以新宠又是热门时算热门）；一次连续翻页内不重复（见 FR-257 翻页一致性）
- **卡片在页内的位置**：按 FR-253 打散，不固定「前 3 张一定是同类」

**验收：**
- 养猫用户打开推荐列表，第一页 10 张里至少 3 张不是猫（其他类够的前提下）
- 养鸟等同类很少的用户，第一页热门不超过 3 张
- 新版 App 新用户的首日推荐页：6 张里没有新宠名额的卡，热门 2 张（同类不够时最多 3 张）
- 第一页就能看到新宠物（新宠池非空时）
- 没宠物 / 游客的第一页没有空位、不报错

### 3.2 防扎堆（FR-253）

- **同一细分物种连续出现不超过 2 张**（后台可调，AB-59）
- 实在排不开（比如整页只剩猫可出）时允许超出，不为了凑规则少出卡
- **养猫用户常排不开，属预期**：新宠、热门两个来源不分物种，而新宠池约 3/4、推荐池约 7/10 是猫，养猫用户一页 10 张里大约 8 张是猫，目标①只靠其他类 3 张保证（2026-11-20 定接受现状，不给新宠 / 热门加物种限制）

**验收：** 能排开时（页内非同物种的卡够插空）不出现连续 3 张同物种；排不开时照常出满，不少出卡。

### 3.3 同类按细分物种（FR-254）

- 「同类 / 其他类」按 `pet_species`（1.5.0 的 27 种细分物种）判断，不再按猫 / 狗 / 其他三大类
- 同品种（规范化后相同，即去首尾空格、不分大小写）在「同类」名额内排在不同品种前面
- 看的人的宠物仍按「默认宠物」规则取（最早建档、在用的那只），不改
- 存量宠物的物种迁移（V1.5.0 Story 1.4）已跑完，细分物种可直接用

**验收：** 养兔子的用户，同类名额里只出兔子；没有兔子可出时由其他来源补（不把仓鼠当同类）。

### 3.4 新宠名额（FR-255）

**新宠物定义**（同时满足）：
- 宠物**建档 14 天内**
- 有头像
- **至少 1 条带图的公开成长记录**（Diary）
- 主人未注销 / 未封号；对看的人照旧排除自己的、已追更的、互相拉黑的

**排序**：新宠池内按 FR-257 同一套规则（最近更新优先 + 热度 + 每日随机）。

- 新宠物**不受普通池「≥ 3 条」门槛**限制；它满 3 条、或建档超过 14 天后，自然转进普通池（同类 / 其他类）
- 两个门槛（14 天、1 条）后台可调（AB-59）

**验收：** 今天新建档、发了 1 条带图公开 Diary 的宠物，当天能在别人的推荐里出现。

### 3.5 热门名额（FR-256）

**热度** = 近 14 天收到的**真人点赞**数（不含自动赞），**越近的赞权重越高**（按时间衰减，建议半衰期 3 天，由架构定具体公式）。只算公开成长记录收到的赞，与现状口径一致。

**热门池** = 普通池 + 新宠池的宠物里，热度前 30 名（新宠物也能进热门）。

**轮换**：每个人每天从热门池里按「人 + 日期」固定的随机顺序取，热度越高被排到前面的概率越大，但**不是所有人都只看到前几名**。

- 热门宠物也在同类 / 其他类里参与排序（热度是排序因素之一），所以热门宠物整体曝光会明显多于普通宠物——这是目标③要的「让更多人看见」；名额上限保证页面不被热门占满
- 14 天窗口、池大小 30、衰减半衰期后台可调（AB-59）
- 普通位排序里的「热度」（FR-257）用的就是这同一个值，全文只有一套热度口径（14 天，与现状窗口一致）

**验收：**
- 热度第 1 名的宠物，出现在用户前两页的概率**不低于 60%**（抽样 100 个用户统计；达不到时调后台权重）
- 两个不同用户同一天的前两页，热门名额里出现的宠物不完全相同
- 同一用户隔天打开，热门名额的顺序不同

### 3.6 普通位排序（FR-257）

同类、其他类、新宠三个来源的池内排序，统一规则：

1. **最近更新优先**（权重最大）：宠物最后一次发公开成长记录的时间越近越靠前。**宠物今天更新了就该往前排，不管看的人之前有没有见过它**
2. **热度次之**：FR-256 的热度
3. **每日随机**：按「人 + 日期」固定的随机扰动，幅度小，作用是让更新时间、热度差不多的宠物每天换着出

默认效果：24 小时内更新过的宠物整体排在 3 天前更新的前面；同一天更新的，热度高的大概率靠前，但不绝对。三者权重后台可调（AB-59）。

**翻页一致性**：
- **一次连续翻页内**（从第一页往下翻），第一页到最后一页**不重复、不漏**
- 实现要求：现在的游标只记一个排序位置，不够用。新游标须**分别记四个来源各自取到哪**，并带上**第一页的时间点**；后面每页都按这个时间点算新鲜度和热度（热度带时间衰减，不定住时间点每次请求分数都会变，会导致重复或漏）
- 翻页过程中宠物新发了帖，**已经翻过的页不受影响**；重新打开（从第一页取）就按新的更新时间排
- **不同次打开之间、不同入口之间**（比如首页横滑行和全屏推荐页）可能见到同一只，接受；不记录谁看过谁（与「本文不含」里不做曝光记录一致）
- 隔天（雅加达时间 0 点后）打开，随机部分换新，顺序变化
- 游客：随机按日期固定（所有游客同一天一样），仍走 10 分钟快照

### 3.7 埋点（FR-258）

现有事件里「命中段」`match` 只有 `same_breed / same_species / global` 三个值（`onboarding_recommend_action` 等推荐相关事件）。改为按**来源**上报：

| 值 | 含义 |
|---|---|
| `same_breed` | 同类名额里的同品种 |
| `same_species` | 同类名额里的不同品种 |
| `other_species` | 其他类名额 |
| `new_pet` | 新宠名额 |
| `hot` | 热门名额 |
| `global` | 没宠物 / 游客时的全站名额 |

- 推荐接口每张卡带上来源，App 照传；所有用到推荐卡的位置（§2.1）的曝光、点击、追更、点赞事件都带这个字段
- 新增值要同步自建埋点的事件目录（event-catalog）

### 3.8 后台「算法参数」页新增「宠物推荐」配置卡（AB-59）

放在现有「算法参数」页，作为一张新配置卡；沿用该页现有的查看 / 编辑权限、保存方式和改动审计（不新增权限码）。

| 参数 | 默认 | 说明 |
|---|---|---|
| 每页同类张数 | 3 | 四项按每页 10 张填，合计须为 10；其他张数按比例折算 |
| 每页其他类张数 | 3 | |
| 每页新宠张数 | 2 | |
| 每页热门张数 | 2 | |
| 首日推荐页：同类 / 其他类 / 新宠 / 热门 | 2 / 2 / 0 / 2 | 按 6 张填，合计须为 6；没宠物时同类并入其他类 |
| 同物种连续上限 | 2 | ≥ 1 |
