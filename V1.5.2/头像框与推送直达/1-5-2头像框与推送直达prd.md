## 1. 版本目标

### 1.1 推送点开直达

现在点开推送，多数类型先落到通知中心，用户要在列表里再找到那一条点进去。推送本身就是为了把人拉到那条内容上，多一步就丢一批人。目标：**点开推送 = 看到内容**。

### 1.2 L 级里程碑催发布

满 1 岁、100 天、365 天是宠物最值得记录的三天。规划是「那天发一条 Diary 来点亮」，让里程碑和一条真实的记录绑在一起。现状偏了：过了那天随便发一条 Diary 都能点亮，第二年生日发帖也会点亮「第一个生日」，App 又写着「自动完成」；满 1 岁当天没有推送，前一天却推两条。目标：**在那天前后催用户发一条，发了就点亮、看到庆祝**。

### 1.3 购买专属头像框

1.4.0 的段位头像框只能靠升级拿，是代码画的圆环。专属头像框给愿意花钱的用户一个「好看、别人看得见」的东西，也是 PawCoin 的新去处。目标：**上线后验证有没有人买**，款式和价格在后台调。

**观察指标（上线后看，不做 A/B）：**
- 推送点开后 1 分钟内到达目标页的比例（直达前后对比，按推送类型）
- 满 1 岁 / 100 天 / 365 天在窗口内发 Diary 的宠物占比
- 专属头像框购买人数、复购（到期后再买）比例、PawCoin 与 QRIS 的占比

数据口径：埋点改报自家服务器后按新事件算；推送打开用现有 `push_opened`（dev_1.5.0 起有），不另写死依赖 PostHog。

## 2. 现状（2026-11-17 读 `origin/dev_1.5.0`）

### 2.1 推送点开去哪

- 推送 SDK 是腾讯 TIMPush，所有状态（前台 / 后台 / 冷启动）走同一个点击回调 `push_service.dart` `_onNotificationClicked`；推送附带 `{type, token, targetRef, commentId}`
- 落点规则 `pushClickLocation`（`push_service.dart:152-163`）：健康提醒 → 目标页；在直达名单 `kPushDirectTypes` 里的 → 目标页；评论被点赞 → 目标页；**其余带 token 的 → 通知中心**
- **已经直达的**（34 类）：升级、复购、优惠券到期、关注的人 / 追更的宠物发帖、陪伴纪念日、新手召回 D1/D3/D7、23 类健康提醒、评论被点赞、兽医问诊消息
- **还先进通知中心的**：帖子被点赞、被评论、被 @、帖子被下架、新粉丝（用户 / 宠物）、场所被评论、收到礼物、送礼退款、生日提醒、里程碑达成、流失召回、退款被拒、客服工单 / 满意度、账号警告 / 封禁、昵称 / 头像被重置、宠物名额到期、运营推送、商城订单类
- 这些类型在通知中心里点那一条，**大多已有去向**（`notification_center_page.dart` `_onTap`），直达要做的主要是把它们加进直达名单，并让推送和通知中心用同一套去向
- **商城已发货 / 订单异常 / 退货进度三类在通知中心点了没反应**：App 没给它们配去向
- 通知中心点开帖子类通知前会先查帖子是否已删除（删了给提示、不跳），直达路径没有这一步，靠详情页自己的「内容已不存在」页兜底
- 点推送会先把那条通知标为已读，再跳转；冷启动时先存下去向，开屏后再跳

### 2.2 L 级里程碑

| 里程碑 | 点亮条件（现在） | 相关推送（现在） |
|---|---|---|
| 满 1 岁「Ulang tahun pertama 🎂」（C/D/G-L1） | 生日那天（月 / 日相同）发 Diary 就点亮，**不检查是不是 1 岁**，第二年、第三年生日发帖也算；2 月 29 日没有兜底 | **前一天 11:00 推两条**：生日提醒「Besok {宠物} genap 1 tahun」（推送先进通知中心，在通知中心点开进发布页，但不带宠物）+ 第一个生日提醒（先进通知中心，点开进里程碑列表）；**当天没有推送** |
| 100 天「100 hari bersama」（L2） | 建档满 100 天**以后**任何一天发 Diary 都点亮 | 1.5.0 陪伴纪念日推送：当天 19:00「Hari ke-100 bareng {宠物}!」，点开进发布页（预选 Diary、带宠物）；同一主人当天多只宠物只推最早建档的那只 |
| 365 天「365 hari bersama」（L3） | 同上，满 365 天以后 | 同上，第 365 天 |

- 点亮时推「里程碑达成」推送（只有 L 级推，S / M 只进通知中心），文案固定「Tonggak / Ada tonggak baru untukmu」，**不带宠物名、不带里程碑名**，推送先进通知中心，点开进里程碑列表
- 里程碑列表的说明：100 天 / 365 天写「Otomatis selesai saat {宠物} sudah menemanimu selama 100 hari」（满 100 天自动完成），与实际（要发 Diary）不符；满 1 岁用通用提示「Kami ingatkan di harinya — unggah catatan Diary untuk menyalakannya」
- 点亮时没有记下是哪条帖子点亮的（`linkedContentId` 为空）
- 从里程碑列表点「去发布」会带上里程碑编号，发帖成功后 App 调「打卡」接口；但 L 级不是打卡类，接口会拒绝，App 静默吞掉 → **帖子发了、里程碑由后台点亮了，但不弹庆祝页**
- 推送去重表 `scheduled_push_marks`（每只宠物 × 推送类型 × 节点只推一次）；健康提醒遇到生日 / 第一个生日 / 纪念日会让路；没有按用户的每日推送总上限

### 2.3 头像框

- 只有一个字段 `growth_accounts.frame_choice`（不戴 / 基础 / 升级 / 动效 / 空 = 自动戴最高一档）；**没有「拥有哪些框」的记录**，能戴什么按段位算
- 切换接口 `PUT /api/v1/me/growth/frame`；别人的头像框随作者信息批量下发（`AuthorView.badgeFrame`）
- 画法：`growth_avatar_decoration.dart` 用代码画渐变圆环（基础 3dp、升级 / 动效 4dp，与头像间留 2dp 白缝，动效 8 秒一圈）；**没有等级角标就不画框**，框和角标绑在一起
- 等级页头像框一排 `frame_picker_row.dart`：写死 4 张卡（不戴 / 基础 / 升级 / 动效），点选即生效，未解锁置灰写「🔒 Lv{n}」；排不下更多的框
- **显示头像框的地方**：Feed 卡片、详情页、评论区（含回复）、场所评论、关注头像条、关注 / 粉丝列表、他人主页、「我的」页、等级页、升级庆祝、存量补发弹窗
- **不显示的地方**：单条分享页（后端下发了框但 App 没用）、场所「谁标记过」、送礼相关（礼物页、拆礼物、送出动画、选礼物面板、送礼记录）、迷你名片、@ 选人、收藏列表、拉黑列表、资料编辑、分享卡
- 付费可复用：通用付费抽屉 `PayChannelPicker` + `PayMethodCards`（PawCoin / QRIS，余额不足去充值）、QRIS 付款码轮询、`runKeepsakePurchase` 购买流程（宠物名额已复用）；付款单 `payment_intents` 加新用途要整列重建检查约束
- 限时类先例：宠物名额租用 `pet_slot_rentals`（到期时间、到期扫描、到期前提醒推送，归「Pesanan & akun」不可关）
- 后台没有头像框配置；价格类配置在 `pricing_config` 单行表 + 后台配置卡

## 3. 功能与需求

### 3.1 推送点开直达（FR-244）

**规则：** 推送点开后，**有目标页的一律直接进目标页**；没有目标页的进通知中心。点开时照旧先把这条通知标为已读。推送和通知中心里点同一条，去同一个地方（共用一套去向，不再两套）。

| 推送类型 | 直达到 |
|---|---|
| 帖子被点赞 | 帖子详情 |
| 帖子被评论 | 帖子详情，滚到评论区 |
| 被 @（帖子 / 评论里） | 帖子详情；在评论里 @ 的滚到那条评论 |
| 帖子被下架 | 帖子详情（显示现有的下架状态） |
| 新粉丝（用户关注你 / 关注你的宠物） | 对方主页 |
| 场所被评论 | 场所详情 |
| 收到礼物 | 收礼宠物的礼物页并打开最新一笔（多宠物时先切到这只宠物，同通知中心现有做法） |
| 送礼未送达退款 | 送礼记录 |
| 生日提醒 | 发布页，预选 Diary，**带上这只宠物**（现在不带） |
| 里程碑达成 | 这只宠物的里程碑列表 |
| 流失召回 | 按召回内容的去向（同通知中心现有映射） |
| 运营推送 | 运营配置的目标（同通知中心现有 `openOpsTarget`） |
| 退款被拒 | 我的退款 |
| 客服工单已处理 / 满意度 | 对应工单 / 满意度页 |
| 账号被警告 / 封禁 | 新建客服工单 |
| 昵称 / 头像被重置 | 「我的」/ 编辑资料 |
| 宠物名额即将到期 / 已到期 | 宠物名额页 |
| 商城订单类 | 见 FR-245 |
| 满 1 岁催发布（新增 `MILESTONE_PROMPT`） | 发布页，预选 Diary，带上这只宠物和里程碑（FR-247） |
| 专属头像框即将到期 | 等级页、滚到这张框并弹再买抽屉（FR-251） |
| 专属头像框已到期（只进通知中心，不推送） | 在通知中心点开进等级页 |

- **留在通知中心的**：举报处理结果、内容审核结果（通过 / 驳回 / 超时）——没有目标页
- **目标已经没了**（帖子删了、对方注销 / 拉黑、宠物删了）：照各页面现有的「内容已不存在」等兜底页显示，不另弹提示；宠物删了的礼物推送进送礼记录（同 1.5.2 回礼 PRD FR-234）
- 未登录 / 换了账号 / 强制更新：照现有处理（推送已随退出登录注销；强更时丢弃跳转）
- 埋点沿用 `push_opened`（`push_type`），新增属性 `landing`：`target` / `notification_center`，用来看直达比例

#### 验收标准

1. 上表每一类推送，App 在前台 / 后台 / 被杀掉三种状态下点开，都直接到对应页面，返回键回到点推送前的页面（冷启动回到首页）
2. 同一条通知从通知中心点进去，去的页面和点推送一样
3. 点开后这条通知在通知中心显示为已读
4. 帖子已删除时点「被点赞」推送，看到「内容已不存在」页，不闪退
5. 举报处理结果、审核结果推送点开进通知中心
6. 生日提醒点开进发布页时已选好这只宠物

### 3.2 商城订单类通知补去向（FR-245）

| 通知 | 去向 |
|---|---|
| 订单已发货 | 订单详情 |
| 订单异常 | 订单详情 |
| 退货进度更新 | 退货详情（没有单独退货详情页时进订单详情） |

推送点开和通知中心点开都按上表；订单号取通知现有的 `targetRef`（订单 / 退货 token）。

1. 三类通知在通知中心点开、点推送，都进对应订单 / 退货详情
2. 订单已不属于当前账号或 token 无效时，进「我的订单」列表，不报错

### 3.3 L 级里程碑点亮窗口（FR-246）

**规则（2026-11-17 定）：** 满 1 岁、100 天、365 天三个里程碑，**只在那一天的前 3 天到后 5 天内**（印尼西部时间，共 9 天）给这只宠物发 Diary 才点亮；窗口外发的不算。**错过窗口不是永久熄灭**：以后会加「补点亮」的方式（例如连续三天发帖，具体方式待定，见 OQ-4）；**本版只显示「已错过」，不提供补点亮**。

| 里程碑 | 「那一天」 | 窗口 |
|---|---|---|
| 满 1 岁 | 宠物满 1 岁的生日（生日 2 月 29 日的，平年按 2 月 28 日） | 生日前 3 天 ~ 生日后 5 天，**只认 1 岁那年** |
| 100 天 | 建档第 100 天（建档当天算第 1 天，照现有算法） | 第 97 天 ~ 第 105 天 |
| 365 天 | 建档第 365 天 | 第 362 天 ~ 第 370 天 |

- 「发 Diary」= 发布一条关联了这只宠物的 Diary（公开、私密都算），照现有点亮逻辑；**点亮时记下是哪条帖子**（写入 `linkedContentId`），里程碑页可以点进那条帖子
- 一条帖子关联多只宠物的，每只宠物各自判断窗口
- 帖子后来被删除：已点亮的不收回（照现有）
- **没有生日的宠物**：满 1 岁不点亮、不推送；补填生日后，若当前还在窗口内照常。里程碑列表点开满 1 岁时提示先填生日并给入口（FR-248）
- **建档时已超过 1 岁 / 已过第 105 天的**：对应里程碑显示「已错过」样式（见 FR-248），等补点亮方式定了再点亮
- **存量**：上线前已点亮的保留；上线时正处于窗口内的按新规则；上线前已过窗口、没点亮的，显示「已错过」
- 只读宠物（名额不足）照现有：不推送、不点亮

#### 验收标准

1. 建档第 97 天发 Diary 点亮 100 天；第 96 天、第 106 天发不点亮
2. 2 岁生日那天发 Diary，不点亮「第一个生日」
3. 生日 2 月 29 日的宠物，平年 2 月 25 日 ~ 3 月 5 日内发 Diary 点亮（以 2 月 28 日为「那一天」）
4. 点亮后里程碑详情能看到并点进那条 Diary

### 3.8 专属头像框到期（FR-251）

- **到期前 3 天**（约同一时刻）发一条推送：标题「Bingkai {框名} berakhir dalam 3 hari」/「Your {name} frame expires in 3 days」，正文「Beli lagi di halaman Level supaya tetap terpasang.」/「Buy it again on the Level page to keep it on.」；点开进等级页、滚到这张框，并**直接弹这款框的再买抽屉**（2026-11-19 定）

  - 只提醒用户**正在戴**的那个框；没戴的专属框到期不提醒（11-18 定）
  - 同一个框有好几份时，按**最晚那份**的到期日算「到期」：提醒、自动摘下都以它为准，中间某一份到期不提醒、不摘下

- 到期扫描照宠物名额租用的做法（定时任务）

#### 验收标准

1. 正戴着的专属框到期前 3 天收到推送，点开进等级页并弹出这款框的再买抽屉（旧、新两个到期日）

### 3.8b 等级页预览阶段权益（FR-259）

**为什么：** 等级页下方「Keuntungan level」（等级权益）已经列了每个阶段的权益文字，但只有文字，用户看不到升到下一阶段后头像框长什么样、能送哪些专属礼物，升级的动力不够直观。2026-11-20 定：加一个**只看不操作**的预览。

**入口：**
- 等级卡进度条右边的下一级胶囊（如「Lv8」）：点了预览**下一个阶段**（不是下一级——下一级多半还在同一阶段、没有新权益）。例：Lv7 属于 Sahabat，点「Lv8」看 Penjaga（Lv10–14）
- 「Keuntungan level」里**还没解锁的阶段卡**：点了预览**这一阶段**
- 提示能点：下一级胶囊里加一个小箭头 ›，未解锁阶段卡右边加一个小箭头 ›
- 已经在最高阶段（Bintang）：下一级胶囊没有箭头、点了没反应；已解锁的阶段卡不能点

**预览抽屉**（底部抽屉，样式同里程碑详情抽屉）：
- 自己的头像戴上这一阶段的段位框的大预览（头像 84 ＋ 这一阶段第一级的等级角标），Bintang 是动效框
- 阶段名与等级范围：「Penjaga · Lv10–14」（复用 `growthLevelTierRange` / `growthLevelTierRangeOpen`）
- 还差多少：「Kurang 1.880 EXP ke Lv10」（还差多少 EXP 到这一阶段的第一级，复用 `growthLevelToNext`）
- 权益清单：标题「Keuntungan level」（复用 `growthBenefitSectionTitle`），每项一行、前面一个阶段色小图标，文案复用现有各项权益文案；有专属礼物的阶段，在「Hadiah eksklusif」行下面露出这一阶段能送的专属礼物小图（礼物目录里最低等级落在这一阶段范围内的在线专属礼物，按最低等级、排序取前 3 个，多的写「+N」）
- 按钮「Oke, paham」/「Got it」（复用 `commonGotIt`），点了或下滑关闭
- **只是预览**：没有购买、去做任务等按钮；不改变任何状态
- **没有新增文案**

#### 验收标准

1. Lv7 用户点「Lv8」：弹 Penjaga（Lv10–14）预览，头像戴 Lanjutan 框，写「Kurang 1.880 EXP ke Lv10」，权益两项（+1 slot hewan、Bingkai avatar Lanjutan），没有礼物行
2. 点未解锁的 Bintang 卡：弹 Bintang 预览，头像戴动效框，权益三项，礼物行露出最多 3 个专属礼物小图，多的写「+N」
3. 点已解锁的阶段卡没反应；Bintang 用户点下一级胶囊没反应、胶囊没有箭头
4. 抽屉里没有任何购买或跳转按钮，点「Oke, paham」关闭

### 3.9 后台：专属头像框配置（AB-57）

后台「成长体系」页新增第 4 个页签「专属头像框」（2026-11-19 定：不放「运营配置」——那里的卡都是单个数值的表单，放不下款式列表、上传图片和上下架）。列表 + 编辑抽屉 + 下架确认照 1.5.0「礼物目录」的做法；权限跟成长体系页（查看 / 编辑）：
