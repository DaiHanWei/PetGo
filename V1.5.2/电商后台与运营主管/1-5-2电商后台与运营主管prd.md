# PRD：TailTopia 后台 V1.5.2——电商后台优化 + 运营主管角色进角色表

## 0. 文档说明

让运营管商品、管订单少做重复活：规格加上看得懂的「SKU 编码」，商品和订单都能按它找；包裹参数用表格一次填完；商品可以批量上下架、能导出；订单能看到是谁买的、能按账号和商品找、能导出；置顶商品有地方配。同时把「运营主管」搬进角色表，让超管能在角色页改它的权限；不再使用的预置岗位「发货专员」删掉。

## 2. 现状（2026-11-17 核实 `origin/dev_1.5.0` 与生产库）

**商品**
- 商品列表的搜索框只能按商品名搜
- 列表的列：商品名、品牌、品类、最低价、规格数、排序权重、上架状态、操作。电商优化分支会去掉排序权重列，并加上适用物种列和筛选（AB-44）
- 规格没有给人看的编码，只有一串 22 位的随机码，后台不显示
- 编辑页的规格表逐个规格编辑、逐个保存；**规格只能新建和编辑，不能删除**
- 包裹参数四项（重量 g、长 / 宽 / 高 cm）在规格表单里必填。缺参数的商品在列表上有「缺包裹参数」标记（1.4.2）
- 新建的商品默认是下架；**上架只有商品列表每行的「上架」按钮这一个入口**，编辑页没有上架开关
- 点「上架」时只检查在售规格总数是否超上限，而这个上限默认不开（配置为 0 = 不限），所以**现在上架实际上什么都不检查**：没有规格、缺包裹参数、没有主图都能上架。主图在编辑页也不是必填（折叠在可展开的区域里）
- 生产库现在没有不满足条件的商品（在售和下架的全部齐全），所以本文的校验是防以后
- 没有任何批量操作，没有导入导出。后台已有通用的表格导出工具（`AdminExportWriter`，可出 xlsx / csv，用户页的「导出手机号召回名单」就用它），也有用表格批量导入的先例（种子数据批量导入）
- 置顶：没有。电商优化分支给商品表加「置顶顺序」字段，但不做配置页

**订单**
- 有两个订单页：「订单履约」（`/admin/shop/orders`，发货用）和「订单」（`/admin/shop/order-list`，看全部，含已取消、退款中），点开都是同一个详情抽屉（「订单」页的抽屉不出发货操作）
- 两页都**不显示下单账号**，详情抽屉里只有收件人、电话、地址
- 两页都能按订单号（含旧订单号）搜，以及按状态、异常标记、下单日期筛选。按收件人电话搜**只有「订单履约」页有**，要单独的权限「按电话搜索订单」（`shop.order_phone_search`，电话是个人信息，默认只给客服）
- 没有导出。已有的「导出订单/收入」权限（`order.export`）管的是 AI 问诊和兽医咨询订单，不是商城订单

**运营主管**
- 预置岗位里，运营专员、发货专员、客服、财务四个在角色表里，超管能在角色页改它们的权限（只能改权限，不能改名、不能删）
- 运营主管和超管一样写死在代码里（当时的决策 D-13），角色页看不到，改权限要发版
- 运营主管现在有 45 项权限，近几个版本的新权限（补发宠物名额、补发免费次数、撤回经验值、调整用户经验值）都是在代码里直接预授的
- 生产库运营主管账号 0 个，搬家没有存量账号要迁
- 生产库「发货专员」账号 0 个（含已停用，2026-11-19 查），角色行和它的 5 项权限（看商品、看订单、发货、看库存、改库存）还在

**服务范围与运费**
- 「服务范围与运费」页（`/admin/shop/shipping`，在「电商」菜单下）管可配送区域与运费、免运门槛与最高减免、发货地址、退货收件地址、Biteship 余额与预警阈值
- 它没有自己的权限，和「运营配置」页（PawCoin 定价、KTP、宠物名额等）共用「查看配置」（`config.view`）、「编辑配置」（`config.edit`）。结果是：想让电商同事改运费，就得连 PawCoin 定价也给他改；想让人改 PawCoin 定价，他也能改运费
- 现在谁有这两个权限（2026-11-17 生产库）：运营专员、财务、自建角色「产品专员」三个角色有「查看配置」；自定义账号 3 个有「查看配置」、2 个有「编辑配置」（都在用）；运营主管两个都有；超管自动有

## 3. 功能与需求

### 3.1 SKU 编码与商品搜索（AB-46）

**SKU 编码**
- 每个规格新增一个「SKU 编码」字段，由运营填，**选填**
- 只允许字母、数字、「-」「_」，最长 32 位，前后空格自动去掉
- **全站唯一**，判重不区分大小写（`abc-1` 和 `ABC-1` 算重复），保存时按输入原样存
- 填写入口：规格表单（新建 / 编辑规格），以及表格批量录入（AB-50）
- 重复时表单报错「SKU 编码已被『{商品名} · {规格名}』使用」
- 编辑页的规格表加一列「SKU 编码」，没填的显示「—」
- 订单详情的商品行显示该规格**当前的** SKU 编码（订单不存快照，规格改了编码后，老订单显示新编码）

**商品列表搜索**
- 搜索框提示文字改为「商品名 / SKU 编码」
- 规则：商品名包含搜索词，**或**它的任一规格的 SKU 编码包含搜索词（都不区分大小写），满足一个就列出
- 和现有筛选（状态、品类，以及 AB-44 加的适用物种）同时生效
- 因 SKU 编码命中时，商品名下面多一行「SKU 编码：{编码}」，命中部分高亮；同一商品多个规格命中就都列出，用「、」隔开。只因商品名命中时不显示这一行

#### 验收标准
1. 给规格填「RC-K-2KG」，在列表搜「rc-k」能搜到这个商品
2. 另一个规格填「rc-k-2kg」保存，报重复，并指出被哪个商品的哪个规格占用
3. 同一商品两个规格分别是「RC-K-1KG」「RC-K-2KG」，搜「rc-k」列出这个商品，商品名下面显示「SKU 编码：RC-K-1KG、RC-K-2KG」，两处「RC-K」都高亮；搜商品名时不显示这一行
3. 填「RC K」（含空格）保存时报格式错误
4. 不填 SKU 编码也能保存规格

### 3.2 置顶商品配置（AB-47）

App 上置顶商品怎么排、怎么轮换，以 [电商优化 PRD](../电商优化/1-5-2电商优化prd.md) FR-226「置顶」为准。本节只管后台怎么配。App 侧要点（后台页面须让运营看懂）：
- 置顶商品排在 Toko 首页最前面，不参与「没看过 / 看过」轮换
- **置顶之间每轮换一次顺序（循环挪位，不是随机）**：按运营添加置顶的先后循环，每开始新一轮（进 Toko 或下拉刷新），上一轮第一位移到最后，6 个置顶 6 轮转一圈，每个都轮得到第一位；每个用户各自记轮到哪；游客不轮换，始终按添加先后
- 运营添加或取消置顶后，所有用户从头开始轮
- 置顶商品售罄时，App 不把它放在最前，而是排进末尾的售罄档
- 置顶商品不出现在 Toko 首页的「为宠物推荐」里（避免同一屏重复）

**后台配置**
- 商品列表上方加「置顶商品」区块，按添加先后横排展示置顶商品（主图、商品名、有没有货），**不显示序号、不能拖动排序**（2026-11-18 拍板：App 每轮都换顺序，后台排出的固定顺序没有意义，还会让运营误以为排第一的一直在最前），右上角显示「{n} / 6」
- 区块标题下一行灰字说明：「App 上这几个商品每次进入 Toko 或刷新轮流排第一；售罄的不排在最前」
- 「有没有货」与 App 售罄判断一致（FR-226 / FR-229）：没有一个规格「可售数大于 0 且包裹参数齐全」就算售罄
- 每个置顶商品有「取消置顶」按钮，点了直接移出，不弹确认
- 商品列表每行的操作里加「置顶」按钮，已置顶的行显示「取消置顶」。新置顶的排在最后
- **最多 6 个**：满 6 个时其他行的「置顶」按钮置灰，悬停提示「置顶最多 6 个，先取消一个」
- **只有上架的商品能置顶**；下架的行不显示「置顶」按钮
- **商品下架（单个或批量）时自动移出置顶**，后面的往前补位
- 售罄的置顶商品留在置顶里、照样占名额，区块里标「售罄」，悬停提示「售罄期间 App 不在最前展示」；补货后下一轮自动回到最前
- 没有置顶商品时区块显示一行灰字「还没有置顶商品，在下方列表点『置顶』添加」
- 权限：看区块要「查看商品与库存」（`shop.product_view`），置顶、取消置顶要「编辑商品与 SKU」（`shop.product_edit`）
- 置顶、取消置顶都记审计日志（记录改前和改后的置顶商品）
- 置顶、取消置顶后，App 上每个用户的置顶轮换从头开始（FR-226，由电商优化分支实现；本分支只写「置顶顺序」字段，见 §6）

#### 验收标准
1. 依次置顶 A、B、C，后台区块按 A、B、C 排，不能拖动；App 上连续三轮排第一的依次是 A、B、C
2. 已有 6 个置顶时，其他行的「置顶」按钮不能点
3. 置顶 A、B、C 时下架 B，置顶区只剩 A、C
4. 已有 5 个置顶时两个人同时点「置顶」，只有一个成功，另一个提示「置顶最多 6 个，先取消一个」

### 3.3 上架前必填校验（AB-48）

**所有让商品变成「上架」的入口都要检查**：列表每行的「上架」按钮、批量上架（AB-49）。编辑页没有上架开关，不涉及；以后加了上架入口也要走同一个检查。

检查三件事，有一件不满足就不让上架（现有的在售规格总数上限检查保留，默认不开）：

| 检查 | 不满足时的提示 |
|---|---|
| 至少有一个规格 | 「还没有规格」 |
| 每个规格的包裹参数四项都填了 | 「{n} 个规格缺包裹参数」 |
| 有主图 | 「缺主图」 |

- 单个上架被拦时，在列表顶部显示红条：「没有上架『{商品名}』：还没有规格；缺主图」（缺几项列几项）
- 规格不能删除、包裹参数在规格表单里必填且表格导入留空不清空（AB-50），所以商品上架后不会再变成「没规格」或「缺包裹参数」；只有主图可能被清掉，本版不另拦
- 已上架的商品不回头检查（生产库现在都满足条件）

#### 验收标准
1. 新建一个只有主图、没有规格的商品，点「上架」，被拦下并提示「还没有规格」
2. 某下架商品有一个规格缺包裹重量（表单和导入都填不出这种数据，测试时直接改数据库），点「上架」，提示「1 个规格缺包裹参数」
3. 有规格、包裹参数齐，但主图为空的商品，点「上架」，提示「缺主图」
4. 条件都满足时上架成功

### 3.4 批量上架 / 下架（AB-49）

- 商品列表每行最前面加勾选框，表头勾选框选中**当前页**全部。不支持跨页选
- 选中后列表上方（摘要条和表格之间）出现操作条：「已选 {n} 个：批量上架　批量下架　取消选择」
- 操作条往下滚时固定在窗口顶部（`position: sticky; top: 0`），勾到页底也不用滚回去；沿用工单页现有的批量操作条 `.batch-bar`，不新写组件
- **批量上架**：不弹确认，逐个按 AB-48 检查。能上架的上架，不能上架的跳过。完成后显示结果条：
  - 全部成功：绿条「已上架 {n} 个商品」
  - 有跳过：黄条「已上架 {n} 个；{m} 个没有上架」，点「查看原因」展开逐个列出商品名和原因
- **批量下架**：先弹确认「下架 {n} 个商品？下架后它们立刻从 App 的所有列表与推荐中消失；已下单未支付的订单照常履约。」。选中的商品里有置顶商品时，确认框加一行「其中 {k} 个是置顶商品，下架后会移出置顶」
- 已经是目标状态的商品（对上架的再点上架）直接算成功，不报错
- 权限：「编辑商品与 SKU」（`shop.product_edit`），没有这个权限时不显示勾选框
- 每个商品各记一条审计日志，同一次批量操作带同一个批次号

#### 验收标准
1. 勾 5 个下架商品，其中 2 个缺主图，批量上架后 3 个上架，结果条列出 2 个的原因
2. 勾 3 个在售商品（含 1 个置顶）批量下架，确认框提示置顶；确认后 3 个下架，置顶区少 1 个
3. 只有「查看商品与库存」、没有「编辑商品与 SKU」的账号看不到勾选框

### 3.5 包裹参数与 SKU 编码批量录入（AB-50）

**流程：下载模板 → 在表格里填 → 上传 → 预览 → 确认导入。**

**下载模板**
- 商品列表上方加「批量填包裹参数」按钮，点开后可以选：
  - 「只下载缺包裹参数的规格」（默认）
  - 「下载当前筛选结果的全部规格」
- 模板是 xlsx，每行一个规格，列如下：

| 列 | 能不能改 |
|---|---|
| 规格 ID | 不能改，导入时按它找规格 |
| 商品名、规格名、商品状态 | 不能改，只给人看，导入时忽略 |
| SKU 编码 | 可填可改 |
| 包裹重量（g）、长（cm）、宽（cm）、高（cm） | 可填可改 |

**导入规则**
- 只更新上表「可填可改」的五列，其他列改了也不生效
- **单元格留空 = 不改这一项**（不会把已有的值清空）
- 数值规则与规格表单一致：正整数，范围沿用表单现有校验
- SKU 编码规则同 AB-46，表内互相重复、和库里其他规格重复都算错
- 规格 ID 找不到（已删除或填错）的行算错
- 最多 2,000 行，文件不超过 5 MB；只收 xlsx

**预览与确认**
- 上传后先预览，不直接写库。预览显示：会更新 {n} 个规格、没有变化 {m} 行、出错 {k} 行
- **有任何一行出错就不能导入**，预览逐行列出错误（第几行、哪一列、原因），改好重新上传
- 没有错时点「确认导入」，一次性写入（全部成功或全部不写）
- 导入完成显示「已更新 {n} 个规格」
- 权限：「编辑商品与 SKU」（`shop.product_edit`）。下载模板不需要导出权限（模板里没有价格、库存）
- 每次导入记一条审计日志：导入人、文件名、更新的规格数；每个被改的规格记改前和改后的值

#### 验收标准
1. 下载「缺包裹参数」模板，填满后导入，列表上的「缺包裹参数」标记消失
2. 模板里某行重量留空、长度改成 30，导入后重量不变、长度变 30
3. 有一行重量填「-5」，预览报第几行重量不合法，不能确认导入
4. 两行填同一个 SKU 编码，预览报重复
5. 改了「商品名」列，导入后商品名不变

## 6. 开发注意与接口约定

- **建议分支**：`feat/1.5.2-shop-admin`，AB-46 ~ AB-56 在一个分支
- **基线**：`dev_1.5.0`
- **合并顺序：电商优化分支（`feat/1.5.2-shop-optimization`）先合，本分支后合。** 原因：
  - 置顶配置页读写电商优化分支加的「置顶顺序」字段（商品表，空 = 未置顶，1 ~ 6 = 添加先后，新置顶的排最后，取消或下架后后面的往前补位、保持连续）。本分支不建这个字段
  - 「添加或取消置顶后所有用户从头开始轮」由电商优化分支负责识别（例如比较置顶列表有没有变化），本分支只要保证每次添加或取消都把置顶顺序整体写成连续的 1 ~ n，不另加字段；如电商优化分支需要一个「置顶最后修改时间」之类的标记，由它建、本分支在保存时一并写
  - 后台「有没有货」与 App 用同一个售罄判断（电商优化分支给商品列表加的「是否售罄」），不另写一套
  - 商品导出的「适用物种」读电商优化分支加的多选字段（FR-232）
  - 两个分支都改商品列表页模板（电商优化：去掉权重列、默认按创建时间排、加适用物种列和筛选；本分支：勾选框、置顶区块、搜索、导出、批量结果提示）；编辑页两边也都改（电商优化：适用物种多选、去掉权重、补保存提示条；本分支：规格表加 SKU 编码列、规格表单加 SKU 编码）。本分支在其之上改，避免冲突
  - 如果电商优化分支延期：除置顶配置页外，本文其他功能都能单独上；导出的适用物种列先读旧的单选字段
- **本分支负责的数据变更**：
  - 规格表新增「SKU 编码」字段，可空；建不区分大小写的唯一索引（只对非空值）
  - 角色表插入「运营主管」预置行，写入 49 项权限，回填运营主管账号的角色 ID
  - 删除「发货专员」：先检查没有账号的角色是 `FULFILLMENT`（有就报错停下），再删角色表这一行和它的权限；账号表角色字段的 CHECK 约束重列全集，去掉 `FULFILLMENT`
