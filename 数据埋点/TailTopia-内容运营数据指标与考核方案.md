# TailTopia 内容运营数据指标与考核方案

**依据文档**：《TailTopia-内容运营工作方案(本地资深运营+设计师)_1.md》+ V1.0.0/V1.1.0 产品 PRD + petgo-platform 实际代码/数据库核查
**目的**：把工作方案 §五「数据验收指标」里偏定性的描述，落成"算法怎么算、数据从哪来、能不能自动化、评的是内容效果还是运营员本人"这几件事讲清楚的可执行文档。

**核心原则（决定了整份文档的结构）**：内容效果（帖子火不火）和运营员绩效（这个人干得好不好）是两件事，不能混为一谈——内容效果受大盘流量、话题本身热度影响，运营员再优秀也未必能让每条内容都爆；但"选品是否及时、回复是否达标、授权是否合规、响应是否及时"这些是运营员**可控行为**，才是绩效考核该重点看的。下文按这个原则拆成「结果类」和「过程类」两条线。

**标注说明（贯穿全文）：**
- ✅ = 现有数据可直接查询计算，今天就能跑
- 📋 = 建议用轻量表格（Excel/飞书多维表格）人工登记，不用等产品开发，先跑起来
- ❌ = 数据地基缺失或依赖的产品能力不存在，需要产品/工程先补上才能算

---

## 0. 先看这里：这份运营方案里有 2 处和产品现状对不上的地方

在设计具体算法之前，必须先说清楚——工作方案里的导流机制，有依赖的产品能力**现在不存在**，如果不先跟产品对齐，对应考核指标会从第一天就算不出来。（原方案 §5.1 积分公式里的"收藏(Save)"一项，经确认 V1.0.0/V1.1.0 均未规划收藏功能，本文档不再讨论，直接按"点赞×1 + 评论×5"两项计算，不作为待确认事项。）

1. **单条内容不能被外部分享。** `V1-0-0PRD.md` §5 明确不做列表最后一条："V1.0.0 不做单条内容的外部分享（仅宠物名片 H5 可外部分享，FR-14）"。这意味着"精选内容"本身没有办法像宠物名片那样生成分享链接去追踪外部传播效果，精选内容的传播目前只能靠站内热度（点赞/评论）体现。
2. **❌「暗号/兑换码」机制不存在，需要产品先设计。** 工作方案 §3.3 提到"群专属福利：定期发暗号，App 内输入领 PawCoin"，用来打通"群→App打开率"这个指标。但检索 V1.0.0/V1.1.0 全部 PRD，没有任何"兑换码/暗号输入"相关的 FR，PawCoin 体系（FR-50 系列）目前只定义了"充值购买"和"消费场景"，没有"输入一个码换奖励"这个动作。**这是运营方案隐含提出的一个新产品需求，需要产品先设计并排期，在此之前"群→App打开率"这个指标无法计算，不是"暂时没埋点"的问题，是功能本身不存在。**

以上第 2 点建议先和产品对一轮；本文档后面的算法会用上面的 ✅/📋/❌ 标注区分"现成可算"「人工登记先顶上」「待产品补功能才能算」三种情况。

## 1. 精选内容运营（TT精选账号）

### 1.1 结果类指标（内容效果——反映"选得准不准"，运营员和产品共同影响）

| 指标 | 算法 | 数据来源/现状 | 用于判断什么 |
|---|---|---|---|
| 单条内容互动分 | `点赞数×1 + 评论数×5` | ✅ `content_likes`/`comments` 表现成，可直接查 | 单条被精选内容的实际效果 |
| 结构化栏目周均得分排序 | 按栏目（身份证展览/新崽报到/里程碑放榜/每周精选合集/崽言崽语）分组，`AVG(单条内容互动分)`，本周 vs 近 4 周 | 📋 **数据地基缺失，用人工表格顶上**——产品目前没有"这条内容被哪个栏目选中、什么时候发布"这个记录能力，20 个 admin 模板里没有内容精选相关的表/页面，靠下面的"运营精选记录表"手工登记即可算 | 判断"每周精选合集"这类兜底栏目该不该砍（方案里明确提到的判断依据） |
| 被精选用户次周活跃率 vs 对照组 | `(被精选用户精选后7天内活跃比例) - (未被精选同期同类用户活跃比例)` | 📋 同上缺"精选记录"，需人工登记；活跃定义本身也受此前《数据v1.0.0-v1.1.0》文档提到的"4 大 Tab 无埋点"缺口影响，活跃口径目前不够精确（这一层不是人工登记能解决的，仍需产品补埋点） | 验证"被看见"是否真的能拉动留存，是精选栏目存在意义的核心假设 |
| Feed 空状态出现率 | `观察窗口内空状态展示次数 / 总访问次数` | ❌ 前端展示空状态是纯 UI 态（FR-18），没有对应埋点上报，无法人工登记（用户单机行为，运营看不到），需产品补 `feed_empty_state_shown` 埋点 | 判断种子内容/精选内容储备是否够用，目标≈0 |

**📋 建议新增的最小数据地基（人工登记，不用等开发）**：一张"运营精选记录表"（哪条内容 / 哪个栏目 / 谁选的 / 什么时候发布 / 私信授权状态），用 Excel/飞书多维表格手工登记——没有这张表，上面 3 个指标里有 2 个永远算不出来，这个优先级比等产品开发端到端埋点更高，运营团队自己就能立刻开始记，不依赖任何技术排期。

### 1.2 过程类指标（运营员本人执行质量——这是"评价这个人干得好不好"的主体）

| 指标 | 算法 | 数据来源/现状 | 备注 |
|---|---|---|---|
| 每日回复达标率 | `count(comments WHERE author_id = TT精选账号 AND created_at::date = 当天) >= 50` | ✅ `comments` 表现成，只要 TT精选是固定账号 ID 就能直接查，**这条不需要新开发，今天就能拿真实数据** | 数量达标是硬指标 |
| 回复质量分 | 数量之外，按周随机抽 10-15 条运营回复，人工评分（1-5 分，是否含具体细节/是否模板化） | 📋 无法靠算法判断文本是否"走心"，必须人工抽查，建议记录在同一张周度考核表格里 | 和数量指标一起构成完整的"回复质量"评价，避免只堆数量水评论 |
| 授权执行率 | `实际发送私信告知的条数 / 应授权条数`，目标 100% | 📋 私信授权是站外流程（IG/WA 私信），产品数据完全覆盖不到，**建议运营自行登记一张轻量表格**（时间戳+对方回复状态），管理者按周抽查，不必强求产品做自动化追踪 | 可以并入"运营精选记录表"，同一条记录多加两列（授权时间/回复状态）即可，不用另开一张表 |
| 话题发布及时率 | `content_posts.created_at` 是否落在周二/周四 19:00-21:00 窗口 | ✅ `content_posts` 表现成可查 | 直接反映执行纪律 |
| 话题跟进达标率 | `count(comments WHERE post_id=该话题贴 AND author_id=运营账号) >= 2`（至少破冰 1 条 + 跟进 1 条） | ✅ `comments` 表现成，可直接查是否做到"发完不晾着" | 对应方案里"发帖只是开始不是结束"这条要求 |
| 官方账号语气一致性 | 内部抽查，对照《声音指南》打分 | 纯人工审计 | 人设边界（不代表客服）是否守住 |

### 1.3 周五"十大精选宠物"榜单

- 算法沿用 1.1 的"单条内容互动分"公式做客观排序，取 Top10——这是对一周工作的**汇总展示**，不是新的筛选动作，不需要额外指标。

|---|---|---|

## 3. 官方宠物群运营

**关键现实**：WhatsApp Community 的群成员数、群内活跃、退群这些数据**都在 WhatsApp 侧，不在 TailTopia 后端**，产品这边唯一能打通的只有"从群导流到 App 之后的行为"。

| 指标 | 算法 | 数据来源/现状 |
|---|---|---|
| 群成员数增长 / 群内周活跃人数占比 / 退群率 | 需接 WhatsApp Business API 拉取，或管理员每周手动登记 | 📋 产品侧完全没有，**建议管理员每周手动登记到轻量表格**，不必等技术对接 API |
| 群→App 打开率 | `count(distinct 使用过暗号的user_id 在使用后24/48小时内有App活跃) / count(distinct 使用过暗号的user_id)` | ❌ **前提是"暗号兑换"功能存在**（见 §0.2），目前产品没有这个功能，指标算不了，不是缺埋点、是功能本身不存在，需先立项 |
| 群内急症求助响应时效 | 纯人工登记"求助时间→管理员响应时间"的差值 | 📋 WhatsApp 群内消息不进 TailTopia 后端，无法自动化，**建议无论如何先靠人工登记兜底**，且这条是方案里明确标注"不可省"的安全底线，不要等技术方案 |

## 4. 运营员绩效评价框架（回答"怎么评价这个人工作结果好坏"）

内容效果会受大盘流量、季节性话题热度影响，同一个人在不同月份可能有完全不同的结果分，所以**绩效权重应该向过程类指标倾斜**，结果类作为参考而非主要打分依据：

| 维度 | 建议权重 | 包含指标 |
|---|---|---|
| 过程执行（可控） | 60% | 每日回复达标率、回复质量分、授权执行率、话题发布及时率、话题跟进达标率、群响应时效、语气一致性 |
| 结果效果（参考） | 40% | 内容互动分周环比、话题单期评论数趋势、群→App打开率（功能上线后再纳入） |

**评价节奏建议**：按方案原文"400 DAU 量级下单周数据波动较大"的提醒，结果类指标看**连续 2-3 周趋势**，不要用单周数据下结论；过程类指标可以按周甚至按日检查（比如每日回复数达标与否是当天就能确认的硬指标）。

## 5. 老板监控视角：结果数据、管理数据都要看，但触发介入的门槛不一样

作为管理者，两条线都要盯，但作用不同：**结果数据**（§1.1/§2/§3 里的互动分、话题热度、群活跃）告诉你"产出好不好"；**管理/过程数据**（§1.2 的回复数、授权率、发布纪律）告诉你"这个人有没有认真、合规地在做事"。两条线不能互相替代——结果好不代表可以不看过程（可能是蒙对一次爆款内容，执行本身在划水）；过程都达标也不代表可以不看结果（可能是选题方向本身就有问题）。下面按"现在要不要出手"分层，出手时机不对，要么错怪了认真做事的人，要么放过了真正的问题。

### 5.0 先说大实话：现在没有一个仪表盘给你看，几乎所有数字都得靠人报

产品后台（admin）目前**一个聚合看板都没有**，全是列表页（详见《数据v1.0.0-v1.1.0》§0.2）。这意味着不管下面哪个指标，你今天都打不开一个页面直接看数字——**现状是靠运营每周整理成周报交给你，或者你让产品/工程专门为你跑一次查询**，不是"数据存在但你不知道去哪看"，是"真的没人做这个呈现层"。下表把每项数据的**现在找谁要**和**长期该怎么解决**分开写清楚。

| 你要看的数据 | 现在从哪拿/找谁要 | 现状 | 长期方案 |
|---|---|---|---|
| 每日回复数（≥50条） | 运营自己每周汇报这个数字（`comments` 表数据本身✅现成，但没人做成报表） | 数据存在，缺呈现，建议先让运营周报里带一句"本周日均回复数 X 条" | 产品/工程做一个简单查询页面，见《埋点数据v1》P1 |
| 回复质量分（是否模板化水评论） | 你自己或指定一人，每周随机抽 10-15 条运营回复看内容 | 纯人工，永远需要人工，不存在自动化方案 | 无（本来就该人工） |
| 授权执行率 | 运营自己维护的"运营精选记录表"（Excel/飞书多维表格，见 §1.1），你按周抽查这张表 | 📋 靠运营自觉登记，**这张表现在存不存在，你应该先问运营要**，不存在就现在建 | 无需产品开发，运营自建即可 |
| 结构化栏目周均得分排序 | 同上"运营精选记录表" + `content_likes`/`comments` 数据，需要有人（产品或运营）做一次简单汇总 | 📋 数据地基缺失，见 §1.1，需要先有"哪条内容归哪个栏目"这张记录表才能算 | 见《埋点数据v1》P0 |
| 被精选用户次周活跃率 vs 对照组 | 目前**任何人都拿不到**——产品数据缺口 | ❌ 短期内你看不到这个数字，不要指望，也不要因为看不到就怪运营 | 见《埋点数据v1》，依赖活跃口径修复（Tab 埋点缺口） |
| Feed 空状态出现率 | 目前任何人都拿不到 | ❌ 需要产品新增埋点 | 见《埋点数据v1》P1，`feed_empty_state_shown` |
| 单期评论数（话题） | `content_posts`/`comments` 表现成，找运营周报要这个数字，或让产品/工程跑一次查询 | ✅ 数据现成，缺呈现 | 同上，建个简单报表 |
| 话题发布及时率/跟进达标率 | 同上，运营周报自查 + 你抽查 | ✅ 数据现成 | 同上 |
| 官方账号语气一致性 | 你或指定人抽查账号历史发言 | 纯人工 | 无 |
| 群成员数/群内周活跃占比/退群率 | **运营每周手动统计后直接口头/文字汇报给你**——这三项完全在 WhatsApp 里，不在 TailTopia 任何系统里 | 📋 纯人工流程，产品这边帮不上忙 | 除非接 WhatsApp Business API，否则永远是人工报数（见《埋点数据v1》P2，不紧急） |
| 群→App 打开率 | 目前任何人都拿不到——依赖的"暗号兑换码"功能不存在 | ❌ 不是数据问题，是这个功能产品还没做 | 见《埋点数据v1》，需先立项开发 |
| 群内急症求助响应时效 | 运营手动记录 WhatsApp 群里的时间戳，按周/按事件汇报给你 | 📋 纯人工，且是安全红线项，建议**要求运营出现一次就当场口头汇报，不要等周报** | 无法自动化，WhatsApp 消息不进产品后端 |

**给你一句可以直接执行的话**：这个月开始，**让运营每周一份固定格式的周报**，里面包含上表里标 ✅/📋 的所有数字（她自己报，你偶尔抽查真实性）；标 ❌ 的几项现在没人能给你，别在这个月的考核里追问它们，去找产品把《埋点数据v1.md》里对应的缺口排上期。

### 5.1 🟢 不用介入——哪怕结果数据不好看

| 信号 | 为什么不用管 |
|---|---|
| 内容效果积分单周下滑，但 §1.2 过程指标全部达标 | 大概率是内容/选题或大盘流量的问题，不是执行问题；按 §4 的节奏看连续 2-3 周趋势，单周别下结论 |
| 结构化栏目得分垫底，但还没到 §1.1 自定的"连续 3-4 周"判断窗口 | 窗口没到，不该提前砍栏目或找人算账 |
| 群成员数/导流规模不及预期，且还在第一个月 | §3 方案原文承认"第一个月只看导流效果，暂不设硬指标"，这是冷启动缓冲期 |
| §3 群→App 打开率、退群率暂时看不到数据 | 这两项依赖的"暗号兑换码"功能本身不存在（见 §0.2），是产品能力没跟上，**不要把"看不到数据"误判成"运营没做事"** |

### 5.2 🟡 该观察，先别出手

| 信号 | 该做什么 |
|---|---|
| 内容效果积分连续下滑，过程指标也全部达标 | 找运营一起复盘选题方向，是业务讨论不是问责 |
| 结构化栏目垫底刚好撞上 3-4 周窗口 | 按方案原定流程，和运营一起决定去留，属于正常运营节奏，不是"介入" |
| 三大板块工时持续顶着方案标注的 13.5-18 小时/周上限 | 先观察是不是常态化超时；如果是，该由你主动砍优先级或加人，不是等对方喊累 |

### 5.3 🔴 必须介入——但要先分清楚该管"人"还是该管"安排"

**执行问题，找运营本人谈：**

| 信号 | 对应本文档指标 |
|---|---|
| 每日回复数持续低于 50 条 | §1.2「每日回复达标率」——先确认是"当天真挑不出 50 条"还是纯粹没干够量，两种处理方式不同 |
| 回复质量抽查发现大量模板化水评论 | §1.2「回复质量分」——**这是最容易被"数量达标"掩盖的问题**，数量够但都是"好可爱"这种没信息量的话，说明在应付指标，必须靠人工抽查才能发现，光看后台数字会被骗 |
| 授权执行率跌破 100% | §1.2「授权执行率」——尤其里程碑放榜这类必须等对方明确回复的严格授权，一旦跳过，是合规风险，发现即处理，不等趋势 |
| 话题该发不发/发了不跟进 | §1.2「话题发布及时率/跟进达标率」——明确的执行纪律问题 |
| 官方账号人设边界被打破 | §1.2「官方账号语气一致性」——品牌一致性问题，发现即纠正 |

**安全红线，是事故处理，不是"管理介入"：**

| 信号 | 说明 |
|---|---|

## 6. 数据缺口汇总清单（给产品/工程排期用）

| 优先级 | 缺口 | 影响的指标 | 类型 |
|---|---|---|---|
| P0（📋 先用轻量表格顶上，今天就能开始，不必等开发） | 运营精选记录表（内容/栏目/时间/授权状态） | 结构化栏目排序、被精选用户活跃率对比、授权执行率 | 人工登记 |
| P0（📋 同上） | 群成员数/活跃/退群人工登记 | 官方群三项指标 | 人工登记 |
| P1（❌ 需要产品补埋点） | Feed 空状态展示埋点（`feed_empty_state_shown`） | Feed 空状态出现率 | 用户单机行为，人工看不到，必须补埋点 |

**一句话总结**：这份方案里能立刻用真实数据跑起来的，是「每日回复数」「话题发布及时率/跟进」「单期评论数」这几个直接查 `comments`/`content_posts` 表就有的过程类指标——建议先把绩效考核锚定在这几个可控指标上；内容效果类指标（排行榜、活跃率对比）和群运营三项指标，靠一张"运营精选记录表"+"群数据登记表"人工顶上就能跑，不用等开发；真正卡住的只有两处产品缺口——Feed 空状态埋点（需要补一个埋点事件）和暗号/兑换码机制（需要产品先立项设计），这两处在第一个月的考核里不要对运营员提出过高预期。
