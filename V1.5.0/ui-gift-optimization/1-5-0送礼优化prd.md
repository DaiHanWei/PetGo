## 1. 版本目标

送礼从「点一下扣钱、弹个 toast」变成一次有仪式感的送礼：送礼人能写祝福语、看到礼物送达；主人收到的是一份要拆开的礼物，而不是一个累计数字。

- 去掉粉丝榜和礼物总价值：不鼓励比拼金额（11-02 拍板）
- 不改价格、EXP 规则、支付渠道和退回规则

## 2. 现状（2026-11-10 核 `origin/dev_1.4.2`）

| 项 | 现状 |
|---|---|
| 送礼接口 | `POST /api/v1/pets/{petId}/gifts`（`GiftSendRequest`：giftToken / quantity 1~99 / channel PAWCOIN·QRIS / requestId / source / postId），**没有祝福语字段** |
| 订单 | `gift_orders`（`GiftOrder`），没有「主人是否已拆」 |
| 礼物展示 | `GET /api/v1/pets/{petId}/gifts` 按**礼物种类汇总**（礼物墙 + 总价值 totalValue + 礼物个数 giftCount + 送礼人数）；`/gifts/supporters` 是粉丝榜分页 |
| EXP | 送达时由 `GiftSentEvent` 入账：送礼人 `GIFT_SENT` 每 Rp1,000 = 5，主人 `GIFT_RECEIVED` 每 Rp1,000 = 4 |
| 收礼通知 | `PET_GIFT_RECEIVED`，点开进礼物页 |
| 送出反馈 | 1–2 秒小动效 + toast（`gift_send_animation.dart`） |

## 3. 功能与需求

### 3.1 选礼物目录（FR-187，泳道 B）

- 价格单位显示「{n} PawCoin」，礼物格显示送礼人自己能得的「+{n} EXP」
- 「收到过的礼物」区（B3）显示是谁送的：「dari {名字}」；超过 3 人显示最近 3 人 +「+N」
- 照线上保留：专属礼物与等级锁区块、按物种排序、数量 ×99 上限、加载失败（B5）

### 3.2 包装页与祝福语（FR-188，泳道 C）

- 选完礼物进包装页（C1），标题「给{宠物名}包一份礼物」
- **礼盒：** 设计稿的「选礼盒」本版去掉，用默认礼盒，总价 = 礼物单价 × 数量（11-02，后续迭代）
- **EXP 提示：** 只写送礼人自己的（如 5,000 档 +25），不写「双方都得」
- **祝福语：** 选填，上限 500 字符，计数常驻，到上限不能再输入
  - 点「Kirim」时先做**敏感词拦截**：命中则不扣款、输入框变红、下方提示（C3）。复用内容审核的敏感词库
  - **不做人工复审**；发出后的问题靠举报（FR-191）
- **支付区：** 默认 PawCoin；QRIS 最低 Rp10,000 按线上（C5，门槛读后台配置）；余额不足时主按钮置灰并自动展开（C6）
- **换付款方式的引导（2026-11-10）：** 收起状态在主按钮提示下方常驻一行「Metode bayar lain ⌃」（其他付款方式），点这一行或上拉横条都能展开，露出「充值 PawCoin」「用 QRIS 付」两张卡；展开后这一行移到两张卡上方、箭头朝下，再点收起。扣款中（C7）这一行置灰
- 扣款中、扣款失败（C7 / C8）照线上

### 3.3 送出仪式（FR-189，泳道 E）

- 付款成功后全屏三段：装盒（E1）→ 飞向宠物（E2）→ 送达（E3「你的礼物已经送到{宠物名}那里了」+ 送礼人得到的 EXP），替代线上的小动效 + toast
- 底色用方向 A：紫色渐变 `#9E55D8 → #7A3FC4`，白字对比度 ≥ 4.5:1（11-09）
- 可以跳过（「Lewati」），跳过直接到送达
- QRIS 付款照线上流程（二维码、过期、失败不改），付款成功后同样进 E1

### 3.4 主人拆礼物（FR-190，泳道 F / G）

- **礼物页改为按订单逐笔列出**（不再按礼物种类汇总）。主人视角有「未拆」状态，按**笔**记，不按个数；可筛选「Belum dibuka」（未拆，F4）
- Diary 礼物行显示未拆数 + 最近几笔（F1）
- **拆礼物：** 单个点开拆（G1 → G2，显示送礼人、礼物、数量、祝福语、主人得到的 EXP）；无祝福语时（G3）不留空白；多笔时可「Buka Semua」（全部拆开）先看汇总（G4 / G5 分页），再逐条看祝福语（G6）
- **拆礼物不触发任何成长值入账。** EXP 仍在送达时由 `GiftSentEvent` 入账，拆礼物页只读这笔订单的 EXP 来显示
- **收礼通知点开直接拆这一份礼物**（G1），不再进礼物页

### 3.5 礼物详情、访客与举报（FR-191，泳道 A / H）

- 礼物详情（H1 主人 / H2 访客）：礼物、数量、收到日期、送礼人和他的宠物、祝福语
- **访客能直接看主人还没拆的礼物，含祝福语；访客侧没有「未拆」状态**（11-02）
- **举报祝福语：** 礼物详情和拆开页的「⋯」菜单 →「Laporkan ucapan」（举报祝福语）（H5 → H6）。复用现有举报抽屉和举报后台，新增一个举报目标类型，**后台不另出稿**
- 举报处理后祝福语隐藏，显示「这条祝福语违反社区规范，已隐藏」（H3）；礼物本身照常显示
- 送礼人已注销（H4）：照线上的注销用户展示规则

### 3.6 去掉粉丝榜与总价值（FR-192）

- Diary 统计卡、礼物页去掉粉丝榜和礼物总价值（Diary 统计卡只剩 Diary · Milestone）
- **H5 宠物名片的「Hadiah」列由礼物总价值改为礼物个数**，布局不变，不出稿
- 后台送礼记录（AB-36）不受影响，照常能看金额

### 3.7 动效位置与交接（FR-189 / FR-190）

**动效以设计师提供的动效文件为准，整合稿里的动效只示意位置和关键帧。** 整合稿 E、G 两条泳道标了「动效位」。

| 屏 | 动效 | 设计稿 |
|---|---|---|
| E1 | 礼物落进礼盒、盒盖合上 | Send gift / Sending |
| E2 | 礼盒飞向宠物头像，头像从右侧滑入 | 同上 |
| E3 | 礼盒到达头像时的送达反馈，随后出现「送到了」文案和 EXP | 同上 |
| G1 | 未拆礼盒的待拆提示（如轻微晃动），点礼盒触发开盒 | Open gift / Single gift |
| G2 / G3 | 开盒：盒子打开，礼物、送礼人、祝福语依次出现（G3 没有祝福语区） | 同上 |
| G4 / G5 | 批量开盒，礼物格依次出现；G5 翻页是普通滑动 | Open gift / Bulk open gift |
| G6 | 无定制动效，祝福语之间普通滑动切换 | — |

**设计师交付动效时须一并给出**（按 `rive-kb` 交接清单；用 Rive 时适用，用 Lottie 等其他格式时给出对应项）：

- 文件版本、artboard 和状态机名称；每个对外属性 / 触发器的名称、类型、默认值、取值范围，触发器能否重复触发
- 礼物图标、宠物头像、送礼人头像这类**运行时替换的素材**怎么传进动效
- 每段时长；哪些地方可以点「Lewati」跳过，跳过后直接显示哪一帧
- 系统开了「减弱动态效果」时的表现（建议直接显示终态）
- 低端机或动效加载失败时的降级（建议直接显示终态，不卡流程）

**QA 场景：** 动效播放中点「Lewati」；连续快速点礼盒；批量拆 1 份 / 9 份 / 超过 9 份；动效素材加载慢或失败；减弱动态效果打开；播放中切到后台再回来。

## 6. 开发注意与接口约定

- **建议分支：** `feat/1.5.0-gift`，与首日与新手任务、推送与召回、健康记录提醒互不依赖
- **数据：**
  - `gift_orders` 加祝福语（≤ 500 字符，可空）和「主人拆开时间」（可空 = 未拆）；**上线前的存量订单一律视为已拆**（2026-11-10 定），老用户打开新版不会突然多出一堆未拆礼物
  - 本版不加礼盒样式字段
- **接口：**
  - 送礼请求加可选的祝福语字段；服务端再做一次敏感词校验，App 的拦截只是提前提示
  - 新增按订单逐笔的礼物分页接口（主人 / 访客两种视角，访客不返回未拆状态）；Diary 礼物行要「未拆数 + 最近 N 笔」
  - 新增拆礼物接口（单笔 / 批量），幂等，**不入账**
  - 收礼通知的跳转目标改为这一笔订单
  - **旧版 App 兼容：** 现有 `/gifts` 汇总接口和 `/gifts/supporters` 保留给旧版 App；新版不再调用
- **举报：** 复用 `ReportSheet` 的 submit 参数（同场所举报的做法），新增祝福语目标类型
- **文案：** 整合稿顶部「新文案表」ID / EN 两列逐条写进 `app_id.arb` / `app_en.arb`，不要自己改写或翻译
