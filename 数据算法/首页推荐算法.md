# 首页推荐算法

**创建日期：** 2026-07-16
**关联 PRD 版本：** V1.0.0（`V1.0.0/V1-0-0PRD.md` FR-17 首页 Feed 内容模型），截至 V1.2.0 未变更
**状态：** 无真正的推荐/排序算法，本文件当前记录的是 baseline 现状，供未来设计正式推荐算法时打底参考

---

## 当前逻辑（V1.0.0 FR-17，非算法推荐）

**排序：** 纯时间倒序（按发布时间排列，最新在前），**不做任何算法推荐或权重排序**。

**过滤：** 按用户宠物状态做硬过滤（非权重调整，是直接的类型可见性开关）：

| 用户状态 | 可见内容类型 |
|---|---|
| A（有宠物） | 三类全显示（日常分享 + 专业知识科普 + 成长日历快乐时刻） |
| B（计划养宠） | 专业知识科普 + 日常分享（不显示成长日历快乐时刻） |
| C（宠物爱好者） | 三类全显示 |
| 未登录 | 三类全显示，无过滤 |

**加载方式：** 无限滚动，首次加载 20 条，滚动至距底部约 5 条时加载下一批（每批 20 条），支持下拉刷新。

**其他说明：**
- V1.0.0 不做关注/好友关系，Feed 为全平台公共内容流，所有用户看到的内容池相同（仅按状态过滤类型，不做个性化排序）
- 种子内容与用户内容混合展示，不做特殊标记区分
- 用户修改宠物状态后，Feed 即时按新状态刷新

## 现状小结

这不是一个"推荐算法"，只是时间排序 + 类型硬过滤。Roadmap.md 月5「小迭代」阶段列了一条"Feed算法优化"，`项目总述/讨论记录文件.md` 也记录了一条未勾选的待办"改为算法推荐排序 → 替换 FR-17 排序逻辑，新增推荐算法 FR"——说明产品已经知道这是未来要做的事，但截至 V1.2.0 尚未启动设计。

## 待迭代事项

- 若启动真正的推荐算法设计，需要新开一个 FR 替换 FR-17 现有的纯时间倒序逻辑，并同步检查依赖"当前无推荐算法"这一假设的其他条目（例如 V1.2.0 FR-58 用户举报处置动作曾以"目前没有 Feed 推荐算法"为由删除了"限流"这项处置动作——如果后续真的做了推荐算法，需要重新评估是否要把"限流曝光"重新加回处置动作选项）
- 个性化排序涉及关注/好友关系，V1.0.0 明确不做；1.6.0 才规划关注/好友系统，推荐算法如果要做个性化，可能需要等到那之后才有数据基础
