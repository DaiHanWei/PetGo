## 0. 先看这里：三件会影响你看数的事

### 0.1 本轮修掉了「底部 Tab 切换完全没有埋点」这个 P0 缺口

`数据v100-v110.md §0.1` 第 1 条记的那个缺口 —— 底部 Tab 切换不产生页面浏览事件 —— **本版本已修**。

原因是技术性的：底部 Tab 切换在代码里不算「页面跳转」，所以自动埋点抓不到。现在改成手动上报。
影响：以「进入某个模块的用户数」为分母的漏斗（比如 AI 问诊选择率、兽医咨询点击转化率）
从 V1.1.2 起**可以算了**，但**只能从 V1.1.2 起算**，历史数据补不回来。

### 0.2 「注册成功」也补上了

旧埋点只有 `login_tapped`（点了登录按钮），没有「真的注册成功了」。本轮新增
`signup_succeeded`，且带上「从哪儿来的」（`entry_source`）。DAU / 新增注册数不再只能查数据库。

### 0.3 这一版的埋点**回答不了「改版是对是错」**

因为没取改版前基线（这是发版策略的结果，不是排期问题：埋点与改版同版本发布，用户装上新版
那一刻 Tab 顺序已经变了，采到的第一个数据点就已是改版后）。

PRD §3.3 五项核心指标里三项拿不到，**§3.3「唯一裁决指标」与 §3.4 处置原则一并失效**：

| 指标 | 状态 |
|---|---|
| 游客→注册总转化率（改版前后对比） | ❌ 不可得 |
| FR-0B 曝光量变化 | ❌ 不可得 |
| B/C 用户留存（改版前后对比） | ❌ 不可得 |
| 转化路径构成（`entry_source` 占比） | ✅ 可用（绝对值） |
| Diary 主动转私密率 | ✅ 可用（绝对值）—— **本版本最关键的产品假设验证** |

**最值得盯的一个数**：Diary 主动转私密率。发布时「同步到 Moment」默认开启，
有多少人主动关掉、只留给自己 —— 这个比例决定「私密记录」这个需求是否真实存在，
也是未来是否要把默认值反转回私密的唯一依据。

## 1. 命名怎么读（新事件一律遵守）

格式：**`模块_对象_动作`**，模块用产品叫法，动作在词尾。

例：`publish_page_sync_to_moment_toggled` = 发布页 · 同步到 Moment 开关 · 被拨动了。

- 模块前缀：`app_`（启动）`bottom_nav_`（底部导航）`diary_`（Diary 页）`social_`（社区广场）
  `health_`（健康页）`publish_`（发布页）`me_`（我的）`signup_`（注册）`milestone_`（里程碑）
- 动作后缀：`_viewed` 看到 · `_shown` 弹出 · `_tapped` 点击 · `_selected` 选择 ·
  `_toggled` 开关 · `_switched` 切换 · `_succeeded` 成功 · `_achieved` 达成

⚠️ **一个必须知道的坑**：代码里 Tab 的内部名字和产品叫法**不一致**（历史原因）。
埋点已统一用产品叫法，看板照下表配即可，不要用内部名：

## 3. 一个可以配成告警的口径

V1.1.2 起，健康类四条里程碑（M3 疫苗 / M4 驱虫 / M5 第一次看兽医 / M9 绝育）
**取消了手动打卡**，改为由健康记录 / 兽医问诊自动达成；后端会在写库前直接拒绝这类打卡请求。

所以线上如果出现 **健康类 code + `path = checkin`** 的 `milestone_achieved`，
说明那道护栏被绕过了 —— **建议配告警**。

（实现上刻意不做「纠正」：遇到这种组合照实上报 `checkin`，不会归一成 `health_record`。
改写等于把护栏失效的现场擦掉，就永远发现不了问题。）

## 4. 服务端埋点：本版本首次出现

`数据v100-v110.md §0.1` 记的「后端零埋点」本轮**局部打通**：只做了里程碑达成（T-12）。

为什么必须放后端：里程碑是否达成、走哪条路径点亮，判定全在服务端（健康记录事件、
兽医问诊关闭、计数阈值、组合解锁），客户端根本看不到，前端补不了这一环。

工程口径（供你了解，不影响看数）：
- **没有引入第三方 SDK**，直接调 PostHog 的 HTTP 接口，不多背一条依赖。
- 只在事务提交后上报（回滚了就不报 —— 否则看板上会多出一条并不存在的达成）。
- 上报失败即放弃、不重试（埋点是可损数据，不值得为它加补偿机制）。
- 用户标识是哈希值，与 App 端**逐字一致**，所以同一个人在看板上是同一个人。
- 凭证走环境变量，**留空即整个服务端上报关闭**（本地/测试默认关闭，不出网）。

⚠️ **上线前需要做的一件事**：把 `POSTHOG_SERVER_KEY` 配到生产环境（与 App 端同一个
PostHog project），否则后端这条事件不会上报。App 端不需要额外配置。
