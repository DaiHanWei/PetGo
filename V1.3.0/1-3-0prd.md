## 2. 里程碑业务现状（2026-08-26 按 `petgo-platform` 代码核验）

> 本节是里程碑模块**当前线上行为**的完整描述，作为本版本 FR-111 与后续所有相关 FR 的现状基线。V1.0.0 PRD FR-42 已于同日按本节订正（本次特殊处理）。

**清单与维护方式**

- 清单为后端编译期常量（`MilestoneCatalog`，唯一事实源），运营不可编辑。猫 31 / 狗 31 / 通用 16，各含 1 个 S 级聚合里程碑「Lulus Pemula」（C-S16 / D-S16 / G-S9，6 项新手任务全完成自动解锁）
- 每个里程碑有稳定 code（`C-S1` 形式）、级别 S/M/L、触发类型三选一：系统自动（SYSTEM_AUTO）/ 用户打卡（USER_CHECKIN）/ 推送+当天发布（PUSH_PUBLISH）
- 展示标题一律在 App 客户端按设备语言取（en / id 双表），后端中文标题仅内部用、印尼语标题仅供 H5 分享页渲染；三处由跨库测试钉住，改任何里程碑文案须三处同步

**完成路径**

- **打卡类**：里程碑列表页点未完成徽章 → 底抽屉（徽章 + 标题 + 级别 + 说明文案）→「已打卡」关联一条本人成长日历内容（已关联过其它里程碑的内容置灰）/「去发布」跳发布页预选成长日历类型，发布成功后自动以新内容回填打卡（失败静默，可回列表页手动关联）
- **健康类四条（M3 疫苗 / M4 驱虫 / M5 看兽医 / M9 绝育）已取消打卡**：只能由健康记录录入 / 真人兽医咨询结束自动完成；列表页点这四条的未完成徽章**直接跳健康记录页并预选记录类型**，不弹抽屉。⚠️ 该规则按 code 后缀 M3/M4/M5/M9 判定，**通用宠物的 G-M1（看兽医）/ G-M2（健康检查）后缀不在集合内，仍是打卡类**——即取消打卡实际只对猫狗生效
- **系统自动类**（建档、首图、首帖、被赞、被评、陪伴天数、记录条数、健康组合、新手毕业）：后端事件驱动，事务提交后异步落库
- **推送+发布类**（L1 生日 / L2 100 天 / L3 365 天）：提醒由 FR-40 / FR-41 推送承担，用户当天（生日 ±1 天）发布成长日历记录后自动完成

**庆祝页（所有级别共用一套，无级别分叉）**

- 全屏纯深色页（#141019）；渐变大徽章 + 徽章下沿级别小标签（L 金 / M 紫 / S 绿，这是级别差异的唯一视觉表达）；掉落彩纸循环；解锁瞬间一次短振动（原生通道，绕过系统触感开关）
- 内容：解锁标头 · 按 code 取的双语庆祝标题/正文（含宠物名占位）· 宠物名 + 完成日期胶囊 · KOLEKSI 已解锁合集预览（级别色圆点，两排放不下折叠「+N」）· 「分享到社区」按钮 · 「查看全部里程碑」入口
- 关闭方式：右上角 ×、左右滑动、点遮罩
- **分享产物是 H5 链接**（服务端渲染分享页，不可枚举 token，携带客户端本地化文案与合集级别串），所有级别都有分享按钮
- **已完成徽章点击 → 重温同一庆祝页**（含分享入口）

**庆祝触发时机**

- 打卡「已打卡」路径：关联成功后立即弹
- 「去发布」路径：发布成功 → 回填打卡 → 弹庆祝 → 关发布 sheet → 跳里程碑列表页
- 健康记录保存路径：后端完成为异步，App 保存后按 500 / 800 / 1200ms 三次重拉列表 diff 出新解锁；**三次都没拉到则静默、当场无庆祝**（解锁不受影响，但用户不会再被告知）。仅当所存类型有解锁可能时才轮询
- **同一操作同时解锁多条 → 只弹一次，取级别最高的一条**，其余由 KOLEKSI 圆点带过（健康路径已实装）
- 系统自动类里程碑在用户不在场时解锁（如被点赞）：**无庆祝**，仅通知中心留痕
- 健康记录保存无新解锁时不弹任何里程碑文案（2026-08-05 拍板）

**通知**

- L 级完成：通知中心 + 系统推送，点击深链到里程碑列表页
- S/M 级完成：只写通知中心、不推送（FR-76）
- 存量不回填；一次多条则写多条

## 3. 功能与需求

### 3.1 宠物年龄换算分享卡（FR-65）

**功能描述：** 将宠物年龄换算为人类年龄当量，生成卡片一键分享至 WhatsApp / Instagram Stories，驱动裂变拉新。**本版本仅支持猫、狗；其他宠物入口显示「暂不支持」**（无公认换算标准，且不同物种寿命差异过大，通用系数只能是娱乐数字，不上）。

**基建：** 复用 FR-73 卡片生成基建（`share_card_template.dart` / `share_card_preview_page.dart`：文字排版、水印能力（本卡不启用，见下）、9:16 + 1:1 双尺寸、系统分享面板）。本 FR 只替换内容模板。默认 9:16。

#### 换算规则（2026-08-26 调研结论）

**调研范围：** AVMA / AAHA 兽医协会换算指引（经 AKC、PetMD 转述）、AAFP + International Cat Care + AAHA 三方联合猫龄指引、UCSD Wang et al. 2020（*Cell Systems*）表观遗传时钟研究、消费级产品（Pedigree 年龄计算器、多家在线计算器）。

**结论：采用兽医协会的三段式分档模型，不采用 UCSD 对数公式。** 理由：① 三段式是 AVMA/AAHA/AAFP 共同背书、消费级产品普遍采用的口径，用户拿卡片去对照任何一家宠物网站都对得上；② UCSD 公式 `16 × ln(年龄) + 31` 只基于 104 只拉布拉多单一品种，AKC 亦指出其变量不足；且其结果反直觉（1 岁 = 31 人岁、2 岁 = 42），做社交分享会引发「算错了」的质疑而非传播。

| 物种 | 规则 | 依据 |
|---|---|---|
| 猫 | 第 1 年 = 15 人岁；第 2 年 +9（满 2 岁 = 24）；之后每年 +4 | AAHA / AAFP / International Cat Care 联合指引 |
| 狗 | 第 1 年 = 15 人岁；第 2 年 +9（满 2 岁 = 24）；第 3 年起按体型每年递增：**小型 +4 / 中型 +5 / 大型 +6 / 超大型 +7** | AVMA 基础口径（中型 +5）+ 主流按体型分档 |

- 体型分档（成年体重）：小型 < 9 kg · 中型 9–23 kg · 大型 23–41 kg · 超大型 > 41 kg。卡片生成时**用户四选一**，档位名旁标注体重区间辅助判断；不落档案字段、不持久化、不校验（娱乐工具）
- 不足整年部分按月线性插值；结果四舍五入取整，卡面展示「≈ N 人岁」
- 未满 1 岁按月龄比例（如 6 个月的猫 = 7.5 → ≈ 8 人岁）
- 宠物年龄按档案生日与生成当日计算；生日为建档必填完整日期，无缺失兜底

> Roadmap 原文「猫前 2 年各 ≈15 人岁（2 岁 = 30）」与所有调研来源不符，已按调研结论修正为 15 + 9。

#### 入口（2026-08-28 拍板）：「Know more about your pet」综合入口

- **成长档案头部现有的宠物身份证（KTP）入口条**（Diary 头部 `diaryIdCardButton` → `/profile/id-card`）**改造为综合入口「Know more about your pet」**（入口名称最终文案待定，中/EN/ID 三语交付）

- 年龄换算项对非猫狗宠物置灰 +「暂不支持」提示；KTP 与 Tailsonality 全物种可用
- ⚠️ 波及面：既有指向 `/profile/id-card` 的深链/通知跳转须兼容重定向，不能断链
- **迁移与新功能引导（2026-09-01 拍板，单页蒙层；2026-09-09 补充分两次触发）**：用户**首次进入成长档案页**（含从建档庆祝页「查看档案」进入）展示一次性蒙层引导——指示 ① KTP 挪到了「Know more about your pet」综合入口的哪个位置、② 性格测试（FR-117）从哪里进入；看过即记录（按账号一次），不重复弹。**分阶段上线的拆分（2026-09-09 拍板）**：FR-117 随批次 B2 才上线（见 §5），先行上线的批次 A 版本蒙层**只讲 ①KTP 位置**；批次 B2（FR-117）上线后，对**已看过第一版蒙层**的账号再触发一次仅讲 ② 性格测试入口的补充引导（同样按账号一次、看过即记录，两次引导互不影响）

#### 卡片（2026-08-28 拍板）

- 卡面：宠物头像（无则字母头像）+ 宠物名 · 实际年龄（X 岁 Y 个月）→ 人类年龄当量（视觉主体大字）· 一句按年龄段取的趣味文案 · 狗卡标注所选体型档 · **无水印** + 下载引导——**与 FR-73 内容分享卡样式保持一致（2026-08-31 拍板）**；水印仅属 KTP/护照的「付费无水印」保护场景，免费传播卡不加（FR-73 已有同款产品决定）

### 3.2 里程碑庆祝页优化与逻辑调整（FR-111）

**基线（已拍板）：** 统一庆祝页为唯一庆祝形态，不补做 V1.0.0 规划的 S/M/L 三级差异化动效。**与既有三条规则的关系**：1.1.0 新手任务复用同一庆祝页——并存不改；1.1.2「多条同解锁只弹最高一条」——并存，且已随漏庆祝收口拍板扩展为全路径统一规则；1.2.0 FR-76 通知分级——并存不改，本 FR 不动通知。

#### 已确认项

**通用宠物健康类里程碑改为自动达成（2026-08-28 拍板，补齐 1.1.2 FR-86 的漏网项）**

- 现状：FR-86「健康类取消打卡、只能自动达成」按 code 后缀 M3/M4/M5/M9 判定，通用清单的 G-M1「第一次看兽医」/ G-M2「完成第一次健康检查/疫苗」后缀不命中，**仍为用户打卡类**——同一里程碑猫狗须真实问诊/录健康记录才点亮，其他宠物点「已打卡」即可，属规则漏网而非有意差异
- 变更：G-M1 / G-M2 **取消打卡路径**，与猫狗健康类同规则——G-M1 由真人兽医咨询结束自动完成（不含 AI 问诊，同 FR-86 OQ-17 口径）；G-M2 由录入「体检」或「疫苗」类型健康记录自动完成
- 列表页点击这两条的灰徽章 → 直跳健康记录页并预选类型（与猫狗四条一致）；已打卡候选过滤、后端拒绝打卡护栏一并覆盖
- 工程约束：健康类判定由「后缀集合」改为**按 code 显式列举**（C/D 系 M3/M4/M5/M9 + G-M1/G-M2），顺带消除 G-M3「陪伴 30 天」/ G-M4「10 条记录」被误判为健康类的隐患（现无用户可感知影响，但埋点 T-12 的线上校验会把它们算错）
- 存量：已通过打卡完成的 G-M1/G-M2 **保持完成态不回滚**；未完成的按新规则走
- 文案：G-M1/G-M2 的打卡引导文案作废，改用与猫狗 M5/M3 同类的说明文案（三处同步）

**漏庆祝收口（2026-08-28 拍板通过）**

- 现状：健康路径三次轮询没拉到就永远不弹；系统自动类在用户不在场时解锁完全无庆祝
- 后端 `pet_milestones` 新增 `celebrated_at`（可空时间戳）；庆祝页每次展示成功后 App 回报一次（best-effort、幂等）
- **补庆祝只挂在里程碑列表页**：进入列表页时若存在「已完成且未庆祝」条目 → 自动弹一次庆祝，多条取级别最高、其余由 KOLEKSI 圆点带过，全部条目一并置位；不按级别过滤（S 级也补——入口是用户主动点击，无打扰问题）
- **成长档案 Tab 的里程碑进度条入口加角标**：存在未庆祝条目时显示小红点 /「+N」，点进列表页后触发补弹、角标消除；档案 Tab 本身不弹全屏庆祝
- 既有即时庆祝路径不变（当场弹仍是首选），短轮询机制保留，只是不再是唯一机会
- 存量迁移：上线时全部既有已完成条目的 `celebrated_at` 一次性回填为完成时间，避免老用户进页被补弹旧里程碑
- 「多条同解锁只弹最高一条」扩展为全路径统一规则（含补庆祝路径）

**庆祝页与徽章视觉方向（2026-08-28 拍板）**

### 3.11 宠物护照与场所盖章（FR-120，2026-08-28 立项——KTP 留存改造）

**问题：** KTP 付费效果好，但它是一次性仪式（领证 → 付费下载 → 分享 → 结束），功能单薄导致用完即走、留存差。本 FR 把 KTP 模块从「一张静态卡」扩展为「会长大的收集品」，提升留存与平台参与度。

**方案：宠物护照 + 场所打卡盖章**（KTP 卡面成长与限定卡面两个方向记入 Roadmap 功能灵感池，等数据后再议）。

#### 规格

- **护照签发**：护照号按既有设计 `2.数据算法/宠物身份码护照编码规则.md` 第二套编码（类型 + 顺序号，不含可解码宠物信息，后台关联表反查身份码）——该编码规则设计已久、首次获得功能承载。宠物首次进入护照页或首次打卡时自动签发，免费
- **盖章**：每次场所打卡（FR-112 ⑧）= 护照盖一枚章。章面按场所**类型**区分（咖啡店/餐厅/公园/商场/酒店民宿/宠物服务/其他，7 款章面插画，与 FR-111 徽章、FR-117 角色同产线：AI 生成 + 人工调整）；**同一场所的章唯一**，重复到访在章上累计次数角标（×2、×3…）
- **场所合并/下架时的章（2026-09-01 拍板）**：运营合并重复场所 → 两枚章**并成一枚、次数相加**，打卡记录全部改挂保留场所；场所下架 → 已盖的章**保留不删**（历史事实，用户无辜），点击跳转显示「场所不存在」
- **集章页**：护照样式翻页浏览，每章显示场所名 / 首次打卡日期 / 到访次数；空态引导去场所列表（导流 FR-112）
- **视觉隐喻（2026-09-01 拍板）**：**护照过关盖章**——内页翻页、油墨章质感，盖章瞬间做「啪」的落章动效；分享卡支持**多套样式**，首发方向含**登机牌/机票**形态（宠物名、护照号、场所、日期排成机票字段，社交传播感强）。**首发 2 款样式（2026-09-01 拍板）**：护照内页 / 登机牌，均可免费使用（带水印），各自独立解锁去水印——多样式与付费模型天然咬合，后续新样式即新 SKU
- **分享**：集章页可生成分享卡（复用 FR-73 卡片基建，9:16 + 1:1），带 App 下载引导——晒护照即拉新
- **入口**：「Know more about your pet」聚合页（FR-65 入口改造）内新增第 4 项：KTP / **护照** / 年龄换算 / Tailsonality
- **依赖**：强依赖 FR-112 §8 打卡子功能——两者按 2026-09-09 拍板的分阶段上线安排同批上线（FR-112 场所本体①~⑦、⑨已先行，见 FR-112 ⑧ 分阶段说明）；护照全物种可用

- **付费点（2026-08-31 拍板订正）：集章页样式一次性解锁**——不是按次下载付费：
  - 未解锁：集章页正常可看、可生成分享卡，但产物**带水印**
  - 用户可选择解锁集章页样式（一次性，按样式独立解锁）：解锁后该样式**永久无水印**，此后新盖的章自动更新进已解锁的页面，**不再收费**
  - **定价（2026-09-01 拍板）**：默认与 KTP 高清下载一致（当前 Rp5,000），**后台运营可配置**（复用既有定价配置机制，按样式独立配置项，见 `v1-3-0后台prd.md` AB-18A）
  - 未来平台上新的集章页样式时，新样式**单独解锁**（新的一次性 SKU）——复购点在「出新样式」，不在「章变多」
  - 与 KTP 的一次性永久购买语义一致（`IdCardHdPurchase` 同款范式），但需**自建护照解锁表**：解锁粒度为 `[ASSUMPTION: 宠物 × 样式]`（KTP 是账号级 UNIQUE(user_id)，护照按宠物签发，粒度需工程与产品确认）
- **分享奖励（2026-08-31 拍板）**：护照卡分享成功**接入 FR-96 PawCoin 分享奖励体系**（跨渠道共用全局月度上限，渠道注册进 AB-3M）
