## 1. 模块 3（扩展）：内容与账号举报审核

对应用户端 PRD：V1.2.0 FR-58（用户账号举报）、内容举报（V1.0.0 FR-25）、已上线的评论举报（V1.0.0 FR-25 曾列为 non-goal，后于此前一次小版本迭代单独实现上线）

**功能描述：** V1.0.0/1.1.0 运营审核后台仅有基础的举报工单列表。随着用户举报（FR-58）加入、评论举报已在此前小版本迭代上线，工单量增加，运营需要更高效的处理工具。

### AB-3D：审核工单统一视图（原 FR-59，覆盖 AB-3A 举报队列升级）

**后果：**

- 工单类型分类标签：内容举报 / 评论举报 / 用户举报 / 账号标识字段（V1.1.0 AB-9A 异步审核产生）
- 每个工单展示：
  - 举报类型 + 举报原因
  - 被举报对象原文/缩略图（含上下文：所属帖子、父评论等）
  - 被举报账号的历史违规记录（同账号历史处置次数）
  - 举报人数（同一内容/评论/账号被举报的总次数，辅助优先级判断）
- 工单优先级自动排序：同一对象被举报次数越多，优先级越高
- 批量处置：运营可选多条同类型工单批量执行相同处置动作

`[NOTE FOR PM: 评论举报的运营后台审核界面需展示被举报评论的上下文（所属帖子 + 父评论），避免运营脱离语境判断]`

### AB-3E：违规内容自动标注辅助（原 FR-60，三方服务扩展）

**背景：** 目前三方审核服务仅在发布/评论时做同步拦截，历史存量内容和新增举报内容不做主动扫描。V1.2.0 扩展三方服务调用范围，辅助运营识别高风险内容。

**后果：**

- 举报工单到达审核队列时，系统自动调用三方服务对被举报内容/评论/账号昵称进行评分（0-1 风险分）
- 风险分 ≥ 0.8 的工单在后台自动标注「高风险」红色标签，供运营优先处理
- 风险分不作为自动处置依据——最终处置仍由运营人工决定，防止误伤
- 历史存量内容扫描：V1.2.0 不做，避免批量误封引发用户投诉（可在运营体量稳定后评估）

`[ASSUMPTION: 三方审核服务支持按需调用（非实时流式推送），可接受工单到达后触发异步调用]`

### AB-3F：运营账号互动能力（新增）

对应用户端 PRD：无直接对应 FR，纯后台运营工具，用于内容运营/新用户互动激励场景

**背景：** 运营需要能够对用户发布的内容进行点赞和评论，用于活跃新发布内容、鼓励新用户。复用现有虚拟账号池（V1.1.0 AB-1.1-02A，此前仅用于种子内容发布），扩展其可执行的操作范围。

**后果：**

- 全量内容管理列表（AB-3B）新增「点赞数」「评论数」两列展示（扩展 V1.1.0 AB-3B / AB-1.1-13 已有列表字段）
- 运营在内容详情/管理页可选择一个虚拟账号（从 AB-1.1-02A 虚拟账号池中选择），以该虚拟账号身份对任意已发布内容执行点赞或发表评论
- **不支持登录/冒用真实用户账号执行该操作**——仅限虚拟账号池内的身份，虚拟账号本身不具备登录能力，只作为点赞/评论的显示身份
- 虚拟账号发表的评论/点赞与真实用户产生的记录混合展示，不做特殊标记区分（延续 AB-1.1-02A"不享受审核豁免、不做特殊标记"的既有原则）
- 操作记录操作人（运营账号）和时间戳，供审计查阅

## 2. 模块 10（扩展）：内容运营管理（顶置 / 话题 / 装饰标签）

对应用户端 PRD：V1.2.0 FR-68（顶置坑位与内容顶置）、FR-69（内容话题）、FR-75（内容装饰标签）

### AB-10A：顶置管理

**后果：**

- 顶置配置列表：按坑位（Feed / 各话题页）分类展示当前及排期中的顶置配置，含生效状态（排期中/生效中/已结束）
- 新建顶置：选择坑位 → 选择类型（顶置已发布内容 / 新建推广卡片）→（内容类型）搜索/选择已发布内容；（推广卡片类型）填写图片+标题+跳转目标 → 设置开始/结束时间 → 保存（同一坑位时间重叠时校验拦截，见 FR-68）
- 编辑/提前下线：排期中或生效中的顶置配置均可编辑或手动提前结束
- 历史记录：已结束的顶置配置保留查询，供运营复盘曝光效果

### AB-10B：话题管理

**后果：**

- 官方话题创建/编辑/下线
- 「精选/推荐」标记设置，控制是否出现在成长档案底部展示位
- 按话题维度查看数据：帖子数、浏览量、曝光量、互动量（点赞+评论）、话题热度分（见 `v1-2-0prd.md` FR-69 术语表「话题热度」定义），支持近7天/历史累计两种口径切换
- **运营手动指定优先展示**：支持在展示位候选池中手动置顶特定话题，优先于自动热度排序（见 FR-69）
- 用户自建话题：后台可查看列表（含孤立话题），可下架/隐藏违规话题名称（配合评论举报/内容举报机制），不支持编辑改名

### AB-10C：内容装饰标签管理（新增）

**后果：**

- 装饰标签创建/编辑/下线：名称 + 图标/样式上传
- 为任意已发布内容分配/取消装饰标签，支持设置生效开始/结束时间（到点自动生效/失效），也支持不设结束时间的永久分配
- 分配记录列表：按内容/按标签两种维度查看当前生效的分配情况，支持按标签筛选

## 3. 模块 11（新增）：用户手机号查看

对应用户端 PRD：V1.2.0 FR-70（手机号采集入口）

### AB-11A：用户手机号查看（扩展 V1.0.0 用户管理模块）

**后果：**

- 用户详情页新增手机号字段展示（沿用现有用户详情只读权限，不新增独立权限项）
- 支持按手机号已填写/未填写筛选用户列表，供运营召回名单导出
- **召回名单不自动排除已封号账号，但需标注账号状态**：导出的召回名单（及列表展示）中，每条记录标注该账号当前状态（正常/已封号），不做自动过滤剔除，由运营根据标注自行判断是否将该账号纳入召回触达
- **手动触发手机号填写提醒推送**：运营可随时对"未填写手机号"筛选结果批量发送推送通知，鼓励用户填写手机号（对应用户端 FR-70 一次性软引导之后的后续提醒，本版本不设 App 侧自动重复提醒，改为运营按需手动触发）；`[ASSUMPTION: 推送文案由运营在触发时自行填写，不预设固定文案模板；触发频次无系统限制，由运营自行把控节奏避免过度打扰]`

## 4. 模块 12（新增）：用户标签管理

对应用户端 PRD：V1.2.0 FR-74（用户标签）

### AB-12A：用户标签配置与分配

**后果：**

- 标签创建/编辑/下线：名称 + 图标上传
- 为任意用户分配/取消标签，支持批量操作；分配支持设置生效开始/结束时间（到点自动生效/失效），也支持不设结束时间的永久分配
- 分配数量不设上限，但用户端同时只展示 2-3 个（见 `v1-2-0prd.md` FR-74，具体排序规则见 OQ-11）
- 分配记录列表：按用户/按标签两种维度查看当前生效的分配情况，支持按标签筛选
