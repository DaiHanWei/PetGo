# V1.2.0 PRD 逻辑与交叉引用一致性审查

审查范围：`v1-2-0prd.md`、`v1-2-0后台prd.md`，对照 `.decision-log.md` 中 2026-07-15 两条条目描述的今日重排（删除 FR-57/FR-61/FR-63/FR-50B/FR-66/AB-2J/AB-2I，拆分 FR-59/FR-60→AB-3D/AB-3E，迁移 AB-10A/AB-10B/AB-11A 至后台文档，FR-58 处置动作删除限流，§3.x/OQ/A 连续重排）。

本次审查**仅**核对内部逻辑一致性（章节引用、编号连续性、术语表用法、跨文件引用有效性、重构残留物），不评估 PRD 整体质量。

## 发现 1（高）：§1 版本目标 第2条 的 §3.X 范围与内容不符，且与文末澄清句自相矛盾

**位置：** `v1-2-0prd.md` 第22行

> 2. **兽医端效率升级 + 收费深化**（§3.2-3.5，2026-07-14 补齐）：对应 `Roadmap.md` 定义的 1.2.0 版本主标签——多宠物账号管理、宠物年龄换算分享卡、软性兽医偏好。

**问题：** 该条列出的三项功能——多宠物账号管理、宠物年龄换算分享卡、软性兽医偏好——在当前文档中分别对应 §3.3（FR-64）、§3.4（FR-65）、§3.5（FR-67）。标注的范围「§3.2-3.5」多包含了 §3.2（健康提醒激活，FR-62）。

而第27行紧接着明确声明：

> §3.2（健康提醒激活）与上述主线均无关，是顺带纳入的补充项，不代表额外的独立主线。

两处直接矛盾：第22行把 §3.2 划入「兽医端效率升级+收费深化」主线范围，第27行又明确否认 §3.2 属于该主线（或任何主线）。范围引用应改为「§3.3-3.5」。

**推测成因：** 疑似 §3.x 顺序号重排（决策日志 2026-07-15 第一条：「渲染完成：v1-2-0prd.md 全文重排（§3.x 顺序号...均已连续重排）」）过程中，只更新了单点引用（如「不在本版本做的」中的「见 §3.10 FR-72」），漏更新了 §1 中的这一处区间引用。

## 发现 2（中）：§5 第4条引用已删除的 FR-61 作为「已确立的先例」，未加历史/存档说明

**位置：** `v1-2-0prd.md` 第311行

> ...**V1.1.0 文档不回改**，以本 FR-62 为准，**沿用 FR-58/61 已确立的跨版本覆盖惯例**。

**问题：** FR-61（兽医资质自助上传）已于 2026-07-14 决定延期，并已从 `v1-2-0prd.md` 正文中完整删除（迁移至 `Roadmap.md`「待排期功能池」）——决策日志明确记录：「已将 FR-61/AB-2I 从 v1-2-0prd.md 正式范围移出（§1/§3.4/§5 标注存档+延期）」。当前文档正文中已找不到任何 FR-61 的定义或说明（`grep FR-61` 全文档零命中；此处「FR-58/61」是紧凑简写，字面不含独立的「FR-61」子串，容易被简单文本搜索漏检）。

任务给定的「已删除编号」清单中明确包含 FR-61。此处引用没有被框定为历史/存档引用（不像 §5 第6条对 FR-50B 那样明确说明「进一步延期」「存档」），读者据此引用去正文查找 FR-61 的具体内容时会扑空，只能在决策日志里找到线索。

**建议：** 要么把这句改为只引用仍然有效的先例（如单独引用 FR-58 之于 FR-25 的先例），要么补充「FR-61 本身已延期存档，但其确立的跨版本覆盖写法仍作为先例沿用」之类的说明。

## 发现 3（中）：后台 PRD 模块1标题行将「评论举报」错误归入 V1.0.0 FR-25

**位置：** `v1-2-0后台prd.md` 第13行

> 对应用户端 PRD：V1.2.0 FR-58（用户账号举报）、**已上线的评论举报/内容举报（V1.0.0 FR-25）**

**问题：** 主 PRD 自己的 §5 第1条对 FR-25 的定性是：

> **V1.0.0 FR-25 范围扩展**：FR-25 原文明确「V1.0.0 不做评论举报、不做用户账号举报」。评论举报已在此前一次小版本迭代中单独实现并上线（不在本 PRD 记录范围内）...

即 FR-25 在 V1.0.0 中明确把「评论举报」列为 non-goal（当时不做），评论举报是后来在某次未被本 PRD 链条记录的小版本迭代中单独补上线的，**并不属于 FR-25 范围**。只有「内容举报」才是 FR-25（主 PRD 术语表：「内容举报 | 对帖子（FR-25）的举报，V1.0.0 已有」）。

后台 PRD 第13行把「评论举报/内容举报」并列打包标注为「（V1.0.0 FR-25）」，相当于把评论举报也算成 FR-25 的产物，与主 PRD 自己的说法矛盾。有意思的是，后台 PRD 紧接着第15行的表述反而是准确的：

> ...随着用户举报（FR-58）加入、**评论举报已在此前小版本迭代上线**，工单量增加...

即同一文档内部，标题行（第13行）与功能描述段（第15行）对「评论举报」出处的表述互相矛盾，标题行应改为类似「已上线的评论举报（另行上线，非 FR-25）/内容举报（V1.0.0 FR-25）」，或直接去掉评论举报后面的编号归属。

## 发现 4（低，建议核实而非确定性 bug）：FR-65 段落内「宠物身份证」卡片一会儿引用 FR-49B，一会儿引用 FR-49
