V1.2.0 · UI 页面完整度草稿

成长档案与宠物管理 — 多宠物账号管理（FR-64）+ 宠物年龄换算分享卡（FR-65）+ 健康提醒激活（FR-62）

阶段 1／3：页面完整度 已对照 petgo-platform（stag 分支）实际代码构建——成长档案页（growth_archive_page.dart）、宠物信息卡（pet_info_card.dart）、健康记录列表（health_list_page.dart）、身份证页（id_card_page.dart）、建档/编辑表单（pet_profile_create_page.dart/pet_profile_edit_page.dart）、二次确认抽屉（confirm_sheet.dart）等真实文件，字体/配色/组件结构均取自代码。仍不是最终视觉稿，阶段 2 再做美观/创意打磨。

本轮核对代码发现的关键点

  1. 宠物切换器是全新 UI 元素：现有 growth_archive_page.dart 完全没有多宠物概念（单宠物档案，无切换器）。本稿在"Paspor {name}"标题行上方新增了横向头像切换器，是本次设计的核心新增部分，非改动现有代码结构。
  2. 建档表单本身不需要重画：FR-64 明确"沿用 V1.0.0 宠物档案创建流程，不新增字段"——pet_profile_create_page.dart 现有表单（头像/名字/物种/品种/生日/简介）直接复用，本稿只展示切换器"+"入口如何跳转到这个既有表单，不重新设计表单本身。
  3. 删除确认沿用 confirm_sheet.dart 组件：拖拽条+圆形图标(危险态红/中性态紫)+标题+说明+主按钮+描边取消按钮，已有的样式，本稿删除宠物场景直接复用。
  4. 健康记录表单目前疫苗名称是自由文本框，不是预设下拉：health_list_page.dart 里 _HealthRecordForm 的疫苗名称字段是 TextField（最多30字自由输入），但 PRD FR-62 假设"沿用 V1.1.0 FR-45A 已定义的预设疫苗名称清单"。如果代码里这份预设清单实际并未落地成一个选择器 UI（本次只查到自由文本框），FR-62 的"按疫苗名称分别设默认提醒间隔"在工程实现上可能需要先把这个字段改造成下拉选择器，否则系统无法准确匹配"这条记录对应哪个预设疫苗名称"来查默认间隔——这是一个需要与工程确认的潜在缺口，本稿设计按 PRD 假设的"下拉选择"呈现，但请注意现状可能是自由文本。
