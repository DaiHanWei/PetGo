## 0. 触发

操作者 2026-11-19 提出三个目标：

1. **不审美疲劳**：养猫的人也想看别的宠物。
2. **新宠物能上推荐**：新建档的宠物要有露脸机会。
3. **热门多曝光，但不只看热门**。

## 1. 现状问题（数据见 V0 节 + 下表）

| | 猫 | 其他 | 狗 | 合计 |
|---|---|---|---|---|
| 能进推荐池 | 130 | 36 | 16 | **182** |
| 近 14 天发过帖、但不满 3 条被挡 | 448 | 116 | 40 | **604** |
| 其中近 14 天新建档的 | 409 | 108 | 33 | **550** |

- 三段先后排：养猫用户要翻约 130 只猫（13 页）才见到第一只狗
- 「≥ 3 条公开记录」门槛挡掉 550 只新宠物
- 没有随机：同品种的人看到的顺序完全一样
- 「同类」按猫 / 狗 / 其他三大类，养兔子的人同类里会出现仓鼠、鸟
- 点赞集中：推荐池前 10% 拿走 52% 的真人赞，中位数 3，32 只零赞，最高 84
- 近 7 天活跃用户：养猫约 65%、其他 16%、狗 5%、没有在用宠物 14%

## 2. 结构

### 2.1 四个来源

| 来源 | 候选 | 池内排序 |
|---|---|---|
| 热门 | 普通池 + 新宠池的宠物里，热度前 30 名 | 按「人 + 日期」固定的加权随机，热度越高越容易排前 |
| 新宠 | 建档 ≤ 14 天、有头像、≥ 1 条带图公开成长记录 | 普通位打分（§2.4） |
| 同类 | 普通池里细分物种（`pet_species`，27 种）与看的人默认宠物相同；同品种排前 | 普通位打分 |
| 其他类 | 普通池里细分物种不同的；没宠物 / 游客时 = 全站 | 普通位打分 |

普通池入池条件不变：近 14 天发过公开成长记录、累计 ≥ 3 条、有头像、主人未注销 / 封号。对看的人照旧排除自己的、已追更的、互相拉黑的。

**已知缺口（接受）：** 54 只建档超过 14 天、近 14 天发过帖但不满 3 条的宠物，两个池都进不去，后续优化再处理。

### 2.2 配方（每页张数）

| 一页张数 | 同类 / 其他类 / 新宠 / 热门 | 没宠物、游客：其他类 / 新宠 / 热门 |
|---|---|---|
| 10 | 3 / 3 / 2 / 2 | 6 / 2 / 2 |
| 6 | 2 / 2 / 1 / 1 | 4 / 1 / 1 |

其他张数按比例四舍五入、保证总数对得上。

**首日推荐页单独配方**（新用户第一印象，不放新宠，名额给热门）：

| 首日推荐页（6 张） | 同类 / 其他类 / 新宠 / 热门 |
|---|---|
| 有宠物 | 2 / 2 / 0 / 2 |
| 没宠物 | — / 4 / 0 / 2 |

- 接口新增位置参数（如 `scene=onboarding`），首日推荐页传，不传走通用配方；旧版 App 的首日推荐页仍是通用配方
- 补位跳过新宠：其他类 → 热门 → 同类，热门最多 3 张
- 除首日推荐页外，本版本所有位置同一套配方

### 2.3 取卡、去重、补位、打散

1. **取卡先后**：热门 → 新宠 → 同类 → 其他类；后取的来源跳过已经出过的宠物（新宠又是热门时算热门）
2. **补位**：某来源没货时，空位按 其他类 → 新宠 → 热门 → 同类 补（跳过没货的来源自己）；**热门每页最多比配方多 1 张**；全都没货才少出、结束翻页
3. **打散（防扎堆）**：同一细分物种连续不超过 2 张；排不开时允许超出，不少出卡

**已知效果（接受）：** 新宠和热门不分物种，新宠池约 3/4、推荐池约 7/10 是猫，养猫用户一页 10 张里大约 8 张是猫，防扎堆常排不开。目标①靠其他类 3 张保证。

### 2.4 普通位打分（同类 / 其他类 / 新宠）

`分数 = w新鲜 × 新鲜度 + w热度 × 热度 + w随机 × 每日随机(人, 日期)`

- **新鲜度**：最后一次发公开成长记录离现在越近越高，权重最大；默认效果是 24 小时内更新的整体排在 3 天前更新的前面
- **热度**：同 §2.5，全文只有这一套口径
- **每日随机**：按「人 + 日期（雅加达时间）」固定，幅度小，让新鲜度、热度差不多的宠物每天换着出；游客按日期固定（所有游客同一天一样）
- 三个权重的默认值由架构定，须满足上面的默认效果

### 2.5 热度

- 近 **14 天**收到的**真人点赞**（不含自动赞），只算公开成长记录收到的赞
- 按时间衰减，建议半衰期 3 天，具体公式由架构定
- 窗口与现状段内排序的 14 天一致（2026-11-20 定，不另用 7 天）

### 2.6 翻页一致性

- 一次连续翻页内不重复、不漏
- 游标分别记四个来源各自取到哪，并带第一页的时间点；后面每页都按这个时间点算新鲜度和热度（热度带衰减，不定住时间点会导致分数变动，引起重复或漏）
- 不同次打开、不同入口之间可能重复，接受；**不做曝光记录**（操作者：宠物更新了就该再看到，靠新鲜度保证）
- 现状对比：V0 游标是单一 keyset，代码注释接受「极少数跨页重复或漏一次」；V1 要求更严

## 3. 参数（后台「算法参数」页 ·「宠物推荐」卡，AB-59）

| 参数 | 默认 | 范围 |

| 每页同类 / 其他类 / 新宠 / 热门（按 10 张填，合计 10） | 3 / 3 / 2 / 2 | — |
| 首日推荐页：同类 / 其他类 / 新宠 / 热门（按 6 张填，合计 6） | 2 / 2 / 0 / 2 | — |

| 新宠：最少带图公开记录 | 1 | 1–3 |
| 热门：统计天数 | 14 | 1–30 |
| 热门：池大小 | 30 | 5–200 |
| 热门：点赞衰减半衰期（天） | 3 | 0.5–14 |

不放出来、保持写死：普通池门槛（近 14 天活跃、≥ 3 条）。保存后下一次请求生效，游客快照最多 10 分钟。

## 4. 验证

- 养猫用户第一页至少 3 张不是猫（其他类够时）
- 同类很少的用户（如养鸟），第一页热门不超过 3 张
- 新版 App 首日推荐页没有新宠名额的卡，热门 2 张（同类不够时最多 3 张）
- 热度第 1 名出现在用户前两页的概率 ≥ 60%（抽样 100 个用户；达不到调权重）
- 两个用户同一天前两页的热门名额不完全相同；同一用户隔天顺序不同
- 今天新建档、发了 1 条带图公开 Diary 的宠物，当天能出现在别人的推荐里

**上线后观察：** 推荐卡点击率按来源拆、推荐带来的追更数、每天被曝光的不同宠物数、新宠物被推荐后 7 天内再发帖比例。按自建埋点算（`match` 六个值：`same_breed / same_species / other_species / new_pet / hot / global`），不依赖 PostHog。

## 5. 仍未解决

- 54 只「建档超 14 天、不满 3 条」的宠物不进池
- 其他位置（首页横滑、全屏页等）是否分配方：本版本不分，上线后按位置看点击率、追更再议
- 新宠 / 热门卡角标：本版本不加，上线后看各来源点击率再议

# V0 · 现状 baseline（2026-11-19 读 `main`）

- 接口：登录 `GET /api/v1/me/pet-recommendations`、游客 `GET /api/v1/public/pet-recommendations`（服务端 10 分钟快照）
- 使用位置：全屏推荐列表页（10 张、可翻页）、首页横滑行、关注列表推荐区、Diary 推荐网格（各 10 张）、首日推荐页、游客横条（各 6 张）
- 入池：近 14 天发过公开成长记录、累计 ≥ 3 条、有头像、主人未注销 / 封号；排除自己的、已追更的、互相拉黑的
- 分三段先后排（按默认宠物 = 最早建档、在用的那只）：同品种 → 同类其他品种 → 其他类；没填品种跳过第一段；没宠物 / 游客只有全站一段
- 「同类」按 `pet_type`（猫 / 狗 / 其他）
- 段内排序：最后发帖日期（雅加达时间）↓ → 近 14 天真人点赞数 ↓ → 发帖时刻 ↓ → petId ↓
- 翻页：`PetRecommendCursor` 单一 keyset（互动量、发帖时刻、petId、段号），实时计算，接受极少数跨页重复或漏
- 没有随机，没有后台参数
