# PRD：TailTopia 运营后台 V1.5.4——后台权限梳理

## 0. 文档说明

后台不少页面「能看就能改」，或者一个权限管着同一页里好几件不相干的事，没法只给某个人其中一部分。本文把这些权限拆开。

| 编号 | 功能 | 来源 |
|---|---|---|
| **AB-61** | 成长体系页：专属头像框、批量发放 EXP 各用自己的权限，页签按权限显示 | 2026-11-26 Hex |
| **AB-62** | 运营配置页：按配置卡分开授权 | 同上 |
| **AB-63** | 商品页：编辑商品、上下架、置顶、隐藏评价、商城 banner 分开授权 | 同上 |
| **AB-64** | 电商订单：发货送达、丢件破损、涉及退钱的处置、门店进货单分开授权 | 同上 |
| **AB-65** | 商城退货与退款打款：不再和问诊退款共用权限，退货审核、退货退款、开封判例、退款打款分开授权 | 同上 |
| **AB-66** | 优惠券、礼物目录：导出兑换码、送礼 QRIS 最低金额单独授权 | 同上 |
| **AB-67** | 查看和编辑分开：运营弹窗、暖贴回复、评论管理、虚拟账号与种子内容、兽医资质、人工复核、场所管理 | 同上 |

- **版本：** V1.5.4，排期待定
- **编号：** AB-61 ~ AB-67；下一个可用 FR-350 / AB-77（同版运营活动占 FR-340、FR-349、AB-68、AB-76，物流优化占 FR-341 ~ 348、AB-69 ~ 75）
- **代码基线：** `petgo-platform` `origin/dev_1.5.2`（2026-11-26 核实：权限常量 `AdminPermissions`、页面归属 `AdminPageCatalog`、各后台控制器的 `@PreAuthorize`）；2026-11-27 复核 `origin/dev_1.5.4`，权限常量与 dev_1.5.2 相同
- **拆分原则（2026-11-26 Hex 定）：**
  1. 每个页面有单独的「查看」权限，只看不能改
  2. 同一页里**互不相干的功能块**各自一个编辑权限（按业务分组，不是每个按钮一个）
  3. **涉及钱的操作**（退款、打款、发 PawCoin、导出兑换码）单独一个权限
- **不在本文：** 「运营活动」页签的查看 / 编辑权限，由同版运营活动规则引擎需求自己新增（`growth.campaign_view` / `growth.campaign_edit`）；本文只管成长体系页上其他页签和页头按钮。同版物流优化需求新增的「运费补贴报表」权限（`shop.shipping_subsidy_view`）和「编辑运费价格」权限（`shop.shipping_price_edit`，管价目表 / 区域价格档 / 保价费率，上线只给超管）也由那边自己加
- **上线分配（2026-11-27 Hex 定）：** 全部按旧权限补码，上线后谁都不多不少；之后由超级管理员在角色配置页按需收权
- **不出 UI 稿（2026-11-27 Hex 定）：** 各页面只是「没权限的按钮不显示、配置卡只读」，角色配置页矩阵由代码按页面归属自动生成；验收按 §3 各表和 §3.9 逐项核

## 1. 目标

- 可以只给某个人其中一部分权限，例如：只管头像框不碰 EXP 数值；只发货不能退钱；只看退货不能打款
- **上线时谁都不多不少**：每个角色、每个自定义账号上线后能做的事和上线前一样（例外见 §3.8：少数「只给了查看却看不了」的情况，上线后变得能看）
- 角色配置页能看清每个权限管什么

## 2. 现状（2026-11-26 核 `origin/dev_1.5.2`）

- 权限码定义在 `AdminPermissions`，分组 `GROUPS`；每个码在 `AdminPageCatalog` 里归属一个页面（查看 / 编辑 / 其他操作三列之一），角色配置页按这个画矩阵
- 角色权限存 `admin_role_permissions`，自定义账号的逐码勾选存 `admin_account_permissions`
- 拆权限的先例：1.5.2 把「服务范围与运费」从运营配置权限拆出（`shop.shipping_view` / `shop.shipping_edit`），迁移按数据补码、不写死角色名
- 问题清单见 §3 各节「现在」一行

## 3. 功能与需求

每节格式：现在 → 拆成 → 上线补码。「补码」= 上线迁移里，持有旧码的角色和账号自动加上新码。

### 3.1 成长体系页（AB-61）

**现在：** 「改 EXP 配置」管成长值规则、消费换算、等级表，还管专属头像框（新建、编辑、上下架）；「调整用户 EXP」管单个用户调 EXP（用户抽屉里）**和**页头批量发放，而且有它就能看整个成长体系页和头像框列表。

**拆成：**

| 权限码 | 中文 | English | Bahasa Indonesia | 管什么 |
|---|---|---|---|---|
| `growth.config_view`（现有） | 查看 EXP 配置 | View EXP config | Lihat konfigurasi EXP | 成长值规则 / 消费换算 / 等级表 三个页签 |
| `growth.config_edit`（现有） | 改 EXP 配置 | Edit EXP config | Ubah konfigurasi EXP | 改这三个页签的数值；**不再管头像框** |
| `growth.avatar_frame_view`（新） | 查看专属头像框 | View exclusive frames | Lihat bingkai eksklusif | 专属头像框页签：列表 |
| `growth.avatar_frame_edit`（新） | 编辑专属头像框 | Edit exclusive frames | Ubah bingkai eksklusif | 新建、编辑、上下架；含同版新增的「活动专属」勾选和 PawCoin 价 |
| `growth.user_adjust`（现有） | 调整用户 EXP | Adjust user EXP | Sesuaikan EXP pengguna | 只管用户抽屉里给单个用户调 EXP；**不再管批量发放，也不再能看成长体系页** |
| `growth.batch_grant`（新） | 批量发放 EXP | Batch grant EXP | Beri EXP massal | 页头「批量发放」：上传、预览、确认 |

**页面入口与页签：**
- 侧栏「成长体系」：持有下面任一权限就显示——查看 / 改 EXP 配置、查看 / 编辑专属头像框、批量发放 EXP、查看 / 编辑运营活动
- 页签按权限显示，没有权限的页签不显示，进页面默认停在第一个能看的页签；只有「批量发放 EXP」的人进来只看到页头和「批量发放」按钮
- 「批量发放」按钮只对持有「批量发放 EXP」的人显示

**上线补码：**
- 持有「查看 EXP 配置」→ 补「查看专属头像框」
- 持有「改 EXP 配置」→ 补「编辑专属头像框」
- 持有「调整用户 EXP」→ 补「批量发放 EXP」「查看 EXP 配置」「查看专属头像框」（现在有它就能做这些）

- `config.edit` 拆完后删掉（2026-11-27 Hex 定，避免一个码绕过拆分）：迁移补完新码后从所有角色和账号上移除，代码里删除这个码

### 3.8 上线迁移的统一要求

- 一份迁移做完 §3.1 ~ §3.7 的补码，照 1.5.2「服务范围与运费」迁移的写法：**按数据补，不写死角色名**，角色表（`admin_role_permissions`，含运营主管等表内角色）和自定义账号（`admin_account_permissions`）都补
- 超级管理员本来就拥有全部权限，不用补
- **例外（权限变宽）：** 评论管理、虚拟账号、兽医资质三处，上线后只持有查看码的人能看到原来看不到的列表 / 详情。这是本来就该有的查看权限，不补码、不收回
- 新码都进角色配置页：放进各自页面的查看 / 编辑 / 其他操作列（`AdminPageCatalog`），中英印三语名称见各节表格（加进 `messages_*.properties` 的 `perm.*`）
- 所有权限变更照旧写审计

### 3.9 验收标准

- 只给「查看专属头像框」：能进成长体系、只看到专属头像框页签，没有新建 / 编辑按钮；页头没有「批量发放」
- 只给「批量发放 EXP」：进成长体系只看到页头和「批量发放」，能上传、预览、确认
- 只给「调整用户 EXP」：用户抽屉里能调 EXP；侧栏不显示成长体系（没有别的成长体系权限时）
- 只给「改 App 付费项价格」：运营配置里 KTP / 宠物名额 / 超值礼包卡可编辑（含 PawCoin 价），其他卡只读
- 角色配置页、账号权限里都不再出现「编辑配置」（`config.edit`）
- 只给「发货与送达」：订单履约页能发货、标记送达，迟到订单退款、取消订单 / 单行的按钮不显示，直接调接口返回 403
