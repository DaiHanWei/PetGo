## 1. 版本目标

运营现在办一次「带 #话题 发帖得奖励」的活动，要在活动结束后自己拉名单、用「成长体系」页的批量发放手工发 EXP，其他奖励（如优惠券）要一个个手动补，参与的用户当时看不到任何回报。本项让运营在后台**自助配置活动**，系统自动判定、自动发奖：

- 「参加就有奖」的活动，用户做完当场到账
- 「比热度」的活动，结束后系统按热度排出名单，运营核对后一键发放（2026-11-11 拍板：两种发放方式都要，由运营按活动选）
- 奖励不只 EXP，还可以发优惠券、KTP 高清解锁、性格测试解锁、免费礼物（Rp1.000 / 5.000 / 10.000 三档）、专属头像框
- 顺带引导用 PawCoin 买虚拟商品：头像框、超值礼包、KTP 高清等一次性解锁、多宠物名额都加一个 PawCoin 专属优惠价，付款抽屉里 PawCoin 卡右上角加「推荐」点赞小圆标（§3.11）

**不做：** 实物奖励；PawCoin 奖励（2026-11-27 Hex 定，先不送）；App 内活动中心 / 活动页（活动说明靠话题页顶置的推广卡和运营推送）。

**观察指标：** 活动期间带活动话题的发帖数、参与人数、参与者活动后 7 天留存（对比同期未参与的活跃用户）、各活动发出的优惠券成本、免费礼物次数。

## 3. 功能与需求

### 3.1 活动由什么组成（AB-40 配置，FR-193 执行）

一个活动 = **名称 + 时间 + 一种行为 + 范围 + 发放方式 + 奖励**。

| 项 | 说明 |
|---|---|
| 名称 | App 里显示（EXP 明细「Event · {名称}」、到账 / 获奖通知）。**印尼语、英语两个名称都必填**，各 ≤ 40 字，App 按用户的界面语言显示（2026-11-12 定）；另有一个只给后台看的备注 |
| 时间 | 开始、结束时间，按 WIB 填写；只判定这段时间内发生的行为，按**行为发生的时间**判，不按系统处理的时间（2026-11-13 定） |
| 行为 | 三选一：**发帖 / 点赞 / 评论**（场所打卡目前在用户侧隐藏，不做） |
| 范围 | 见 §3.2，按行为不同 |
| 发放方式 | **参与即奖** 或 **排名奖励**（只有「发帖」能选排名），见 §3.4 / §3.5 |
| 奖励 | 一份「奖励组合」，见 §3.3 |

一个活动只配一种行为（2026-11-11 定）。想做「发帖 + 评论都有奖」就建两个活动、用同一个名称；这样每个活动的判定、上限、数据都单一，后台好核对。

### 3.2 行为与范围

所有行为都沿用线上成长值的判定口径，只是多了「活动范围」这一层过滤：

| 行为 | 什么时候算一次 | 可选范围 | 不算的情况（同线上） |
|---|---|---|---|
| 发帖 | 帖子发出；需人工审核的帖子在**审核通过**时发奖，但按**发帖时间**判是否在活动时间内，活动结束后才审核通过的也补发（2026-11-13 定） | 指定话题（1–3 个，可不选 = 不限）· 内容类型（Diary / Moment / Tips，可多选，默认全部） | 私密帖（2026-11-11 定：不限话题的活动也不算） |
| 点赞 | 给别人的帖子点赞 | 被赞的帖子带指定话题（可不限） | 给自己点赞；同一个人对同一条帖子只算一次（取消后再点不重复算） |
| 评论 | 在别人帖子下的评论**变为可见**时 | 被评论的帖子带指定话题（可不限） | 自己帖子下的评论；同一个人在同一条帖子下只算一次（多条评论、删了再评都不重复算，2026-11-13 定） |

- **话题只能选官方话题**（2026-11-11 定）：用户话题谁都能建、名字随意，挂活动容易被抢注蹭；选择框只列状态为「正常」的官方话题
- 活动进行中话题被**隐藏**：活动照常判定（隐藏只是不推荐）；话题被**禁用**：之后的帖子不再关联该话题，自然不算，后台活动页提示「话题已禁用」

### 3.3 奖励组合（2026-11-11 拍板扩展奖励种类）

每「一份奖励」可以包含下面任意几项（至少一项）：

| 奖励 | 填什么 | 到账后在哪看 / 怎么用 |
|---|---|---|
| EXP | 数值（1–1,000） | EXP 明细「Event · {名称}」，同线上 |
| 优惠券 | 从商城优惠券里选 1 张（只列「生效中、未过期」的券） | 「我的优惠券」，有效期、使用门槛按这张券的配置；**发券遵守这张券自己的总库存和每人限领**（见下） |
| KTP 高清解锁 | 次数 + 模板（**12 款之一**，或「任意款」；1.5.4 KTP 分享链接新增 4 款，2026-11-26 改） | 「Koin & Jatah Saya」页，用法同超值礼包发的次数；「任意款」次数可用在任何一款 |
| 性格测试解锁 | 次数 | 同上 |
| 免费礼物 | 价格档（Rp1.000 / Rp5.000 / Rp10.000 三选一）+ 次数 | 同上，在送礼支付区用：一档的次数只能送单价正好是这一档的礼物（同现有 Rp1.000 免费次数的规则）；专属礼物也能用，只要送礼人等级够（线上有 1 件 Rp10.000 专属礼物）。线上普通礼物现在 1.000 / 5.000 / 10.000 / 25.000 / 50.000 五档各 8 件，前三档能用免费次数 |
| 专属头像框 | 选一款 + 有效期。可选的款：**在线的普通款**（商店也在卖）和**在线的活动专属款**（§3.10，商店不卖）；已下线的款不能**新选**（已发布的活动里选的框之后被下线，照常继续发，§3.6）。有效期：两种款都可以填天数（1–365，默认 30）或选「**永久**」（普通款一般限时送，后台提示） | 「Tailrent Level」页的头像框区。限时的和买的一样显示「Berlaku sampai {date} · {n} hari lagi」，到期提醒、到期摘下同买的（只针对正戴着的那款；活动专属款的提醒文案不同，§3.10）；永久的显示「Permanen」，不到期也不提醒；活动专属款带「Khusus event」标签（§3.10）。**不自动戴上**，用户自己去换；已有同款就再多一份，各算各的到期（同购买），其中有永久的就按永久算；活动专属款、已下线的款、已永久拥有的款都不出「Beli lagi」 |

- **在线普通款和活动专属款的区别要在后台写明**：选头像框那一行下面常驻一段灰字——普通款商店也在卖，用户可以自己买，活动送的那份和买的叠加，一般限时送（用户买一次只有 90 天，送永久会让这款没人买）；活动专属款商店不卖，只能从活动拿到，用户不能自己买或续，适合做稀缺奖励，可限时也可永久
- **点赞活动只能发 EXP**（2026-11-13 定）：取消点赞只扣得回 EXP，优惠券、权益次数、头像框扣不回（§3.4），如果点赞活动发这些，「批量点赞领奖再全部取消」就能白拿；后台行为选「点赞」时奖励只列 EXP
- **权益次数的有效期：** 同超值礼包，**到账起 3 个月**（2026-11-11 定礼包为 3 个月；活动发的次数沿用同一规则，2026-11-11 定）
- **成本控制**（2026-11-11 定）：**参与即奖**活动的奖励里含优惠券时，必须填**活动总份数上限**（全站最多发出多少份），发满自动停止发放、后台活动页标「已发完」；只发 EXP / 权益次数 / 头像框的可以不填。排名活动的份数由档位决定，不填（2026-11-13 定）
- **优惠券的库存与每人限领**（2026-11-12 定）：活动发券和其他渠道一样，受这张券的总库存、每人限领数约束。库存发完或这个用户已领满时，**只跳过这张券，同一份里的其他奖励照发**，发放记录里写明「券未发出：库存不足 / 已达每人限领」。后台选券时旁边显示这张券的**剩余库存**和**每人限领数**，由运营自己判断够不够（不拦）
- **免费礼物三档的验收：**活动发 Rp5.000 免费礼物 2 次 →「Koin & Jatah Saya」里多一行「Hadiah Rp5.000 gratis」2 次；送 Rp5.000 的礼物时出现「Pakai jatah gratis」（用免费次数）并扣这一档，送 Rp1.000 / Rp10.000 的礼物不能用这档次数；等级够的用户能用 Rp10.000 次数送 Rp10.000 专属礼物；后台奖励类型里没有 PawCoin
- **到账通知**（2026-11-11 定）：奖励里含 EXP 以外的东西时，发一条站内通知（文案见附录 A.1），点开按奖励内容去一个页面：**含免费次数** → 「Koin & Jatah Saya」页；**没有免费次数、含头像框** → 「Tailrent Level」页并滚到这款框 `/me/growth?frame={token}`；**只剩优惠券（可带 EXP）** → 「我的优惠券」。正文三种写法和这三个落点一一对应；**不发推送**；同一活动每人每天最多 1 条（当天后续到账合并不再发）。只有 EXP 的不发（同线上）

### 3.4 发放方式一：参与即奖

- 每次符合条件发**一份奖励**，**当场到账**
- 上限按**次数**算：**每人每天最多几次**（按 WIB 切天，可不填）和**每人活动内最多几次**（必填，防止无限刷）；含优惠券时另有活动总份数上限（§3.3）
- 活动奖励**不占**日常 EXP 规则（发帖 3 次 / 天等）的额度，也**不受**日常规则启停影响；只受 `OPS_CAMPAIGN` 总开关控制（关掉 = 所有活动暂停发放）
- **扣回：**
  - EXP 沿用线上：帖子被**运营下架** → 扣回这条帖子从参与即奖活动得到的 EXP（排名奖不扣，见 §3.5）；**取消点赞** → 扣回这次点赞得到的 EXP；作者自删帖、评论被删不扣回；只扣实际入账的部分，不扣成负数
  - **优惠券、权益次数、头像框不扣回**（2026-11-11 定）：用户可能已经花掉 / 用掉，扣回会出现负余额和客诉；防刷靠次数上限和总份数上限，以及运营在后台对异常用户停发（§3.8）
- 同一个行为同时符合多个进行中的活动：**每个活动各算各的**（2026-11-11 定）；后台新建活动时，如果和进行中的活动「行为 + 话题」重叠，提示一次但不拦

### 3.5 发放方式二：排名奖励（只限发帖）

用于「谁的帖子最火谁得奖」的活动（2026-11-11 拍板）。

- **参赛帖子：** 发帖时间在活动时间内、带指定话题（活动设了话题的话；没设 = 所有话题）、符合内容类型的公开帖子；需人工审核的帖子按发帖时间算，生成名单时还没审核通过的不参赛（2026-11-13 定）
- **热度：** 截至活动结束时刻，帖子的 **点赞人数 × 1 + 评论人数 × 3 + 收藏人数 × 2**（与「被点赞 / 被评论 / 被收藏」的 EXP 权重一致）；评论按不同评论人算，同一个人在这条帖子下评论多条只算 1 次（2026-11-13 定，防小号刷评论）；只算真实用户的互动，不算作者自己、不算虚拟号；同分时先发的排前面（2026-11-11 定）
- **奖励档位：** 运营配置若干档，每档一份奖励组合（§3.3），如「第 1 名：300 EXP + 永久头像框；第 2–3 名：150 EXP + 优惠券；第 4–10 名：50 EXP + Rp5.000 免费礼物 3 次」；最多 5 档，名次连续不重叠
- **每人只取最好的一条帖子**，一个人不会占多个名次
- **结算流程：**
  1. 活动结束后系统自动生成「待发放名单」（结束后 1 小时内）：名次、用户、帖子、热度、应发奖励
  2. 运营在后台核对，可以**剔除**某个用户（必填原因，如刷赞）：剔的是人不是帖子，这个人的其他帖子也不再上榜（2026-11-13 定）；剔除后后面的人自动递补名次；发放前可以「撤销剔除」（2026-11-13 定）
  3. 点「确认发放」→ 服务端确认弹窗（人数、EXP 合计、优惠券张数、各类次数合计、头像框份数）→ 发放；同一活动只能发一次，重复点不会重复发。个别用户发放失败的标「发放失败」并写原因，可在名单里重新发放（见 §3.8）
  4. 名单生成后**超过 7 天**还没确认，进后台侧栏「📥 待办中心」：照「商城待办」的写法在末尾加小标题「运营待办」+「排名待发放 ↗」，角标 = 超过 7 天未确认的排名活动数，点进运营活动页签并筛「待发放」；只对有「编辑运营活动」权限的人显示（后台没有首页待办区；权限见 §3.9）；不自动发放
- 发放时帖子已被下架、作者已注销 / 停用：该行自动标为「不发放」并写明原因，不递补
- **排名奖发出后一律不扣回**（2026-11-12 定），包括 EXP：名单是运营人工核过的，有问题应在发放前剔除；之后帖子被下架也不扣
- **获奖通知**（2026-11-11 定）：发站内通知 + 推送各一次「恭喜！你的帖子在 {活动名} 里拿了第 {名次} 名」，正文列出奖励（文案见附录 A.1），点开进这条帖子；推送分类归「Promo & aktivitas」（`PROMO`）。**推送限频（对齐 1.5.4 通知优化）：获奖推送不计入「每人每天最多 8 条」，也不计入「运营推送每人每天最多 2 条」；但遵守 00:00–07:00 免打扰**——夜里确认发放的，通知中心立刻写，推送攒到 07:00，和其他攒下的推送一起发（只有 1 条就原样发，多条合成一条汇总推送）。点推送**直达帖子**，不先进通知中心（2026-11-13 定）；从通知中心点、帖子已删时留在通知中心弹 toast「Konten ini sudah tidak ada」（这条内容已经不在了），同追更宠物。获奖通知已经列了奖励，不再另发 §3.3 的到账通知
- 排名活动**也可以同时设参与奖**：建两个活动（一个参与即奖、一个排名），同名即可

### 3.6 活动状态

| 状态 | 什么时候 | 能改什么 |
|---|---|---|
| 草稿 | 新建未发布 | 全部 |
| 未开始 | 已发布、未到开始时间 | 全部 |
| 进行中 | 开始 ≤ 现在 < 结束 | **只能延长结束时间、提前结束**（2026-11-11 定），避免同一活动前后口径不一 |
| 已发完 | 参与即奖活动发满总份数上限 | 只能延长结束时间（不能加份数）、提前结束 |
| 待发放 | 排名活动到结束时间或被提前结束后、确认发放之前（名单在结束后 1 小时内生成，生成前详情页显示「名单生成中」） | 不能改设置；只能在名单里剔除 / 撤销剔除、确认发放 |
| 已结束 | 参与即奖活动到结束时间或被提前结束；排名活动确认发放之后，或结束时没有任何参赛帖子（不进待发放、不进待办） | 不能改 |

- 提前结束：二次确认；已发的奖励不收回
- 删除：只有草稿能删
- 选作奖励的优惠券在活动期间被停用 / 过期：之后这一项不再发，其余奖励照发；后台活动页提示「优惠券已失效」
- 选作奖励的头像框在活动期间被下线：**照常继续发**，下线只影响商店和新活动能不能选；后台下线头像框的确认弹层提示「有 {n} 个未开始 / 进行中的运营活动在用这款，会照常继续发」

### 3.8 【后台】运营活动（AB-40）

**位置：** 「配置与安全 → 成长体系」页新增页签「运营活动」，排在现有 成长值规则 / 消费换算 / 等级表 / 专属头像框（1.5.2 加的）之后，是第 5 个页签。

- **列表：** 名称、行为、范围（话题）、发放方式、奖励摘要、时间、状态、参与人数、已发出（EXP / 优惠券 / 次数 / 头像框）合计；按状态筛选、按名称搜索
- **新建按钮：** 放在「运营活动」页签内工具栏右侧，页头「批量发放」不动
- **发布确认**（2026-11-13 定）：点「发布」弹服务端确认弹层，逐项复述名称、时间、行为与范围、发放方式、每份奖励、上限，并提醒「发布后进行中只能延长结束时间或提前结束」；和进行中的活动「行为 + 话题」重叠时，在这个弹层顶部加黄色提示、按钮改「仍然发布」，不另弹（§3.4 的重叠提示即此处）
- **新建 / 编辑：** 右侧 480 抽屉表单（同后台惯例），字段见 §3.1–§3.5；名称分印尼语 / 英语两栏；选优惠券时显示剩余库存与每人限领；选头像框时下拉只列在线的普通款和活动专属款（标出「活动专属」），有效期两种款都可填天数或选「永久」、默认 30 天，下面常驻两类框的区别说明（§3.3）；按所选行为显示对应的范围字段，行为选「点赞」时奖励只能加 EXP；奖励组合用「＋ 添加奖励」逐项加；发放方式选「排名奖励」时出现档位编辑，每档一个奖励组合
- **活动详情：** 成长体系下的**独立子页**（面包屑回「运营活动」页签），不用抽屉——明细要分页、筛选、批量勾选，排名名单要逐行剔除（2026-11-13 定）
  - 参与即奖：参与人数、发放次数、各类奖励合计、EXP 被扣回合计、券未发出次数、发放失败次数；明细（时间、用户、关联帖子、发了什么、券未发出原因、状态），可导出 CSV
  - **发放失败与重新发放**（2026-11-13 定）：系统出错没发成功的（不含券因库存 / 限领发不出），明细里标「发放失败」并写原因，运营可单条或批量「重新发放」；重发不会重复到账。用户说「参加了没拿到」时，运营在这里能查到
  - **停发某个用户**（2026-11-11 定）：明细里对异常用户「停发」（必填原因），之后这个活动不再给他发，已发的不收回；停发后不能恢复（2026-11-13 定）

### 3.9 【后台】运营活动的查看 / 编辑权限（AB-40）

运营活动页签不借用成长体系的「查看 / 改 EXP 配置」，用自己的两个权限，这样可以只让某个人管活动、不碰成长值规则和等级表。

| 权限码 | 中文 | English | Bahasa Indonesia | 管什么 |
|---|---|---|---|---|
| `growth.campaign_view` | 查看运营活动 | View campaigns | Lihat kampanye | 运营活动页签：列表、活动详情子页、导出 CSV |
| `growth.campaign_edit` | 编辑运营活动 | Edit campaigns | Ubah kampanye | 新建、编辑、发布、删除草稿、提前结束、停发、剔除、确认发放、重新发放；待办中心「排名待发放」 |

#### 验收标准
- 只给某账号「查看运营活动」：能进成长体系看到运营活动页签和详情，不能新建、编辑、发放
- 只给「编辑运营活动」：能新建、发布、确认发放
- 待办中心「排名待发放」只对有「编辑运营活动」的人显示

### 3.10 活动专属头像框（FR-340 / AB-68）

运营希望有一些头像框**只能靠活动拿到**，买不到也续不了，有的还能**永久**拥有。

**叫法：** 「专属头像框」是 1.5.2 起所有头像框的总称（后台页签名、App 等级页）；本节新增的属性叫「**活动专属**」，有这个属性的叫「活动专属款」，没有的叫「普通款」。现在头像框只有「在线 / 已下线」，没法区分「以前卖过、后来不卖」的普通款和活动专属款，快到期提醒也一律叫人「去再买一次」。

**后台（AB-68）**——「成长体系 → 专属头像框」页签：
- 新建 / 编辑头像框加一个勾选项「**活动专属**」，说明：不在 App 商店里卖，只能通过运营活动发放
- 勾了「活动专属」：价格、PawCoin 价不用填（不可填）；列表里这一行带「活动专属」标记
- 在线 / 下线照旧：活动专属款**在线 = 运营活动里能选**，下线 = 不能再被新活动选；已发出的照常有效，已发布的活动里选了它的照常继续发（§3.6）
- **「活动专属」建好后可以改**：
  - 专属改普通：必须填价格和 PawCoin 价才能保存；在线的话从此出现在 App 商店里能买；用户手上的永久框照旧永久，限时的照旧到期。**如果有未开始 / 进行中的活动用这款发「永久」，不让改**：确认弹层列出这些活动，要等它们结束（或提前结束；未开始的可以先把奖励改掉）才能改
  - 普通改专属：从 App 商店撤下；用户已经买的照常戴到到期（活动送的永久份照旧永久），不能再买；快到期提醒改用专属款文案
  - 改动写审计；保存前确认弹层说明上面这些影响
- 用户抽屉「这个用户拥有的头像框」：有效期一列，永久的写「永久」，活动专属款带标记

**发放：** 运营活动奖励里，活动专属款和普通款的有效期都可以填天数，也可以选「永久」（普通款一般限时送，§3.3）。同一个用户同一款既有限时的又有永久的，以永久为准。

**App（FR-340）**——「Tailrent Level」页头像框区：
- 活动专属款**只在用户拥有有效的一份时显示**（没拥有的买不到，不显示）
- 框卡加小标签「**Khusus event**」（活动专属）；永久的在有效期那一行写「**Permanen**」（永久），不写到期日、不显示剩余天数
- 活动专属款**不出「Beli lagi」**（再买一次），也没有购买入口
- 永久框不会到期、不会被摘下、不发快到期和已到期通知
- 普通款被永久拥有（活动送的永久份）：同样显示「Permanen」，不出「Beli lagi」，也没有购买入口（已经永久拥有，再买没有意义）；不带「Khusus event」标签

**快到期提醒：**
- 提醒规则不变（正戴着的那款、最后一份到期前 3 天、推送 + 通知中心）
- **活动专属款**用新正文：「Bingkai ini khusus event, jadi nggak bisa dibeli atau diperpanjang.」（这款是活动专属框，不能购买或续期。）；点开进「Tailrent Level」页并滚到这款框，**不弹再买抽屉**
- 已下线的普通款：保持现有文案，不改
- 已到期通知（只有标题「Bingkai {0} sudah berakhir」）：不变
- 判断按**发提醒那一刻**这款是不是活动专属

#### 验收标准
- 后台新建头像框勾「活动专属」：不用填价格就能保存；App 商店里看不到这款
- 运营活动选头像框：下拉只有在线的普通款和在线的活动专属款；两种款的有效期都能选天数或「永久」，默认 30 天
- 用户通过活动拿到永久的普通款：等级页显示「Permanen」，没有「Beli lagi」和购买入口，一直不到期
- 用户通过活动拿到永久专属框：等级页显示「Khusus event」「Permanen」，没有「Beli lagi」，一直不到期、不收到任何到期通知
- 用户戴着限时的活动专属框，到期前 3 天收到的推送正文是「…khusus event, jadi nggak bisa dibeli atau diperpanjang」，点开到等级页、不弹购买
- 把一款专属框改成普通款并上线：App 商店出现这款；之前拿到永久框的用户仍是永久
- 用户戴着已下线的普通款快到期：提醒文案和现在一样
- 有进行中的活动用某款专属框发永久时，后台把这款改成普通款：被拦住，弹层列出这个活动
- 进行中的活动选的头像框被下线：之后符合条件的用户照常拿到这款框

### 3.11 虚拟商品 PawCoin 优惠价（FR-349 / AB-76，2026-11-27 Hex 定）

现在每种虚拟商品只有一个价，PawCoin 和直接付（QRIS）付同一个数（1 PawCoin = Rp1）。改为**两个价**：**价格（Rp）** 是原价，直接付（QRIS）付这个；**PawCoin 价** 是 PawCoin 专属优惠价，用来引导用户充 PawCoin。

**范围**（2026-11-27 Hex 定）：

| 商品 | 现价（价格 = PawCoin 价） | 后台在哪定价 |
|---|---|---|
| 专属头像框（普通款，每款一个价） | Rp500 | 成长体系 → 专属头像框 |
| 超值礼包三档 | 8.000 / 11.000 / 13.000 | 运营配置 → 超值礼包 |
| KTP 高清、护照快照、登机牌 | 各 1.500（后两样入口目前隐藏，价格一起加） | 运营配置 → 一次性解锁定价 |
| 性格测试解锁、配型单买 | 5.000 / 3.000 | 运营配置 → 一次性解锁定价 |
| 多宠物名额月租（每个名额 30 天） | 5.000 | 运营配置 → 宠物名额 |

**不做**：AI 问诊解锁、礼物、兽医问诊、PawCoin 充值、商城订单，照旧一个价。

**规则：**
- **PawCoin 价必填，不能高于价格**；等于价格 = 不打折。上线迁移把每项的 PawCoin 价设成和现价相同，用户看到的价格不变，运营之后自己调
- **两种付款方式都能用**，没有金额门槛；余额够时默认选 PawCoin，不够默认选直接付（同现在）
- **性格测试**：配型价须比解锁价至少低 100 的校验，两套价各自校验；已单买配型再解锁完整结果时的补差价，按所选付款方式分别算（PawCoin 付 = 解锁 PawCoin 价 − 配型 PawCoin 价；直接付 = 两个价格之差）
- **多宠物名额**：一次买几个名额时，总价按所选付款方式的单价 × 数量
- **超值礼包**：PawCoin 卡显示这一档的 PawCoin 价；礼包页上「Hemat Rp{x}」（省多少）的算法不变（按价格算）
- **订单 / 支付记录**：照旧记当时的付款方式和实付金额；按消费给的 EXP 照旧按实付算
- **改价**：只影响之后的购买，和现在一样

**App（FR-349）**：这些商品的付款抽屉都用同一个组件 `PayChannelPicker`（头像框已经在用它的单独 PawCoin 价参数），各商品接上即可：
- PawCoin 卡显示 **PawCoin 价**，卡内右上角加一个「推荐」小圆标（紫底白色点赞图标 `thumb_up`，不写字；读屏文字「Disarankan」/「Recommended」，2026-11-27 Hex 定只放图标）；直接付卡显示**价格**（原价）
- 主按钮金额跟着所选付款方式变（选 PawCoin「Bayar 800 PawCoin」、选直接付「Bayar Rp1.000」）
- 余额不够：PawCoin 卡照现有写「Saldo {余额} · kurang {差额}」+「Isi saldo dulu →」，默认改选直接付，推荐图标照样显示
- 礼包推荐行（付费抽屉里推荐买超值礼包那一行）、用免费次数解锁等现有内容不变

**后台（AB-76）**：
- 「运营配置」的「一次性解锁定价」「超值礼包」「宠物名额」三张卡：每个价格行右边加一栏「**PawCoin 价**」（必填，下限 100），提示「PawCoin 专属优惠价，不能高于价格。」；高于价格时这一行报错、保存禁用（同现有行内校验）；确认弹层复述改动时两栏都列
- 「成长体系 → 专属头像框」：普通款 PawCoin 价从选填改必填，同上校验
- 权限：定价卡的 PawCoin 价跟同一张卡的价格用同一个编辑权限（同版后台权限梳理把「编辑配置」拆开后为「改 App 付费项价格」`config.paid_item_pricing_edit`）；头像框的 PawCoin 价用「编辑专属头像框」`growth.avatar_frame_edit`

#### 验收标准
- 后台一次性解锁定价卡：每行有「价格」「PawCoin 价」两栏；PawCoin 价高于价格时该行报错、不能保存
